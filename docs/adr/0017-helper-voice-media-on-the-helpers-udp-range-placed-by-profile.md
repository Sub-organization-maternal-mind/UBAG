# Helper voice media terminates on the helper's bounded UDP range; a call is placed by its account's profile and takes one workload and one lane

Helper-hosted voice (`UBAG_HELPER_VOICE`, default off, last rung of the helper flag ladder) needs two decisions that the media contract (P5.7, P5.10) assumed and the placement (P5.9) must make: where the WebRTC media terminates, and how a call is chosen a node.

**Media terminates on the Helper Node, on a bounded public UDP range.** The browser, the audio environment, the relay and the WebRTC endpoint are co-located on the node (decision D7), so audio never crosses the WireGuard link; the primary keeps public signaling (`POST /v1/voice/sessions/{id}/connect` is unchanged) and forwards the offer. The node binds its ICE ports in a bounded UDP range (`UBAG_HELPER_VOICE_UDP_PORTS`, at least 8 ports per audio environment) and advertises its public IPv4 as a NAT 1:1 host candidate (`UBAG_HELPER_VOICE_NAT_1TO1_IP`); a node with no reachable UDP may add a TURN relay candidate, with credentials the primary mints per attempt (`UBAG_HELPER_VOICE_SERVER_VIA_TURN`). The fleet manager's grant carries the same facts (`voice_capable`, `udp_port_range`, `nat_ip`), and `nodes.Allocation.Validate` already refuses `voice_capable` without a range and an address, so a node that is voice capable is one the manager opened the range for. Relaying the media through the primary was rejected: a relay hop over the 156 to 193 ms primary-helper round trip breaks the 100 ms p95 budget, and it would make the primary a media server for every helper. TURN alone was rejected as the default for the same hop and for its cost; it stays the fallback. Consequence, external to this repository: the manager must open the UDP range to the internet, set the NAT 1:1 address and provide a reachable TURN service; until it does no grant is `voice_capable` and no call is placed on a node.

**A call is helper-hosted exactly when its account has a profile on a node.** A voice session is admitted against the voice store by (account, environment) pairs the primary's topology offers. When the tenant's profile registry (`helperauth.ProfileStore`, the same `profile_ref` bindings jobs use) binds the account `(tenant, target, identity_ref)` to a node, the call must be hosted by that node, and the account is never offered to the primary's own browsers: when its node cannot take the call the candidate is dropped and the session queues (the same answer as no free account). An account with no profile on a node is primary-hosted, exactly as before. The environment is the topology instance of the account's context (the node's `instance_ref`, loopback on the node); a helper-bound environment that carries a CDP endpoint in the topology is refused rather than driven across the WAN, and environment names must be unique across the fleet because the environment lease is global. An unreadable registry or fleet offers no helper-bound placement and, for the registry, no placement at all, since a helper-bound account cannot then be told from a local one.

**The node must be able to host: host health, media capability, capacity and lane.** `nodes.Placer` is the one authority. A node is a candidate only when it is in the placer's eligible view (an active grant with a known reservation, a valid grant, a live heartbeat, no drain, a limit above zero after pressure, ramp and the ceiling table), so an unknown reservation, a draining, silent or expired node and a host of unknown size are all ineligible. It must be `voice_capable`. The call then takes one workload slot on the node and the account's identity lane (the `profile_ref`, the key a text job on that profile takes) in one reservation: one call counts as one node workload (D6, and the helper counts it as one attempt unit too), and a call and a job on one account exclude each other in both directions. The reservation is taken before the voice store decides, one per helper-bound candidate and only for the length of that call; the winner keeps its reservation for the session's life and the rest are returned. Slots and lanes are in-process, as in ADR-0016: one primary replica per fleet, with the helper's own admission as the backstop.

**Provider readiness is not host health.** Whether the account is logged in (`login_state` in the topology, written by the worker's own observation) is decided before any node is asked and is never an input to node eligibility; whether the node is healthy, voice capable and has room is decided from the fleet and never writes back to the account. A refusal for one says nothing about the other: the metric `ubag_helper_voice_placements_total{outcome}` has `node_unavailable`, `not_voice_capable`, `no_capacity`, `identity_busy`, `wan_endpoint` and `error` (and `placed`), and provider readiness is deliberately not an outcome. Voice capability is not a health verdict either: a node that cannot host media stays eligible for jobs.

**Bound at admission, released with the lease, hidden from clients.** Right after the store admits the session the primary binds it to the node (`BindNode`, P5.8): the generation fences every later write and control call, and the holder is no longer an unidentifiable browser to the job lane probe (a node-hosted holder holds no primary browser lane; an unbound one still fails closed). The node slot lives exactly as long as the voice store says the session reserves its environment (`ListLeaseHolders`, which includes a terminating hold), so every ending path, a lease sweep and a peer failure included, returns it; the paths that end a session on this replica release at once and a 5 s loop covers the rest. The node id, its address, the lease generation and the profile handle are never serialized: `voice.Session` keeps them `json:"-"` and the responses are tested for them. The primary never runs `voice.activate` or `voice.deactivate` for a helper-hosted environment (it has no endpoint for it): the node activates its own browser as part of the offer. A node-bound session is handed only to a negotiator that declares it terminates media on the node (`NodeMediaNegotiator`, supplied by P5.11); the primary's own hub, which would resolve some other account's relay for it, answers 503.

Decided 2026-10-06. Consequences: with `UBAG_HELPER_VOICE` on but no node-capable negotiator (until P5.11) a placed session can be created and held but not connected; a node-bound session does not take a terminating hold yet (nothing starts media on the node before P5.11), so its account and environment free at terminate; after a primary restart a surviving node-bound session no longer holds its slot in this process; multi-replica placement needs the slots and lanes in the shared admission store. (Superseded in part by ADR-0018, P5.11: the node-capable negotiator and the terminating hold for node-bound sessions now exist; the other consequences stand.)

Status: accepted
