# Helper trust plane: a separate mTLS listener, URI-SAN identity, SPKI pins, per-message re-check

Helper Nodes are trusted through their own gRPC listener (`UBAG_HELPER_PLANE`, default off, requires `UBAG_HELPER_NODES`), never through the plaintext public `grpcServer` and never through the Caddy edge. The listener is TLS 1.3 only with required client certificates chained to the fleet manager CA (`UBAG_HELPER_CA_FILE`), no session tickets, no reflection, and a node can only call what later slices register on it. The node identity is the single URI SAN `spiffe://ubag/node/<node_id>` of the leaf certificate; the CN and every other SAN are ignored, so a CN can never name a node. The leaf must not be a CA, must carry `clientAuth`, and may live at most 72 h (decision D3; a 10 minute backdating slack is tolerated). The node must exist in the P4.4 registry, must not be revoked, and the SHA-256 of the certificate's SubjectPublicKeyInfo must equal the registry's current or next pin. The same check runs at the TLS handshake, on every RPC, and around every stream message in both directions, so revocation, a pin promotion or a certificate expiry ends a live stream at its next message; a registry read failure fails closed (`Unavailable`). Any `node_id` carried in a message is only a cross-check: a bare `node_id` may be empty or must equal the certificate identity, a `Fence.node_id` must equal it, and a disagreement is `PermissionDenied`. Peers never learn why they were rejected (`Unauthenticated`); the reason goes to a hook (log now, aggregated audit in P4.8). Rotation is an overlap window: pins `current` and `next` are both valid until `PromoteSPKI`, which retires the old certificate even on open streams. Revocation is sticky. Development certificates come from `deploy/mtls/gen-certs.{sh,ps1} --node`; the production CA belongs to the fleet manager and is not in this repo. Decided 2026-10-06 because the helper RPCs carry attempt capabilities and a certificate bound only to a CA would let any CA-issued certificate speak for any node.

Consequences: the registry is the revocation authority and is read per message (no cache, so no revocation lag; add a short TTL cache only if Postgres load demands it and accept that TTL as the revocation latency). The primary-to-helper dial (the primary is the gRPC client, ADR-0006) must apply the same URI SAN and SPKI checks to the helper's server certificate; that client side lands with dispatch.

Status: accepted
