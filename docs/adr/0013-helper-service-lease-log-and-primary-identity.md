# The Helper Node serves attempts as a leased, replayable event log and authenticates the primary by exact URI SAN

`ubag-helper` is the gRPC server of `ubag.helper.v1` (decision D3: the primary dials it over WireGuard). It authenticates the primary from the client certificate: the chain must reach the fleet manager CA (`UBAG_HELPER_CA_FILE`), the leaf must carry exactly one URI SAN, `spiffe://ubag/primary/<id>`, equal to the configured primary identity, plus the `clientAuth` EKU and a validity of at most 72 h; an SPKI pin set of at most two values (`UBAG_HELPER_PRIMARY_SPKI_SHA256`) is optional because a pin only helps while the primary re-uses its key. A Helper Node certificate (`spiffe://ubag/node/<id>`) is also CA-issued and `clientAuth`-capable, so chain validity alone would let one compromised helper dispatch work to every other helper; the primary and node identity namespaces therefore never overlap and a node URI can never be configured as the primary. The CN and other SANs are ignored. The helper's own certificate must carry exactly its node URI SAN and `serverAuth` (checked at start and on every reload), so a mismatched `UBAG_HELPER_NODE_ID` refuses to start instead of serving a certificate the primary would reject.

An attempt lives on its Attempt Lease, not on a stream. The service keeps a bounded per-attempt event log (the primary's ingest bounds: 60 KiB per event, 4 MiB and 4096 events; over-limit output fails the attempt and is never truncated), a `RunAttempt` stream only reads that log, and a repeated `RunAttempt` with the same attempt id, generation and fingerprint re-attaches and replays from sequence 1 (the primary dedupes by event key `attempt_id:sequence`). A lease that is not renewed is killed by the helper itself, with no help from the primary; a renew never shortens a lease, is clamped to `now + 5 min`, and cannot resurrect a lapsed one. Fencing is exact: Renew, Cancel and re-attach need the job, attempt and generation the helper holds; a lower generation or a second attempt id on one generation is `Aborted`; a higher generation supersedes the older holder (killed, `stream_end_reason` `superseded`). The identity slot is held until the runner really returns, so a runner that ignores cancellation can never overlap a successor on the same `(provider, identity_ref)` (decision D6). Outcomes follow D4 and the helper's own knowledge of the submission boundary wins over the runner's claim: a failure after `PROMPT_SUBMITTED` is `submitted` with `reconcile_required`, a deadline cut is `timed_out` with `partial` and no result, and the helper writes sanitized fixed text for every failure it composes itself. The helper has no journal: after a restart `InspectAttempt` answers `UNKNOWN` and the primary reconciles from its own ledger, never re-running an attempt that ledger says was submitted.

A Helper Node holds no database, queue, object-store or application secret and drives no remote browser: it refuses to start when its environment carries any (`CheckEnvIsolation`), when it has no local Chrome, when it is told to listen on a wildcard or a hostname instead of one interface address, or when it cannot load its adapter registry (`registry_digest`, a canonical digest of the registry and its manifests, is reported in Handshake and on every capacity report; a mismatch is the primary's ineligibility rule F8). The browser work sits behind a `Runner` interface; the service core imports only gRPC and the generated proto (measured: 114 non-standard-library packages for the whole binary against 228 for `internal/executor`, which would add wazero, the MinIO client, pgx and the NATS client), so the real runner is extracted from the executor into its own package by P4.12 rather than imported. Decided 2026-10-06 because the helper's value is that a compromised or misconfigured peer, or a lost network, can neither start work on the wrong node nor leave a browser running unattended.

Consequences: the manager CA must issue the primary's certificate with the URI SAN `spiffe://ubag/primary/<id>` (to confirm with the manager team, like the node profile in ADR-0010); lease expiry uses the helper's clock against the primary's absolute `lease_expires_at`, so clocks must be within seconds (the handshake returns `server_time` so the dialer can measure skew and refuse a node that drifts); the primary's gRPC keepalive must not ping more often than every 10 s; a restarted helper forgets every attempt.
