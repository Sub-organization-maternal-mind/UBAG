# The primary negotiates helper-hosted voice with stateless, lease-fenced control and one supervisor per call

ADR-0017 placed a voice call on its account's Helper Node and bound the session to it. P5.10 built the node's side (`HelperVoiceService`). This decision is the primary's side: how a node-bound session's media is negotiated, controlled and ended (`UBAG_HELPER_VOICE`, default off, last rung of the helper flag ladder).

**One negotiator, routed by `Session.NodeID`.** `voice.RemoteNegotiator` is the media plane of a node-bound session and slots in at `httpapi.MediaNegotiator`, so the connect response, the OpenAPI contract and the SDKs are unchanged. `voice.NodeRouter` sends a session with a node to it and every other session to the primary's own `MediaHub`, as before; the router declares `HostsNodeSessions` (P5.9's marker), so the 503 that kept a node-bound session off the primary's hub is lifted exactly when a node-capable plane exists. It lives in `internal/voice` (the work item's `voice/remote.go`), not in a package of its own: it needs only the proto, gRPC and four small seams (`RemoteDialFunc`, a node endpoint resolver, a profile resolver, the voice store), so `internal/voice` still imports nothing from `nodes`, `jobs`, `executor` or `httpapi` and the `helpervoice` helper build stays inside the P5.10 import guard. The wiring (`serve/voice_nodes.go`) adapts `helperclient`, the node store and the profile registry to those seams.

**The attempt is a pure function of the lease.** The node's fence needs an `att_` attempt id and per-attempt credentials. Rather than a ledger row, the attempt id is `AttemptIDFor(session, generation)` (a hash, in the shape the node requires) and the credentials end `RemoteCallMaxAge` (4 h) after the session was created, so every replica, and a restarted primary, derives the same keys from the session record alone. That is what lets a reconnect served by another replica, or after a restart, issue the client a media credential the node still verifies. A new generation (a new `BindNode`) is a new attempt. Consequences: a call lives at most 4 h from its session's creation (the supervisor ends it just before), and a session queued for longer than that cannot connect; a TURN-relayed leg cannot outlive the credentials either. The node is told the account by its `profile_ref` (`voiceplace.Placer.ProfileRef`), the key a text job on that profile takes on the node's identity gate, so a call and a job on one account exclude each other on the node too.

**Control is stateless and fenced by the store.** Mute, interrupt, terminate and the offer itself are addressed by the session record. Each one first passes `HelperVoiceGuard` (tenant-scoped lookup, the fence must be exactly the lease the voice store holds) and carries the `VoiceFence` of that lease to the node, which checks it again. A stale generation, another node or another tenant's session is refused before any dial: another tenant's session reads as `ErrNotFound`, identical to an unknown one, and over HTTP as the same 404 on every route. Ending a call uses `AuthorizeEnding`, which also accepts a session that already reads terminated (a terminating hold keeps its leases), with the same fence. Only the supervisor (below) lives in memory and is rebuilt by the next connect.

**One supervisor per call, store first.** After a successful offer the replica that served it starts a supervisor: a renewal loop and an event stream on the call's own connection. Every 20 s it renews the store's media lease first and the node's lease second (the node ends the call by itself when renewals stop); a failed store renewal is never followed by a node renewal, so the node cannot outlive the record. The node's lease is shortened by the clock-skew bound (5 s, also checked in the handshake) so it stops no later than the store lets anyone else start. The window is 60 s; a node that has not answered a renewal for a whole window is declared lost and the record ends with `helper_unreachable`, so an unreachable node cannot pin an account. A supervisor whose lease was replaced (another generation, another node) ends its own call under its own fence and stops: a node that has moved on to the successor refuses the stale fence, so a successor is never touched. A primary restart ends its calls within one window (the nodes' dead-man and the lapse of the store's media lease, which the sweeper ends). The handshake before the first offer checks protocol, node id, voice support, workload version, adapter registry digest and clock skew, like job dispatch does.

**Events are fenced primary writes.** The node's event stream is applied in order, resumed after the last applied sequence when it breaks. An event of another attempt or generation is rejected (counted in `ubag_helper_fenced_rejects_total`), and the store's own fence (`CommitTransition`, the new `CommitMuted`, `ReleaseHold`) rejects a stale writer a second time, which also stops the supervisor. `CONNECTED` (written by the node only when the provider is verified ready and the client's peer is up) commits connecting to connected; the client's own mute over its data channel commits the flag. `ENDED` is the node's acknowledgement that the provider left voice mode, because it is written last: it releases a terminating hold, or ends a record that is still live (the call ended on its own: media failure, activation failure with the provider state, lease) with the node's end reason as `last_error`, from a validated token set, never free text, and without a hold since nothing is left to tear down.

**Terminate takes the hold; the node's acknowledgement releases it.** A node-bound session's terminate (and an expired connect lease, and a record whose media lease lapsed while the node was reachable) ends the record with the terminating hold (P5.8) and tells the node, in the background: a client's terminate never waits for a node. The node closes the media at once and deactivates the provider; `ENDED` releases the hold. When nothing ever ran on the node it answers `UNKNOWN` and the hold is released at once. A replica that did not serve the connect streams the node's retained events for just long enough to see `ENDED`; a node that cannot be reached leaves the hold to run out at its 45 s cap. This replaces the "no hold yet" consequence recorded in ADR-0017.

**Mute is confirmed before it is recorded.** For a node-bound session the node owns the microphone path, so the handler writes the mute flag only after the node confirmed it, and an unconfirmed mute answers 503 (`UBAG-VOICE-MEDIA-UNAVAILABLE-007`) instead of claiming success. A mute set before any media exists rides the offer. Interrupt is forwarded (`InterruptSession`) but the node answers `UNIMPLEMENTED` (no provider-side barge-in primitive), which is reported as `ErrInterruptUnsupported`; no HTTP route exists for it, because a public route is a contract change that needs a primitive behind it.

Decided 2026-10-06. Consequences and limits: one primary replica per fleet for placement (ADR-0016, ADR-0017), though the control surface itself works from any replica; a helper restart loses its in-memory calls and nothing deactivates their provider UI (the primary ends the record `helper_lost`; a node-side reconcile is still needed before enabling); no attempt ledger row exists for voice; live two-way audio on a real helper is a human-run check (RUNBOOK "Helper-hosted voice: first live check") and has not been performed.

Status: accepted
