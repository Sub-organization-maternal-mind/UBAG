# P0.5 Acceptance harness integrity and goal thresholds

Status: merged-ready (code + offline tests + docs). No real run was made; the harness was not aimed at any host.

## Files

- `tests/load/acceptance.mjs`: integrity gates, `steady-state` scenario, `--require-goals`, second-tenant probe.
- `tests/load/acceptance.test.mjs`: fake gateway gained tenancy, result bodies, events, list, artifacts and fault options; 14 new cases.
- `tests/load/thresholds.json`: new default gates (see below). `max_create_p95_ms` stays 2000 as the 100-client burst limit.
- `tests/load/thresholds.goals.json` (new): steady-state create p95 <= 200 ms, read p95 <= 100 ms, minimum verified counts.
- `docs/load-testing.md`.

## Behaviour added

- Completed jobs are re-fetched: `job_id`, status, non-empty `result.output.text`; for the `mock` target the text must name the job, end with the prompt and hold the nonce (the idempotency key, appended to every prompt) exactly once. Wrong, truncated or duplicated result => `result_mismatches`.
- `GET /v1/jobs/{id}/events` (paged, bounded to 20 pages): exactly one terminal event, no duplicate sequences => else `terminal_event_violations`.
- `completed_with_warnings` is no longer success; counted in `warning_jobs` (max 0).
- Second tenant via `UBAG_LOAD_API_KEY_B` (must differ from key A; never in reports): GET job/events/artifacts must be 403/404, list must not contain tenant-A job ids. Budget `--tenant-probe-samples` (default 10).
- `facade_image` final non-200 / empty content => `facade_image_failures` (max 0).
- `overload` must produce >= 1 rejection (`min_overload_rejections`), else FAIL.
- `steady-state` scenario (in `--scenario all`): constant create rate plus a dedicated GET mix; `steady_create_p95_ms` / `steady_read_p95_ms` are separate from the burst `create_p95_ms`, which now excludes steady-state creates.
- `--require-goals`: merges `thresholds.goals.json` and makes every unmeasured threshold FAIL (so run `--scenario all` with key B set).

## Deviations / assumptions

- Result verification of the `mock` target assumes the adapter text shape `Mock response for <cmd> on <target> (<job_id>): <prompt>` (adapters/mock `_resolve_tokens`); non-mock targets only get the non-empty text check.
- Terminal event types are matched against the job terminal status names (optional `job.` prefix stripped), per the mock adapter's `completed` event. Verify against a real gateway log on first real run; if a gateway names its terminal event differently the run fails closed (loudly), not silently.
- Legacy k6/Locust scripts (D10) are out of scope here.
- Existing offline fake now always supplies key B, so every smoke run also exercises the probe.
