# P6.3 - Dashboard truthful queue depth and shared snapshot store

Status: merged (see PR). Flags: none. Migrations: none. Contract changes: none (P2.6 already landed `GET /v1/jobs/summary`).

## What landed
- `apps/dashboard/src/lib/stores/snapshot.ts` (new): in-memory TTL snapshot store (`createSnapshotStore`, singleton `snapshots`).
  `get(key, fetcher, { ttlMs = 10 s, force })`: fresh hits skip the network; concurrent reads of a key share one in-flight request
  (including `force`); only 2xx responses are cached (errors/denials are never pinned); max 32 keys (oldest evicted);
  `clear()` bumps an epoch so a fetch started before a clear cannot repopulate. `settings.set()` clears the store so cached reads
  never outlive a gateway/secret change.
- `lib/api/jobs.ts`: `failedStatusesToFetch(summary)` (non-zero failed statuses, or all when no summary) and `mergeNewestFirst`.
- Overview (`routes/+page.svelte`): Recent Activity asks for `limit=5` (was 100 full job bodies); counts come from `/v1/jobs/summary`;
  all reads go through the snapshot store, so Overview and Metrics share requests within 10 s; Refresh forces. The capped
  `limit=100` list is read only when the summary route is missing (older gateway).
- Metrics (`routes/metrics/+page.svelte`): no job list at all; summary + targets + adapters + browser summary via the store; same
  legacy fallback.
- Failed (`routes/failed/+page.svelte`): reads the summary, then one `filter[status]=<failed status>&limit=100` page per non-empty
  failed status (not 100 bodies of every status), merged newest-first; the strip shows the true failed total and
  "(showing newest N)" when it exceeds the rows shown. Polling/Refresh force-refresh the summary; first paint may reuse a fresh one.
- Also: `ErrorPanel retry` on these pages now passes an explicit arrow (the click event was previously forwarded into `load` params).
- No `fields=` / `include=` are used (the gateway ignores them).
