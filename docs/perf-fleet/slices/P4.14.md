# P4.14 Primary remote runner, HelperPicker interface and in-process cancel registry

Status: merged when its PR is merged into `feat/perf-fleet`. Size L. Depends on P3.12, P4.3, P4.9 and P4.12, all merged. Inert: everything is behind `UBAG_HELPER_DISPATCH` (default off). With the flag on and no picker wired (the placer is P4.17) `executor.NoHelperPicker` places nothing, so every job still runs on the local runner. No migration, no public contract change.

Design record: `docs/adr/0014-remote-attempt-lifecycle-on-the-primary.md`.

## What landed

- **`executor/helperpicker.go`**: `HelperPicker` (an interface; the real implementation, the P4.17 placer or a manager adaptor, is out of this slice and the OET fleet manager is out of the repo), `HelperPlacement` (`NodeID`, `Endpoint`, opaque `ProfileRef`, an idempotent `Release`), `ErrNoHelper` (run locally), `HelperRetryError` (hold the job, delayed lease Retry), `NoHelperPicker`, and the static eligibility rule `helperEligible`: `antigravity_*` targets, `voice.*` command types, conversation jobs, jobs with declared attachments (or the legacy audio key), names or trace ids the helper would refuse, and any job whose P4.7 projection the payload policy or the helper size bounds refuse never reach the picker and run locally.
- **`executor/remoterunner.go`**: `RemoteWorkerRunner` (`Place`, `Run`), one attempt per `Run`: ledger pre-check (a live predecessor lease means wait) -> dial and `Handshake` (protocol, node id, workload version, registry digest, clock skew <= 10 s; any mismatch holds the job before anything is leased) -> `BeginAttempt` (generation n+1, 120 s lease, fresh `att_` id, input fingerprint) -> `RunAttempt` -> every event through `HelperIngest` (P4.9 fenced, idempotent commit). Re-attach after a broken stream (the helper replays from sequence 1; already committed sequences are skipped), a lease keeper renewing every 20 s (ledger first, then helper; the helper is told a lease 10 s shorter than the ledger's) and declaring the helper lost after 120 s without a successful renewal, `CancelAttempt` on cancel, shutdown, loss, a rejected attempt and a job that ended under the attempt. Loss follows the submission boundary: before `PROMPT_SUBMITTED` the job is held and reassigned (generation+1 after the old lease lapses), after it `ErrAmbiguous` (`failed_terminal`, `submitted`, `reconcile_required`, queue lease failed, never replayed). A ledger-fenced attempt stops without writing or cancelling. Output that breaks the contract fails the attempt through the same fence (P4.9 classes) and the helper is told to stop.
- **`executor/cancelregistry.go`**: `CancelRegistry` and `NewCancelNotifier`. The cancel API calls `Dispatcher.CancelJob` first and writes the canceled status second; the wrapper turns a successful `CancelJob` into a hint for the consumer supervising the job, which re-reads the store (up to 3 s) before stopping the run. A remote attempt no longer polls the store at 250 ms: only the 2 s safety net remains for a cancel written by another process.
- **`executor/helperdispatch.go` and `workerconsumer.go`**: `WorkerConsumer.Remote` and `.Cancels`. After the lease and the exec lease and before assignment the consumer asks `Place`; a placed job skips the browser-lane check (it drives the helper's browser), runs under the same supervisor as a local run (queue and exec lease heartbeats, cancel watch) and, on a clean return, is closed from the job's own state (`finishRemoteRun`, the same closing sequence as a locally ingested job). `HelperRetryError` shares the delayed-Retry path of pool overload and voice-lane holds (`retryAfterDelay`). `runWorkerWithCancellation` is now a thin wrapper over `superviseRun` (behaviour unchanged for local runs). With `Remote` nil the code path is the previous one.
- **`internal/helperclient`** (new, the primary's dial, decision D3): TLS 1.3, no resumption, the primary's own certificate presented; the helper's certificate is verified in `VerifyConnection` because it is addressed by a WireGuard IP: chain to the manager CA with `serverAuth`, exactly one URI SAN `spiffe://ubag/node/<id>` for the node the placement named, not a CA, valid now, at most 72 h (+10 min slack), and an SPKI that is the current or next pin of the node registry with the node not revoked (registry errors fail closed). Keepalive 30 s (the helper's minimum is 10 s).
- **`serve/helper_dispatch.go`**: `newHelperRemoteFromEnv` (flag, prerequisites, files, registry digest) and the wiring in `serve.go`: the cancel registry wraps the dispatcher the cancel API uses (flag on only), `consumer.Remote` and `consumer.Cancels` are set after the consumer is built.
- **`tests/chaos`**: four experiment definitions (helper lost before and after submission, superseded helper, fleet manager down) and `test_helper_dispatch.py`, which keeps them valid, reversible, labelled `definition_only` and pointed at Go tests that exist. They are NOT evidence of a live run.

## Flags and defaults

- `UBAG_HELPER_DISPATCH` (default off; third rung of the ladder). On requires `UBAG_HELPER_PLANE` (and so `UBAG_HELPER_NODES`), `UBAG_EXECUTOR_ATTEMPTS` with a ledger store (Postgres; memory for tests), and the new `UBAG_HELPER_CLIENT_CERT_FILE`, `UBAG_HELPER_CLIENT_KEY_FILE` (the primary's dial certificate, URI SAN `spiffe://ubag/primary/<id>`, re-read when renewed) and `UBAG_HELPER_WORKLOAD_VERSION`; it reuses `UBAG_HELPER_CA_FILE` (the plane's bundle), `UBAG_ADAPTERS_DIR` (default `adapters`; its registry digest must equal the helper's) and `UBAG_WORKER_MAX_RUNTIME_MS` (the attempt's `deadline_seconds`, at most 1 h). Off: `newHelperRemoteFromEnv` returns before reading any of them and nothing is wrapped or constructed.
- Defaults inside the runner (not env): lease 120 s, renewal 20 s, clock-skew bound 10 s, handshake 5 s, renew RPC 10 s, cancel 5 s, retry delay 5 s.

## Deviations

- Files: the work items name `helperrunner.go` / `remoterunner.go` and a `serve.go` mTLS listener. The listener was P4.5; this slice adds `remoterunner.go`, `helperpicker.go`, `cancelregistry.go`, `helperdispatch.go` and the dial in a new package `internal/helperclient`. No store code changed (`jobs.FencedApplier` is P4.9's name for P4.2's `CommitEvents`).
- Flag: the work item says `UBAG_HELPER_EXECUTION=0`; the other work item and BINDING use `UBAG_HELPER_DISPATCH`, which is the taxonomy name and is used.
- `WorkerRunner` returns a slice, which cannot carry a fenced, incremental commit, so the remote path is not a `WorkerRunner`: the consumer branches on `Place` and closes the lease from the job state. The local path is untouched.
- The picker wired by `serve` is `NoHelperPicker` (the placer is P4.17, and the real fleet picker is out of repo), so the flag moves no job yet. This is logged once at start.
- A placed job needs the primary to supply assets and a conversation block the helper contract cannot carry yet (no attempt token in `RunAttempt`, no conversation field or event), so those jobs are never dispatched (see follow-ups); they run locally exactly as before.
- Renewal order and the 10 s shortening of the helper's lease are decisions beyond the spec (ADR-0014): they make "helper lease never outlives the ledger lease" structural instead of timing luck.
- No new metric series: the renewal loop records the existing `ubag_lease_renew_failures_total{lease="attempt"}` (the P4.23 runbook and alerts already expect it). Fenced rejects and policy violations are P4.9's counters.
- An attempt abandoned by a refusal, a handshake problem after `BeginAttempt` or a loss holds its ledger lease until it lapses (at most 120 s); the ledger has no explicit release. The runner reads the ledger first and waits for the lapse instead of spinning.
- tests/chaos holds experiment definitions plus a consistency test, not live runs: there is no lab host (D5) and no picker.

## Follow-ups

- **P4.17 placer**: implement `HelperPicker` over `nodes` grants, `ProfileStore`/`EligibleProfiles` and the identity lane (a `HelperRetryError` for busy or bound-node-down, `ErrNoHelper` for manager unreachable); pass the cancel registry and `Remote` it already has; derive `PoolSize` from capacity. Until then dispatch moves nothing.
- **P4.18 reconciler**: consult the ledger before `RecoverOrphanLeases`; on a gateway restart re-attach to a submitted attempt (`InspectAttempt`) instead of the current fail-closed `ErrAttemptSubmitted`; close the window where a helper submits and dies before any event reached the primary (the runner only knows `PROMPT_SUBMITTED` it has read). Consider a ledger "release attempt" so a refused or abandoned attempt does not hold its 120 s lease.
- **Assets and conversations**: an attempt token in the `RunAttempt` contract, the manifest filler (`Asset.name` = declared key, in manifest order, P4.12) and a conversation block plus events, then lift those two ineligibility rules in `helperEligible`.
- **Manual-action events from a helper** raise no operator alert and no login-state projection yet (P4.9 follow-up): the primary's topology login state belongs to the primary's own browser, so it must not be reused as is.
- **Dev tooling**: `deploy/mtls/gen-certs.{sh,ps1} --primary` to issue the primary's dial certificate; today it has to come from the manager CA (URI SAN `spiffe://ubag/primary/<id>`, `clientAuth`, at most 72 h, confirm with the manager team). Tests use `authtest`.
- **Serve-level wiring test**: `Run` is not unit-tested end to end; the env table and the runner are. A canary (P4.20) must watch `ubag_lease_renew_failures_total{lease="attempt"}` and the fenced counters from the first attempt.
- The primary-side `registry_digest` is computed once at start; re-read `UBAG_ADAPTERS_DIR` on change if adapters become hot-reloadable.
- **Revocation of a node mid-attempt**: the dial reads the SPKI pins and the revoked flag at the TLS handshake only, and a connection lives for one attempt, so a node revoked while an attempt runs keeps that attempt (the primary's own listener re-checks every message, the dialed connection does not). Stopping work on a revoked node belongs with the drain/revoke handling (P4.21/P4.18); until then new placements are refused by `nodes.Evaluate` and the pin is checked at every new attempt.
