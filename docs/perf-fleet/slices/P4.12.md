# P4.12 Helper bounded pool, staging and identity lock wired in

Status: merged into `feat/perf-fleet`. Size M. Depends on P3.6, P4.7, P4.10 and P4.11, all merged. The helper binary is still started by nothing (not in compose, not in the gateway); this slice gives it a real runner, so a deployed helper now executes attempts.

## What landed

- **Extraction (first commit, behaviour-preserving)**: `apps/gateway/internal/workerdaemon` is a stdlib-only leaf holding what P3.6 built, so the helper can run the same pool without linking the executor (P4.11 measured 228 vs 114 non-std packages):
  - `Pool`: the identity gate (one active job per physical session key), warm affinity (warm, then live cold, then never started, then LRU eviction), bounded wait and bounded queue with the typed `OverloadError` / `ErrOverloaded`, drain on `Close` (stdin EOF, kill after 5 s). `Pool.Run(ctx, key, fn)` hands `fn` the held `Slot`; a failure before `Slot.Run` leaves the slot as it was, one after it leaves it cold.
  - `Process`: one supervised daemon behind its one-job mutex (the former `DaemonWorkerRunner` process half); the run timeout starts after the slot is held.
  - `ReadJob` and friends: the v1 stdio protocol. `AllowedEnv` / `FilterEnv`: the worker env allowlist, moved out of `workerconsumer.go`.
  - `attachments.MaterializedFilename` / `ExtForContentType` moved from the executor (the helper needs the same temp-file naming).
  - `executor.DaemonPool` and `executor.DaemonWorkerRunner` keep their public API and behaviour; they are adapters (`PoolOverloadError`, `ErrPoolOverloaded` are aliases). Tests that poked pool internals now use `Pool.Counts` / `Pool.SlotCommand`; the size and default-bound tests moved to `workerdaemon/pool_test.go`.
- **`internal/helper/runner`** (new): `Runner` implements `helper.Runner` over a `workerdaemon.Pool`.
  - One process slot per allowed attempt (`Slots` = `UBAG_HELPER_MAX_ATTEMPTS`, default 1: the node starts at one browser workload). The pool key is `sha256("helper:"+identity_ref, target)`: tenant-free, per physical session. The helper core's own gate (one active op per provider + identity_ref) refuses a second attempt first; the pool's gate and the worker's flock are the second and third layers.
  - Worker payload is built from the validated `AttemptSpec`, never a primary envelope: top-level `profile_ref` = `identity_ref` (the worker derives `<profile root>/helper/<ref>` from it in `UBAG_HELPER_PLANE` mode), `attempt.id`, `job.{target,command_type,input,options}`. Dropped, mirroring `executor.NewHelperAttemptSpec` (a test compares the two): options `user_data_dir`, `profile_dir`, `profile_path`, `account_binding_id`; input `attachment_local_paths`, `audio_local_path`. No tenant id, callbacks, client or context reach the worker.
  - Worker env = the shared allowlist minus `UBAG_REMOTE_BROWSER_ENDPOINT` and `UBAG_NOVNC_BASE_URL`, plus `UBAG_HELPER_PLANE=1` (set last, so a stray value cannot turn helper mode off), `UBAG_WORKER_SLOT_ID`, `UBAG_WORKER_POOL_SIZE` and the node's `UBAG_PROFILE_DIR`. A test sets every primary-only variable in the process env and asserts `helper.CheckEnvIsolation` passes on the result.
  - **Staging**: declared attachments (`input.attachments`, parsed with `attachments.DeclaredAttachments`) are matched one to one with `RunAttemptRequest.assets` (by `Asset.name` = the declared key), fetched from an `AssetSource`, written to `ubag-attach-*` temp files (the prefix the worker's path guard needs) while size and SHA-256 are verified, then pointed at via `attachment_local_paths` (and `audio_local_path`). Any mismatch, short or long stream, bad digest or source failure removes every file and ends the attempt `failed` (`helper_asset_integrity`, `helper_assets_unavailable`, `helper_assets_invalid`) **before a worker is touched** (a test asserts no daemon was started and no prompt submitted). Files are removed when the attempt ends.
  - **Event mapping**: STARTED when the slot is held; worker `session.opening` to BROWSER_OPENED, `session.manual_action_required` to MANUAL_ACTION_REQUIRED (only a reason token), `prompt_submitted` to PROMPT_SUBMITTED, `token` to TOKEN. `completed` to COMPLETED with `result_json` = the worker's result object. `timed_out` to TIMED_OUT with `partial` and the partial text (capped 32 KiB) on the terminal event's data, never in the result (D4). `failed` / `blocked` / `dead_letter` to FAILED with a stable code and a reason token only: **the worker's message text never leaves the node** (test). Everything else (queued, session.* bookkeeping, concurrency / conversation / topology telemetry, anything after the terminal) is dropped.
  - A worker that overruns `deadline + DeadlineSlack` (10 s, below the service's 15 s backstop) is killed and the attempt ends TIMED_OUT (`partial` only if tokens streamed, no result); cancel, lease expiry and shutdown surface as the context error so the service writes the right terminal. A dead worker returns an error (the service ends the attempt `failed`, `runner_error`).
- **`cmd/ubag-helper`**: builds the runner from `UBAG_HELPER_WORKER_SCRIPT` (required, must be a file), `UBAG_HELPER_WORKER_PYTHON` (default `python`), `UBAG_HELPER_PROFILE_ROOT`, with `Slots = UBAG_HELPER_MAX_ATTEMPTS`, and closes it after the node stops. Binary links 117 non-std packages (114 before: the runner, `workerdaemon` and `attachments`); `imports_test.go` now allows exactly those three for the binary and still holds the service core at gRPC + proto.

## Deviations and assumptions

- **Extraction instead of importing the executor**, as P4.11 required; the executor is now an adapter over `workerdaemon` (same behaviour, tests adjusted for the moved internals).
- **No production `AssetSource` yet.** The RunAttempt contract carries no attempt token, so the P4.10 staging client cannot be built inside the binary (and `internal/helper/staging` links the artifact store). The binary runs with no source: an attempt that declares attachments ends `failed` (`helper_assets_unavailable`, not submitted) rather than running without them. `staging.StagingClient.Get(ctx, key)` is the fetch the adapter wraps; the dial slice supplies the token and the adapter.
- **`Asset.name` is the declared attachment key**, and assets must match `input.attachments` one to one. The proto only says `name`; the primary side that fills it (P4.13+) must follow this.
- `identity_ref` values the worker would refuse (`:` passes the helper's pattern, not the worker's `profile_ref` pattern) end `failed` (`helper_identity_ref_unsupported`) before any worker.
- `UBAG_HELPER_CHROME_BIN` is not passed on: the worker launches Playwright's bundled Chromium (no executable-path setting exists), so the lookup only gates start-up as in P4.11. Worker support for a pinned Chrome is a follow-up.
- No tenant id or api_version in the payload (the proto carries neither); the worker defaults them, and in helper mode the profile is derived from `profile_ref` alone.
- Pool start size is one slot (`UBAG_HELPER_MAX_ATTEMPTS` default 1), the "1 browser workload" rule; ceilings above that remain the node logic's.
