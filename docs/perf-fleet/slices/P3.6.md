# P3.6 - Go DaemonPool: bounded isolated slots replacing the single mutex

Status: merged (see PR). Inert by default: `UBAG_WORKER_POOL_SIZE` unset or 1 builds exactly today's single `DaemonWorkerRunner`. The pool size ceiling is provisional because no real slot cost has been measured (see "Sizing").

## What landed
- `apps/gateway/internal/executor/daemonpool.go` (new): `DaemonPool` (WorkerRunner + StreamingWorkerRunner) over N `DaemonWorkerRunner` slots.
  - **Slot isolation**: one worker process per slot, the stdio protocol unchanged (v1 request lines, one JOB_END per job). Slots are spawned lazily with `UBAG_WORKER_SLOT_ID=<i>` and `UBAG_WORKER_POOL_SIZE=<N>` appended after the scrubbed env, so the worker scopes its page registry per slot (P3.3), takes the identity flock, and reaps registries of slots >= N on start. A failure, cancel or deadline kills only that slot's process.
  - **Identity gate** keyed by the physical session, tenant-free (`daemonIdentityKey`, the Go twin of `physical_session_key`): with `UBAG_REMOTE_BROWSER_ENDPOINT` set it is byte-identical to the worker's hash (checked against two vectors produced by the Python function); otherwise it hashes the requested profile directory (options then context, same precedence as the worker, cleaned but not symlink-resolved) plus the target. One active job per key. A symlink alias that Go sees as two keys is serialized by the worker's flock (the backstop).
  - **Warm-affinity routing**: idle slot warm for the key, then a live cold slot, then a never-started slot, then the least recently used warm slot of another key (a fresh start is preferred over evicting a warm page). Each slot tracks at most one warm key; a failure clears it.
  - **Bounded wait / overload**: FIFO placement queue bounded by `MaxQueue` (default = pool size), waits at most `MaxWait` (default 30 s, deliberately not MaxRuntime which is 25 min in production). Refusal is a typed `*PoolOverloadError` (`errors.Is(err, ErrPoolOverloaded)`, reason `queue_full` | `wait_expired`, `RetryAfter` default 2 s). A busy identity does not block a later request for a free identity.
  - **Run timeout starts after slot acquisition** (also fixed in the legacy runner: the `context.WithTimeout` moved from before `mu.Lock()` to inside `runLocked`, so a job queued behind another no longer spends its own MaxRuntime budget waiting). Attachments are materialized once a slot is held (own maxRuntime budget).
  - **Drain**: `Close()` refuses new/waiting jobs, waits for in-flight placements, then each slot finishes its active job and has its stdin closed (the serve loop exits on EOF and closes its warm pages), killed only after `DrainTimeout` (5 s).
- Rebased over P3.12 (strict-submit): the job callbacks carry its `submitted *atomic.Bool`, and both `DaemonWorkerRunner.runJob` and `DaemonPool.run` wrap the whole run in `classifySubmission`. With `UBAG_WORKER_STRICT_SUBMIT` on, a placement refusal reads as `ErrNotSubmitted` while `ErrPoolOverloaded` stays in the chain, so the consumer's overload branch still matches. Flag off: untouched.
- `daemonrunner.go`: `DaemonWorkerRunner` gains `slotMode/slotID/poolSize` (zero value = legacy), `runExclusive`/`runLocked` split out of `runJob`, `drain`, shared `batchDaemonJob`/`streamingDaemonJob`, `materializeDaemonAttachments`. Legacy behaviour is otherwise unchanged.
- `workerconsumer.go`: `RunOnce` treats `ErrPoolOverloaded` as lease-then-place (ADR-0011): releases the exec lease, holds the lease for the overload's `RetryAfter` (default 2 s, max 30 s), then `lease.Retry`. It is never failed, completed, acked or retried at once; the job stays `assigned`. The exec-lease release became idempotent (`sync.Once`) so the early release and the deferred one cannot double-release.
- `serve.go`: `workerPoolSizeFromEnv`, `coupledWorkerConcurrency`; `buildWorkerRunner` builds a `DaemonPool` only when the size is > 1; `newWorkerConsumerFromEnv` raises `UBAG_WORKER_CONCURRENCY` to the pool size when the daemon is on (never lowers it) and warns when a pool size is set without the daemon.
- `docs/adr/0011-lease-then-place-with-delayed-retry.md` (new, in this slice as BINDING requires), `CONTEXT.md` (Daemon Pool, Slot), `docs/perf-fleet/ALLOCATION.md` (ADR 0011 claimed), `docker-compose.vps.yml` / `deploy/vps/env.example` / `deploy/vps/README.md` (env passthrough, defaults preserve today: `UBAG_WORKER_POOL_SIZE:-1`, the other two empty).

## Flags (defaults)
- `UBAG_WORKER_POOL_SIZE` (default 1 = today). Only read when `UBAG_WORKER_DAEMON` is on. Invalid/non-positive fails startup (same as `UBAG_WORKER_CONCURRENCY`).
- `UBAG_WORKER_POOL_MAX` (new, default 3, hard max 32): the operator ceiling; the applied size is `min(SIZE, MAX, 32)` with a warning when clamped.
- `UBAG_WORKER_POOL_WAIT_MS` (new, default 30000): bounded placement wait.
No migrations. No new dependency.

## Sizing (the ceiling is provisional)
No real slot cost exists: P0.8 measured only a stub (about 17 MiB per slot) and recorded the hypothesis that the 1300m gateway cgroup caps the pool at 2-3 real slots; P0.13 shipped the `budget` tool but no baseline (D5: no isolated lab host). So the default ceiling is 3 and is a placeholder, not a measurement. To raise it: run `apps/worker/tests/bench/measure_slots.py --real --playwright` and `tools/perf/baseline-matrix.mjs budget --role gateway ...` on a lab host, then set `UBAG_WORKER_POOL_MAX`. Where the worker slots' cgroup is (gateway container, per P0.13's open question) decides which role to budget.

## Deviations / notes
- v1 wire protocol only: the pool does NOT send `proto:2`. The deliverable says "stdio protocol unchanged per slot", and v2 changes the JOB_END status for a deadline-cut stream to `timed_out`, which the Go reader would turn into a failure; that mapping belongs with the strict-stream/submission slices (P3.8/P3.10/P3.12), which are also the consumers of `submitted`/`outcome_signal`. The Go side learns warm affinity from its own key, not from `warm_key`; the schema fields are untouched.
- Added two operator knobs not named in the spec (`UBAG_WORKER_POOL_MAX`, `UBAG_WORKER_POOL_WAIT_MS`) because the ceiling must be overridable once measured and the wait must be tunable; both default safe.
- The consumer-side retry delay is an in-process hold of the lease (the file spool has no delayed Retry; NATS already delays). It pins one consumer worker for the delay; see ADR-0011 for the head-of-line limit and the NATS `MaxDeliver` caveat.
- `targetWorkerRunner` (serve.go) still implements only `RunWorker`; routing `StreamWorker` through it is P3.10's job. `DaemonPool` implements both interfaces so P3.10 needs no pool change.
- Resizing the pool down to 1 leaves orphan slot registries (the single daemon does not reap them); resizing between sizes > 1 reaps them on slot start.
