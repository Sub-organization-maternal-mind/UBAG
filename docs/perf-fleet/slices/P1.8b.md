# P1.8b - Attachment copies, warm-page reloads, idle polling

Status: merged (three opt-in changes, all default OFF = today's behaviour).

## Changes

| Change | Flag (default) | Files |
|---|---|---|
| Hardlink local-fs artifacts into the worker temp dir instead of streaming a second copy; any failure (flag off, non-local store, cross-device, link refused) falls back to the copy path | `UBAG_ATTACHMENT_HARDLINK` (off) | `artifacts/store.go` (`LocalObjectPather`), `artifacts/localfs.go`, `artifacts/replicate.go`, `executor/workerconsumer.go` (`linkArtifactLocally`) |
| Defer the every-N-jobs warm-tab reload while `performance.memory.usedJSHeapSize` is under a budget; hard cap at 4 x `UBAG_WARM_RELOAD_EVERY` jobs; any doubt (no reading, CDP error) reloads | `UBAG_WARM_RELOAD_HEAP_MB` (unset = off) | `worker/ubag_worker/live/page_driver.py` (`_reload_due`), worker env allowlist in `workerconsumer.go` |
| Idle backoff of the lease loop's fallback poll: doubles per consecutive empty poll up to a cap, resets on work/error; the enqueue wake channel still pre-empts the wait | `UBAG_WORKER_IDLE_POLL_MAX_MS` (unset = fixed `UBAG_WORKER_POLL_INTERVAL_MS`) | `executor/workerconsumer.go` (`idlePollWait`), `serve/serve.go` |

Migrations: none. Contracts: none (internal behaviour).

## Isolation / safety reasoning
- Hardlink: the path comes from the same tenant/job-scoped metadata lookup and root-containment check as `GetArtifact`. The worker only reads attachments (browser file upload); cleanup unlinks only the temp link, the artifact object survives. A re-upload or delete of the artifact replaces/removes the old inode without touching the link. Remaining risk: any future worker code that WRITES to an attachment path would corrupt the artifact, hence default off.
- Warm reload: only the memory-bounding reload is deferred. The per-job emptiness proof (`_wait_until_absent`, New chat, fresh-chat flag) and the cold-page fallback are unchanged; the page-reset safety tests in `test_latency_fixes.py` / `test_warm_reuse.py` pass unchanged.
- Idle poll: pickup latency for enqueues the wake channel cannot see (another replica sharing the spool dir, delayed retries) grows up to the cap. Same-process file-spool enqueues wake immediately. Pick a cap of about 1000 ms for a single gateway.

## Before / after (reasoned, not measured)
- Attachment bytes written per job: 1 full copy per attachment -> 0 (link) on local-fs artifact stores. MinIO/Garage/memory stores still stream (no local file exists).
- Warm reload: one full provider-page load (about 7.6 s for ChatGPT per existing notes) every 10 jobs -> at most every 40 jobs while heap stays under budget.
- Idle lease polls at `UBAG_WORKER_POLL_INTERVAL_MS=75`: about 13/s per idle worker -> 1/s at a 1000 ms cap. P0.8 measured a pending-dir lease at about 2.6 ms on a Windows dev box, so the saving is small CPU but removes constant wakeups. NON-AUTHORITATIVE; no real-Chrome or VPS measurement was taken.
