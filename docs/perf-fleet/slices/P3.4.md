# P3.4 - Daemon protocol v2, Python side

Status: merged (Python daemon only; no Go consumer sends proto:2 yet, that is P3.5).

## What landed
- `daemon_protocol.py`: strictly opt-in v2.
  - A job line with `"proto": 2` gets a JOB_END that also carries `proto`, `pid`, `attempt_id` (echo of `attempt.id`), `slot_id` (echo of the request), `warm_key`, `outcome_signal`, `submitted`. A v2 deadline-cut stream (a `timed_out` event) ends `timed_out`, never `completed` (D4); the hard-deadline marker is `timed_out` + `worker_deadline_exceeded` + `outcome_signal: timeout` in v2 and stays `failed` in v1.
  - `{"__ubag_control__": "hello"|"probe", "proto": 2}` gets exactly one control reply (`hello`: pid, slot_id when `UBAG_WORKER_SLOT_ID` is numeric, `features`; `probe`: `state: idle`, read-only, touches no browser). A control line without `proto:2` is handled as before (v1 bad-request marker). The daemon never emits an unsolicited line.
  - v1 requests produce byte-identical output (golden-string test). One JOB_END per job is unchanged (`_JobOutput` still lets exactly one marker win).
  - `submitted` and `outcome_signal` are derived from the events passing through (`prompt_submitted` / `data.submitted`; blocked reasons `selector_drift_detected` -> drift, `human_verification_required` -> captcha, other blocked / `session.manual_action_required` -> manual_action, `timed_out` / `stream_end_reason: deadline` -> timeout, else none). Detection only; no behaviour change.
- `daemon.py`: `WarmWorkerDaemon.warm_key(payload)` = `physical_session_key(...)` (sha256 hex of endpoint-or-realpath + target, no tenant, never a raw path).
- `run_worker_daemon.py`: slot mode (`UBAG_WORKER_SLOT_ID` set) refuses `UBAG_ORCHESTRATOR_ENABLED` (exit 2, stderr message): per-process AIMD would emit conflicting caps across slots. `os._exit(75)` stays per-process.
- `tests/test_warm_daemon_protocol.py`: v1 byte identity, v2 fields, outcome signals, timed_out vs v1 failed, hello/probe opt-in, one-marker invariant, slot-mode orchestrator refusal.

## Flags / migrations
No new env flag: v2 is opt-in per request line (`proto:2`). No migrations.

## Checks run
`pytest apps/worker/tests/test_warm_daemon_protocol.py test_warm_daemon.py test_slot_isolation.py test_strict_submit.py` (43 passed, 1 skipped: POSIX flock test on Windows).

## Checks not run
Schema validation of the emitted markers against `worker-daemon-job-end.schema.json` (jsonschema not installed here; fields were matched to the schema by hand). Go `daemonrunner` interop (P3.5).

## Deviations / follow-ups
- Events are not re-stamped with `attempt_id` by the daemon, and `attempt` is not injected into the engine payload: attempt-scoped event ids stay with P3.7 behind `UBAG_WORKER_ATTEMPT_EVENT_IDS`. The engine already reads `payload.attempt`.
- `hello.features` lists `attempt`, `outcome_signal`, `strict_stream_end`, `strict_submit`; `stream_events` is omitted until a streaming slice lands it.
- A v2 request with a malformed payload gets a v1-shaped failed marker (still schema-valid).
