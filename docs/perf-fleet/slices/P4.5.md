# P4.5 Helper trust plane: separate mTLS listener, URI-SAN node identity, dev certs

Status: merged into `feat/perf-fleet`. Size L. Depends on P2.3 (helper proto), P2.5 (authz/audit vocabulary) and P4.4 (node store), all merged. Inert: nothing is bound and no store is read unless `UBAG_HELPER_PLANE` is on, and the plane has no services registered yet (attempt assets/staging land in P4.6/P4.8, dispatch later).

## What landed

New package `apps/gateway/internal/helperauth` and a separate listener in `serve`:

- **Identity** (`identity.go`): the node id comes only from the leaf's single URI SAN `spiffe://ubag/node/<id>` (`nodes.NodeIDFromURISAN`); the CN and other SANs are ignored. The leaf must not be a CA, must carry the `clientAuth` EKU, must be inside its validity window and live at most 72h (`MaxCertLifetime`, plus a 10 minute backdating slack). `Authenticator.Verify` then reads the P4.4 registry: unknown node, revoked, or an SPKI SHA-256 that is neither the current nor the next pin is rejected; a registry error is a fail-closed `Unavailable`. Typed `RejectError` with a `Reason`, an `OnReject` hook for audit/metrics (wired to a log line now; P4.8 aggregates).
- **TLS** (`tlsconfig.go`): TLS 1.3 only, `RequireAndVerifyClientCert` against the CA bundle, session tickets disabled (no resumption can outlive a revocation), and a `VerifyConnection` that runs `Verify` before the handshake completes. `KeyPair` re-reads the listener's own certificate when the files change (keeps the last good pair on a bad reload); `LoadCAPool` fails on an empty bundle.
- **Interceptors** (`interceptor.go`): unary and stream interceptors re-run `Verify` for every RPC and around every stream message in both directions (`SendMsg` and `RecvMsg`), so revocation, a pin promotion or certificate expiry ends a live stream at its next message; the stream context is also cancelled at the leaf's `NotAfter`. A message `node_id` is only a cross-check: a bare `node_id` (Handshake, ReportCapacity, Drain) may be empty or must equal the certificate identity; a `Fence.node_id` / `VoiceFence.node_id` must equal it (empty is a mismatch); a disagreement is `PermissionDenied`. Peers see only a generic `Unauthenticated` (no reason oracle). A connection without a verified client cert (plaintext) is rejected, so wiring the interceptors to the wrong server fails closed. `IdentityFromContext` gives handlers the authenticated node.
- **Server** (`NewServer`): own `grpc.Server` with TLS creds, the interceptors, `UnknownServiceHandler` returning `Unimplemented` (reached only after authentication, so the service surface is not probeable), no reflection and no health service, 1 MiB max receive message, 64 concurrent streams, 10 s handshake timeout.
- **serve** (`serve/helper_plane.go` + one block in `serve.go`): `newHelperPlaneFromEnv` returns nil and binds nothing when `UBAG_HELPER_PLANE` is off. On, it requires `UBAG_HELPER_NODES` and the four variables below, loads the TLS material at startup (bad files fail startup), binds at start like the public gRPC server, and stops with the same half-grace budget. It is a different `grpc.Server` from the plaintext public one; helper RPCs are never registered on the public server.
- **Dev tooling** (`deploy/mtls/gen-certs.sh`, `gen-certs.ps1`): `--node ID [--node-days 1..3] [--label L]` issues an EC P-256 node cert (URI SAN, clientAuth+serverAuth, at most 72h) under a reused dev CA and writes `node-<id>[.<label>].spki.sha256`; README documents the certificate profile, env vars, rotation overlap runbook and revocation. `authtest` (in-memory test CAs/leaves) is used by the tests.
- ADR `docs/adr/0010-helper-trust-plane.md`; ALLOCATION.md ADR table updated (0009 was taken by P4.15 on the integration branch, so this ADR is 0010).

## Flags

- `UBAG_HELPER_PLANE` (default off; second rung of the helper flag ladder; requires `UBAG_HELPER_NODES`). Off: no listener, no store reads.
- When on, all required: `UBAG_HELPER_GRPC_ADDR` (listen address, bind to the WireGuard interface), `UBAG_HELPER_CA_FILE` (PEM trust anchors, the fleet manager CA), `UBAG_HELPER_TLS_CERT_FILE` and `UBAG_HELPER_TLS_KEY_FILE` (the listener's own certificate; the last two are additions to the names the slice spec lists, because a TLS server needs its own certificate).

## Migrations

None. The registry is P4.4's `0023_helper_nodes`; SQLite refuses helper mode (P4.4), so no SQLite migration or `schema.sql` change and no migration-vs-bootstrap parity to check.

## Deviations

- ADR is `0010-helper-trust-plane.md`, not `0006-...` (0006 is taken; 0009 was taken by P4.15 on the integration branch).
- Two env variables beyond the spec's two (`UBAG_HELPER_TLS_CERT_FILE`, `UBAG_HELPER_TLS_KEY_FILE`).
- Policy choices beyond the spec, all fail closed: exactly one URI SAN, explicit `clientAuth` EKU, not a CA, validity at most 72h (+10 min slack) enforced server side, session tickets off, a `Fence` without `node_id` is a mismatch.
- No sqlite migration / `schema.sql` / `0021_helper_nodes.sql` (security-03 file list is stale: P4.4 shipped the registry as Postgres `0023` and SQLite refuses helper mode).
- `authtest` is a non-`_test` package under `internal/` so `serve` tests can reuse it.
- The primary-to-helper dial (primary is the gRPC client, D3) is not built here: the deliverable is the listener. The client side must apply the same URI SAN and SPKI checks to the helper's server certificate.

## Follow-ups

- Nothing writes the registry yet outside tests: a `fleet:manage` route and/or P4.15's poller must call `PutRegistry`, `PromoteSPKI` and `RevokeNode` (and emit `node.enrolled`, `node.cert_rotated`, `node.revoked`).
- P4.8: hook `Authenticator.OnReject` to `node.auth_rejected` with aggregation (today one log line per rejection, which a CA-valid but unregistered peer can multiply), and make the audit append fail closed.
- P4.6 and later register helper-facing services on `hplane.server` (`serve.go`); the unknown-service handler keeps answering `Unimplemented` until then.
- The registry is read on every RPC and stream message with no cache; if Postgres load matters, add a short TTL cache and accept the TTL as the revocation latency (ADR-0010).
- An idle stream (no messages) of a freshly revoked node is only noticed at its next message in either direction; add a periodic re-check if that gap matters.
- The CA bundle is read once at startup (restart to change); the listener's own certificate is hot-reloaded.
- Confirm the manager CA's certificate profile (single URI SAN, `clientAuth` EKU, validity at most 72h) before enabling the plane against the real manager.
