# P2.4 Node-allocation consumer schema and error codes

Status: merged (contract-only; no runtime change).

## What landed

- `packages/shared-schemas/schemas/node-allocation.schema.json` (`$id` `https://schemas.ubag.dev/v1/fleet/node-allocation.schema.json`): one grant per Helper Node. Fields: `schema_version`, `node_id`, `region`, `endpoint` (WireGuard host:port), `cert_identity` (`uri_san`, optional `spki_sha256`), `cpu_millis` and `memory_bytes` (already net of manager reservations), `reservation_state` (known|unknown), `state` (active|draining|revoked), `max_browser_workloads`, `voice_capable` (requires `udp_port_range` + `nat_ip`), `valid_until`, `generation`. `$defs/allocation_list` is the polled response body (`schema_version`, `generated_at`, `allocations[]`, max 256). `additionalProperties:false`: no tenant or job ids cross this interface.
- `UBAG-WORKER-NODE-FENCED-005` (worker category, retryable:false) in `errors.json`; SDK manifests regenerated with `node tools/make-sdks/generate-manifest.mjs` (147 error codes).
- Fixture `packages/conformance/fixtures/node-allocation/v1.json` (valid and invalid grants and lists), validated in `packages/conformance/scripts/validate-fixtures.mjs`; `tools/check-contracts.mjs` asserts the required grant fields, `additionalProperties:false` and the fencing code.

## Consumer semantics (interface proposal for the fleet-manager team)

Documented in the schema description; enforced later by P4.x. Effective cap = min(grant, UBAG ceiling table). A lower `generation` than the last accepted is stale and rejected. Past `valid_until`, `reservation_state=unknown` or `state=draining` means no new placements (existing work keeps its limits); `revoked` fences the node. Manager unreachable: last-known-good stays, never increased (ADR-0006, D3). The manager owns the producer; this file is the proposal handed to the OET team.

## Deviations

- The error code is `UBAG-WORKER-NODE-FENCED-005`, not `UBAG-WORKER-NODE-FENCED`: `error.schema.json` requires the pattern `^UBAG-[A-Z0-9-]+-[0-9]{3}$` and every catalog code ends in a 3-digit suffix. Later slices (P4 fenced applier) must cite the suffixed form.
- `UBAG-WORKER-OVERLOAD` not added: `UBAG-WORKER-UNAVAILABLE-001` (retryable) already covers "no worker/node capacity" and `UBAG-OVERLOAD-*` covers gateway self-protection; per the slice rule a new code is only added if those do not cover it.
- `/v1/nodes`, `node:read`, openapi and authz edits from fleet-02 dropped, per the slice deliverable.
- `$defs/allocation_list` and `cert_identity.spki_sha256` are additions beyond the field list, needed for the polled response and the D3 SPKI pin.

## Follow-ups

- P4 slices implementing the consumer must enforce the semantics above (stale generation, `valid_until`, `reservation_state=unknown`, `udp_port_range.min <= max`, `node_id` equals URI SAN identity); JSON Schema cannot express the cross-field checks.
- Hand `node-allocation.schema.json` plus this shard to the OET team for review; schema_version stays 1 until they respond.
