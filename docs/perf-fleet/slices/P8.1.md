## What the check script verifies
Every taxonomy flag from BINDING is in the inventory; each row's `Read in` file exists and mentions the flag; the `Compose` column equals what `docker-compose.vps.yml` actually has; an inert-by-default flag is not defaulted on in compose; each `managed` flag has a ROLLOUT section with non-empty Live-DOM verification, Canary criteria, Rollback and Ledger steps; each flag appears in `deploy/vps/env.example`; every `UBAG_*` name in FLAGS.md and ROLLOUT.md exists somewhere in apps, deploy, tools or compose.
It does not verify behaviour, and the code default is checked only through the compose and `Read in` rules, not by running the code.

## Findings worth acting on
- **Compose delivers only some flags.** `docker-compose.vps.yml` has an explicit `environment:` list and no `env_file`; of the managed flags, `UBAG_WORKER_STRICT_STREAM_END`, `UBAG_WORKER_ATTEMPT_EVENT_IDS`, `UBAG_EVENT_NOTIFY`, `UBAG_SSE_CLOSE_ON_TERMINAL`, `UBAG_FILESPOOL_HONOR_NOT_BEFORE`, `UBAG_REDACT_REMOTE_ENDPOINT`, `UBAG_PROFILE_OPTIONS_POLICY`, `UBAG_WARM_RESUME_FASTPATH`, `UBAG_EXECUTOR_ATTEMPTS` and all `UBAG_HELPER_*` / `UBAG_FLEET_MANAGER_URL` are not passed, so setting them in `env.local` would do nothing. ROLLOUT.md section 1 makes the passthrough line a prerequisite per flag. P8.1 did not add them (the instruction was no production config change).
- **`token_events` was refused as a credential key** (the P4.9 latent bug, still present at this tip): `payloadpolicy` rejects any key with a `token` segment except `token_index`, `token_count`, `first_token`; the worker's deadline-cut event carries `data.partial.token_events` (also in the job-event schema and a conformance fixture, so renaming it would have been a contract change). With `UBAG_WORKER_STRICT_STREAM_END` on, that terminal event would have failed validation. Fixed by exempting that exact key; `token_events_secret`, `refresh_token_events` and `token` stay refused (test `TestValidateAllowsDeadlineCutPartialShape`). A production gateway needs this build before that flag is set; ROLLOUT.md says so.
- Truthy values differ: the gateway `envBool` accepts `1`, `true`, `yes` only (not `on`), and `UBAG_SSE_CLOSE_ON_TERMINAL` accepts only `true`. The docs standardise on the literal `true`.
- Worker flags outside the daemon env allowlist (`UBAG_PROFILE_OPTIONS_POLICY`, `UBAG_WARM_RESUME_FASTPATH`) are not forwarded to a gateway-spawned worker; ROLLOUT.md section 1 flags it.
- `UBAG_PROFILE_OPTIONS_POLICY=namespaced` moves the profile directory, so a human re-login (or a profile move) is needed per target; it is documented as a graduation cost.
