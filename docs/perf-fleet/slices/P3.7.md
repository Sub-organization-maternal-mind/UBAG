# P3.7 Local attempt identity and attempt-scoped event ids (carve-out)

Status: merged (carve-out; no store schema change).

## What landed
- `DispatchEnvelope.Attempt *DispatchAttempt{ID}` (`omitempty`) in `apps/gateway/internal/executor/executor.go`. lease_generation / expires_at join in P4.2.
- Consumer sets `Attempt.ID = lease.LeaseID()` per delivery only when `UBAG_WORKER_ATTEMPT_EVENT_IDS` is on.
- Python worker (`live/engine.py`, `live/events.py`): reads `payload.attempt.id`; event id = `evt_` + sha(`job:attempt:seq`) and `data.attempt_id` is stamped. No attempt => legacy `job:seq` id, byte-identical.
- Gateway failure id (`failureEventID`) gains the attempt id suffix when an attempt is set.
- Stale-attempt events (`data.attempt_id` set and different from the leased attempt) are dropped in-process before normalisation.

## Flags
`UBAG_WORKER_ATTEMPT_EVENT_IDS` (Go consumer), default OFF.

## Mixed-id behaviour (retry spanning a deploy)
Events without `attempt_id` always pass the stale filter and keep legacy ids; an attempt that started before the flag/deploy keeps legacy ids, the next attempt gets scoped ids, so they cannot collide. Toggling the flag off mid-flight returns to legacy ids (same collision risk as today).

## Verification of assumptions
- `live/envelope.py` `normalize_payload` reads known keys only; the extra `attempt` block is ignored.
- `validateLeaseEnvelope` compares fixed fields only; `Attempt` is not compared (leased envelope has none).
