# P5.9 Node-aware voice placement and node-lane admission

Status: merged into `feat/perf-fleet`. Size L. Depends on P5.8, P4.1 and P4.17, all merged. Inert by default: everything new is behind `UBAG_HELPER_VOICE` (default off; the whole ladder `UBAG_HELPER_NODES` < `UBAG_HELPER_PLANE` < `UBAG_HELPER_DISPATCH` < `UBAG_HELPER_VOICE`). No migration, no public contract change (the OpenAPI session object serializes nothing new). The primary-side media negotiator that actually dials the helper is P5.11, so with the flag on a call can be placed, bound and held but not yet connected.

Design record: `docs/adr/0017-helper-voice-media-on-the-helpers-udp-range-placed-by-profile.md` (written first, its own commit). It also records the decision this slice was assigned: **media terminates on the helper, on its bounded public UDP range** (NAT 1:1 advertised address, TURN as the fallback with primary-minted credentials), never relayed through the primary (the 156 to 193 ms round trip would break the 100 ms p95).

## What landed

- **`internal/voiceplace` (new): `Placer`.** Joins the tenant's profile registry (`helperauth.ProfileStore`) with the fleet placer (`nodes.Placer`). A voice account is helper-hosted exactly when it has an active profile on a node; such an account is never offered to the primary's browsers (its candidate is dropped and the session queues). `Admit` reserves, for every helper-bound candidate, one node workload slot plus the account's identity lane (the `profile_ref`, the same key a text job on that profile takes) in a single `nodes.Placer.Reserve`, so one call counts as one node workload and a call and a job on one account exclude each other both ways; `Settle` (called once with the session the store returned) keeps the winner's reservation for the session's life and returns every other. `Available` is the read-only twin for the capability view. `ReleaseEnded` frees the reservation of every session that no longer reserves its environment, read from `voice.Store.ListLeaseHolders` (the truth the job lane probe already uses, including a terminating hold); it judges only sessions held before it read the store, so a fresh admission is never freed by an older snapshot, and a store error frees nothing. Outcomes (bounded): `placed`, `node_unavailable` (host health: not granted, draining, silent, expired, **reservation unknown**, unknown host size, unknown node), `not_voice_capable`, `no_capacity`, `identity_busy`, `wan_endpoint`, `error`. A nil `*Placer` is the flag-off placer: everything passes through. An unreadable fleet offers no helper-bound placement; an unreadable registry offers no placement at all (a helper-bound account cannot then be told from a local one).
- **Provider readiness is separate from host health.** The account's `login_state` is decided by the existing topology read before any node is asked and never feeds node eligibility; node eligibility, voice capability and capacity are decided from the fleet and never write back to the account. Neither is an outcome of the other (provider readiness is deliberately not a placement outcome). Tests cover both directions at the HTTP level, including that a silent node leaves the context's `login_state` untouched and a provider that is not ready leaves the node eligible and unreserved.
- **`nodes.Node.VoiceCapable`**: the placer's view copies the grant's `voice_capable` (`Allocation.Validate` already requires a UDP range and a NAT address with it). Being listed at all is the health verdict; a node that cannot host media stays eligible for jobs.
- **`voice.LeaseHolder.NodeID`** (memory, SQLite and Postgres `ListLeaseHolders` read the P5.8 `node_id` column) and **`voice.LaneProbe`**: a holder bound to a Helper Node holds no primary browser lane. Without this, a helper-hosted session (its environment has no endpoint in the primary's topology) would fall into the probe's fail-closed unknown-lane branch and hold back every browser job on the primary.
- **`httpapi`**: `Config.VoiceNodes`. `voicePlacements` now returns a `settle` func instead of a bare release: it releases the browser-lane registrations and the node reservations the session did not win, and returns the node of the winner. Create and connect-claim then `BindNode` the session at admission (media lease TTL = the lease window; P5.8's generation fences everything after) and end the session (503, `UBAG-VOICE-MEDIA-UNAVAILABLE-007`) when it cannot be bound. Terminate returns the node slot at once; the 5 s loop in `serve` covers lease sweeps, peer failures and terminates served by another replica. A node-bound session is handed only to a `NodeMediaNegotiator` (marker `HostsNodeSessions`, supplied by P5.11); the primary's own hub answers 503, because its relay resolver (including the single-environment `UBAG_VOICE_AUDIO_RELAY_ADDR` fallback) would attach the call to some other account's browser. The primary never starts `voice.activate` for a node-bound session (the node activates its own loopback browser as part of the offer, D7). The capability view's `available` / `free_resources` count a helper-bound account only while its node could take a call (read-only, nothing reserved). No node id, address, generation, media lease or profile handle appears in any response (tests scan create, get, list, queued, connect and refusal bodies).
- **`serve`**: `voice_nodes.go` builds the `Placer` over the dispatch fleet's placer and profile store when `voice.HelperVoiceEnabled` and voice sessions are on (the ladder without helper placement is a startup error, never a primary fallback) and runs the 5 s release loop.
- **`helpermetrics`**: `ubag_helper_voice_placements_total{outcome}` (7 outcomes + `other`); no node, tenant, session or profile is ever a label. A dry-run read (capabilities) counts nothing.
- Docs: ADR-0017, `ALLOCATION.md` (ADR number, the package and wiring note), `RUNBOOK.md` (flags row, metric, "Voice calls queued for placement").

## Flags and defaults

- No new flag. `UBAG_HELPER_VOICE` (default off, requires the whole ladder) now also selects `Config.VoiceNodes`. Off means `Config.VoiceNodes` is nil: every call is hosted on the primary exactly as before (`TestVoicePlacementKeepsAHelperBoundAccountOffThePrimary` pins this). In-code constants: node release loop 5 s.

## Migrations

None. Uses P5.8's `0025_voice_lease_generation` columns (`node_id` is now also read by `ListLeaseHolders`) and P4.16's `0024_helper_profiles`.

## Deviations

- **Package.** The work items name `voice/voice.go` (and `voice/remote.go`); the placer is `internal/voiceplace`, because `internal/voice` is linked into the `helpervoice` helper build, which a test pins to carry no `nodes`, `jobs` or `executor` code, and placement needs `nodes` and `helperauth`. `voice` itself only gains `LeaseHolder.NodeID` and the lane probe rule.
- **Node-lane admission is `nodes.Placer.Reserve` (node slot plus identity lane), not the shared token store.** `topology/store.go` and `topology/admission_sql.go` are untouched: jobs already take their node slot from the in-process placer (ADR-0016), and a call counts as one node workload only if it takes it from the same authority. The topology half of the exit gate therefore matches one pinning test only. Same ceiling as ADR-0016: one primary replica per fleet, the helper's own admission as the backstop.
- **Bound at admission, not at connect.** `BindNode` runs right after the store admits (or claims) the session, so the holder is node-identified from the start (the lane probe would otherwise treat an unbound helper environment as an unknown browser and hold back primary jobs until connect). The media lease TTL is the lease window; P5.11 must renew it (`RenewVoice` -> `RenewMediaLease`) or the sweeper ends the session as `media_lease_expired`.
- **Not in this slice (P5.11, work item fleet-11):** the remote negotiator and gRPC forwarding (`voice/remote.go`, `helper/voice.go` consumers), event ingestion as fenced writes, and the terminating hold for node-bound sessions. `terminateVoiceSession` still releases a node-bound session at once (nothing starts media on the node before P5.11, so there is no teardown to wait for).
- **Provider readiness separation is a property and tests, not a new response field.** A new field on the capability response would need the OpenAPI contract first and is not required by the deliverable.
- **Added beyond the spec:** the metric and runbook section, `LeaseHolder.NodeID` plus the lane probe rule, the `NodeMediaNegotiator` refusal, and the capability-view gating. The first two are needed for correctness (the probe) or operability; the refusal is what makes placement safe before P5.11.
- The environment-to-identity pairing is the primary's topology (a context row names the account's environment) and the node binding is the profile registry; no topology column was added (it would need a migration), so a helper environment is a topology instance registered without a CDP endpoint, with a fleet-unique name.

## Follow-ups

- P5.11: a `NodeMediaNegotiator` (`HostsNodeSessions() bool`) that routes the offer by `session.NodeID` with the `LeaseGeneration` fence, `RenewVoice` -> `RenewMediaLease`, helper events -> `CommitTransition`, `ENDED` -> `ReleaseHold`; take the terminating hold for node-bound sessions once media starts; skip nothing else (activation is already skipped for them).
- Move the node slots and lanes into the shared admission store before running more than one primary, and re-take the slot of a surviving node-bound session after a restart (`LeaseHolder` would need the identity or the profile).
- An operator route to register helper environments in topology (no `remote_endpoint`, fleet-unique names) and to bind profiles (the P4.16 follow-up); until then nothing is helper-bound and nothing changes.
- Run the Postgres lease-contract entry and the metrics cardinality check against real instances.
