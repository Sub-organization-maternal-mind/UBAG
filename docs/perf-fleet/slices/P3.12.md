# P3.12 - Submission boundary on the local path: no replay after submit

Status: merged (see PR). Flag: `UBAG_WORKER_STRICT_SUBMIT` (default OFF; same flag the worker honours, P3.2).

## What changed
- `apps/gateway/internal/executor/submission.go` (new): typed `ErrNotSubmitted` / `ErrAmbiguous`, `classifySubmission`,
  prompt_submitted detection, detached fail-closed context.
- `daemonrunner.go`: `runJob` tracks, in process, whether a `prompt_submitted` line went by on this job's stream and types
  every failure (batch and streaming, deadline/cancel/daemon death/marker-failed). Cause stays in the chain
  (`errors.Is(err, context.Canceled)` still true). `runDaemonJob`/`streamDaemonJob` keep their signatures (tracked twins added).
- `workerconsumer.go`:
  - `ProcessWorkerRunner` failures are typed from the marker found in the stdout it captured.
  - RunOnce error path: `ErrAmbiguous` never reaches `lease.Retry` - not on shutdown (ctx cancelled), not on lease loss.
    The job ends `failed_terminal {submitted:true, retryable:false, reconcile_required:true, stream_end_reason:"error",
    reason:"post_submit_failure"}` (same shape engine.py emits), then `lease.Fail`. Terminal writes use a context detached from the
    cancelled parent (15 s cap). A user cancel (job already `canceled`) still wins and ends `canceled`.
  - Pre-submit (`ErrNotSubmitted`): shutdown keeps `lease.Retry` (new attempt on the next consumer); other pre-submit errors keep the
    existing `failed_retryable` + `lease.Fail` (no automatic gateway-side replay loop; see deviations).
  - Ingestion failures (invalid event, !=1 terminal, missing terminal, store apply error) whose events contain `prompt_submitted`
    fail closed too.
  - Env forwarding of `UBAG_WORKER_STRICT_SUBMIT` to the worker was found missing (P3.2 gap) but landed upstream in the shared
    `workerEnvAllowed` map during rebase; this slice only adds a regression test for it.
- Flag off: no wrapping, no new branches taken; the existing executor suite passes unchanged.

## Tests

## Deviations / follow-ups
- The boundary is coarse until P3.8 (durable attempt ledger): the marker lives in process memory. The worker buffers a turn's events until
  the interaction ends, so a daemon/process killed mid-interaction usually never printed `prompt_submitted` and reads as `ErrNotSubmitted`.
  ProcessWorkerRunner only sees the marker if the process flushed it before dying.
- If the fail-closed write itself fails, the lease is `Fail`ed (not retried) so nothing replays; the job stays non-terminal until the
  stale-job reaper settles it.
- Pre-submit failures other than shutdown are not auto-`Retry`'d at the lease: a persistent pre-submit failure (daemon cannot start) would
  otherwise spin at the poll interval. The job ends `failed_retryable` as today.
- NATS consumer (`natsconsumer.go`) has its own ack/nack paths and was not changed (local path only).
