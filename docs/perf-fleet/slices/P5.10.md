# P5.10 - Helper-side voice endpoint: MediaHub, loopback relay, browser and audio co-located

Status: merged when its PR is merged into `feat/perf-fleet`. Size L. Depends on P5.7, P4.12 and P5.6, all merged. The helper side of `HelperVoiceService` is complete and tested; nothing on the primary dials it yet (that is P5.11), so production behaviour is unchanged. The helper binary is still started by nothing, and its default build cannot serve voice (see the build tag below).

## What landed

- **Service core** `apps/gateway/internal/helper/voice.go`: `HelperVoiceServiceServer` (`OfferVoice`, `ReconnectVoice`, `ControlVoice`, `RenewVoice`, `StreamVoiceEvents`) on the same `Server` as `HelperService`, so it shares the node's identity gate, capacity bound, drain and shutdown. It imports gRPC and the proto only (the P4.11 import guard still holds). It owns what must hold whatever terminates the media:
  - **Fence**: node id must be this node, ids and attempt id are shaped, `lease_generation` is 1..2^53-1, `expires_at` must be in the future (`DEADLINE_EXCEEDED` otherwise). Every non-offer RPC needs the call's exact `(session, tenant, attempt, generation)`: another tenant's session is `NOT_FOUND` (same as unknown), any other attempt or generation, older or forged-future, is `ABORTED`. A newer generation of a session supersedes the older call; lower or equal is stale.
  - **One exclusive audio environment per call**: `instance_ref` names one of the node's `VoiceEnvironment`s (an unknown name is `FAILED_PRECONDITION`, a busy one `UNAVAILABLE`). The call also takes the node's identity gate (`provider = target`, `identity_ref`) and one unit of attempt capacity, so a voice call excludes a text attempt on the same identity and counts as one workload in `ReportCapacity` (D6, P5.5/P5.9 rule).
  - **Dead-man**: the lease starts at `fence.expires_at` clamped to `LeaseMaxTTL` (5 min), `RenewVoice` extends it (never shortens, clamped to now+TTL, a lapsed lease is never revived), and when it is not renewed the NODE ends the call by itself, with no help from the primary: the media is closed first, then the provider UI is deactivated, then everything is released.
  - **Teardown order**: `end()` closes the media synchronously (audio stops before any RPC returns), then `finish()` awaits an in-flight activation, runs `voice.deactivate` (bounded 45 s, the primary's terminating-hold cap), releases the environment and the identity, and only then writes the `ENDED` event. `ENDED` is therefore the node's acknowledgement that the provider session left voice mode, for the primary's terminating hold. A failed deactivation is a `WARNING` (`deactivate_failed`) and `data.deactivated=false`; it never pins the identity.
  - **Activation helper-local**: after the SDP answer is returned (the client waits on the answer, not on a provider page) the node runs `voice.activate` as a control job on its own `Runner` (the P4.12 pool: same identity lock and worker as every attempt) against the environment's loopback CDP endpoint. No WAN CDP endpoint exists: `VoiceEnvironment` has no host field. `CONNECTED` is written only when the provider is verified ready AND the client's peer connection is up (the primary-hosted rule). A failed activation ends the call `activation_failed` with a provider-state token (`login_wall`, `failed`, or the worker's state); worker text never leaves the node. A node with no runner refuses the offer before any media starts.
  - **Events**: bounded log (256, one slot kept for `ENDED`) per call, key `attempt_id:sequence`, replayed from `after_sequence` and followed until `ENDED`; kept `Retain` (1 h) after the end so the primary can read the tail. `end_reason`: `terminated`, `lease_expired`, `superseded`, `shutdown`, `drain_grace_elapsed`, `activation_failed`, `media_ended` (with a token `reason`), `offer_failed`.
  - **Control**: mute and unmute are fenced and idempotent (one event per change; the client's own data-channel mute is reported the same way); `TERMINATE` closes the media before returning and is idempotent (an unknown session reads as `UNKNOWN`, nothing left to end); `INTERRUPT` answers `UNIMPLEMENTED` (see deviations). `ReconnectVoice` and a repeated `OfferVoice` under the same fence renegotiate the live call's media (RECONNECTING, mute carried over) and never re-activate the provider.
  - **No secret**: `VoiceCredentials` (`relay_key`, `media_key`, `ice_servers` with primary-minted TURN credentials) is handed to the media endpoint and the service keeps no copy; the type prints as `redacted`. The helper has no field for a global secret, and its environment gate refuses `UBAG_VOICE_TURN_SECRET`, `UBAG_VOICE_RELAY_SECRET` and `UBAG_APP_SECRET`.
- **Media endpoint** `apps/gateway/internal/helper/voicehub` (new): `helper.VoiceMedia` over `voice.MediaHub`, reusing it unchanged except two additive hooks below. One `MediaHub` per call (its relay dialer and control authorizer carry that call's keys), pointed at the call's loopback relay:
  - the per-attempt relay key is written to the environment's key file (0600, atomically) before the relay is dialled, the dial sends the P5.7 BOUND hello (node + generation signed), and the file is removed when the call closes (a late Close of an older generation removes only a file that still holds its own key; calls are keyed by attempt and generation, not session);
  - the client's control data channel is authorised with the per-attempt media key only (`HelperVoiceSpec.MediaCredentialVerifier`);
  - media binds inside the configured UDP range, advertises the NAT 1:1 address as its host candidate, and uses the TURN credentials the primary minted for the attempt (`ICEConfig.FixedServers`; a TURN entry is used only with `UBAG_HELPER_VOICE_SERVER_VIA_TURN`). The node mints nothing;
  - a `Close` that races an in-flight `Open` undoes it (no media, no key, no entry); stale key files from a crashed run are removed at start, and an unwritable key directory refuses to start.
- **`voice.ICEConfig.FixedServers`** (`internal/voice/ice.go`, additive): pre-minted ICE servers replace `STUNURLs`/`TURNURLs`/`TURNSecret` for an endpoint that holds no TURN secret. `HelperVoiceSpec.MediaCredentialVerifier` (`attempt.go`) now takes the app id from the credential when the session has none (the fence carries no app id; the per-attempt key authenticates that field together with tenant, session and expiry). A caller that knows the app id keeps strict app binding.
- **Relay** `deploy/vps/browser/audio-relay.py`: `UBAG_VOICE_RELAY_KEY_FILE`. When set it replaces `UBAG_VOICE_RELAY_SECRET` (which is then ignored, never a fallback) and is re-read on EVERY hello, so no relay restart is needed per attempt (the P5.7 follow-up). A missing or empty file refuses every session (`unconfigured`). Wire protocol unchanged.
- **Settings and binary** (`config.go`, `voice_config.go`, `cmd/ubag-helper`): the voice settings below; `Settings.Open(runner, voice)` registers the service next to `HelperService` behind the same mTLS and primary-identity interceptors; the handshake advertises the `helper_voice` feature only when voice is configured. `runner.Config.ExtraEnv` lets the binary add `UBAG_VOICE_CDP_ALLOWED_HOSTS=127.0.0.1` to every worker (never a job; entries that are denied or carry primary-only configuration are refused), which is what lets the worker attach to the node's own loopback browser.
- **Build tag `helpervoice`** (`cmd/ubag-helper/voicemedia_on.go` / `voicemedia_off.go`): the media endpoint links `internal/voice`, and with it pion, pgx, modernc sqlite, `storekit` and `topology`: 253 non-std packages against 117 for the default helper. So the default binary does NOT contain it and refuses to start with `UBAG_HELPER_VOICE=1`; build with `go build -tags helpervoice ./cmd/ubag-helper` (see deviations for why not a split of `internal/voice`).

## Flags and env (all default off; none a secret)

On the helper process (`UBAG_HELPER_VOICE` is read alone there: the `UBAG_HELPER_NODES < PLANE < DISPATCH < VOICE` ladder is the primary's, which only dials the service when the whole ladder is on):

| Variable | Meaning |
|---|---|
| `UBAG_HELPER_VOICE` | `1`/`true`/`on`/`yes` serves `HelperVoiceService`. Default off: nothing is registered. |
| `UBAG_HELPER_VOICE_ENVS` | `<instance_ref>=<cdp_port>:<relay_port>,...` (1..8). Both ports are on `127.0.0.1` by construction; ports 1024..65535, all distinct. |
| `UBAG_HELPER_VOICE_KEY_DIR` | existing directory; the environment's relay key file is `<dir>/relay-key.<relay_port>`. |
| `UBAG_HELPER_VOICE_UDP_PORTS` | `<min>-<max>`, required, at least 8 ports per environment: the range the fleet manager opens. |
| `UBAG_HELPER_VOICE_NAT_1TO1_IP` | optional public IPv4 advertised as the host candidate. |
| `UBAG_HELPER_VOICE_SERVER_VIA_TURN` | optional; allow a TURN relay candidate (credentials come from the primary). |

On each environment's relay (browser container, same host): `UBAG_VOICE_RELAY_ADDR=127.0.0.1:<relay_port>`, `UBAG_VOICE_RELAY_KEY_FILE=<key dir>/relay-key.<relay_port>` (shared volume, same uid because the file is 0600), `UBAG_VOICE_RELAY_NODE_ID=<UBAG_HELPER_NODE_ID>`, and `UBAG_VOICE_ENV_ID=<id>` when environments share a PulseAudio server or `/tmp` (P5.6). Do not set `UBAG_VOICE_RELAY_SECRET` there. The browser's CDP proxy listens on `127.0.0.1:<cdp_port>`. Provider logins are out-of-band human logins in each environment's browser (D3); nothing here logs in, scrapes or stores credentials (safe mode).

## Deviations

- **Split and tag, not a bare import.** The work item says the helper reuses `voice.MediaHub`. Linking `internal/voice` into the default `ubag-helper` would take it from 117 to 253 non-std packages (pion, pgx, modernc sqlite, `storekit`, `topology`), against the P4.11/P4.12 bar that the node binary stays small and free of database code. The core (`internal/helper/voice.go`) is interface-only, the real endpoint lives in `internal/helper/voicehub`, and only a `-tags helpervoice` build links it; a test pins both builds. Splitting `internal/voice` into a media package and a store package would remove the tag but moves `Session` and touches P5.8/P5.9 files; recorded as a follow-up.
- **Files.** The work items name `voice/remote.go`, `httpapi/voice_handlers.go`, `httpapi/voice_control.go` and `serve/serve.go`: those are the primary-side `RemoteMediaNegotiator` and control forwarding, which the slice map assigns to P5.11 ("Primary RemoteMediaNegotiator and control forwarding", depends on this slice). Not touched. The work item's flag `UBAG_VOICE_HELPER_MEDIA` is stale; the binding flag is `UBAG_HELPER_VOICE`.
- **`INTERRUPT` is `UNIMPLEMENTED`.** The proto lists it, but the worker's voice job accepts only `activate|deactivate` and the relay has no barge-in control, so no provider-side primitive exists. Acknowledging it would lie; refusing it is honest. Needs a worker action or relay control first.
- **No `app_id` in the fence.** The media credential binds an app id the helper cannot know (the P5.7 fence and `OfferVoiceRequest` carry none, and the proto was not changed here). `MediaCredentialVerifier` takes it from the credential for a session without one; see above for why that is sound.
- **The primary picks the environment.** `instance_ref` is the environment name (`UBAG_HELPER_VOICE_ENVS` key); the node never picks "any free environment", because an environment is logged in as one provider identity and a wrong pick would use the wrong account. The environment-to-identity pairing is the topology the primary holds.
- **`DEVICES_LOST` and `INTERRUPTED` events are not emitted.** The hub reports a relay failure only as `relay_recv_failed`/`relay_send_failed`, so it surfaces as `ENDED` `media_ended` with that reason token.
- **A failed `ReconnectVoice` keeps the call.** `MediaHub` tears the old client leg down before it re-dials, so the call has no media after a failed reconnect; the node does not end it (the client may retry) and the dead-man or a terminate ends it eventually.
- **Context index (P5.6).** A helper environment hosts one provider context, so no `context` index is sent in the control jobs.
- **Fence expiry on every RPC.** `fence.expires_at` must be in the future on every RPC (proto mapping `DEADLINE_EXCEEDED`); for Offer it is the lease start (clamped), for the others the primary sends a current value (the keys are not re-derived from it). A reader of the tail of an ended call therefore needs a fresh expiry too.
