# P3.5 - Worker env passthrough, chat-ledger sink in daemon, mock synthetic knobs

Status: merged (see PR).

## Changes
- `minimalWorkerEnv` now forwards UBAG_WORKER_SLOT_ID, UBAG_WORKER_IDENTITY_LOCK, UBAG_WORKER_STREAM_EVENTS,
  UBAG_WORKER_STRICT_STREAM_END, UBAG_WORKER_STRICT_SUBMIT, UBAG_MOCK_SYNTHETIC. UBAG_ORCHESTRATOR_ENABLED is deliberately not forwarded.
- `WarmWorkerDaemon(chat_sink=...)`; `run_worker_daemon.py` wires `chat_ledger.chat_sink_if_enabled()` (UBAG_CHAT_LEDGER_ENABLED, existing flag,
  default off). The sink is passed to the engine factory only when set, so the default path is unchanged.
- Mock adapter: `mock_delay_ms` (<=60 s), `mock_fail`, `mock_result_bytes` (<=8 MiB) honoured only when UBAG_MOCK_SYNTHETIC is truthy.
  `mock_fail` raises MockAdapterError after queued/running. A >512-event output trips the gateway maxWorkerEvents error (explicit failure).

## Flags
UBAG_MOCK_SYNTHETIC (new, off). UBAG_CHAT_LEDGER_ENABLED (existing, off). No migrations.

## Checks run
`go vet ./internal/executor`; `go test ./internal/executor -run Env`; pytest adapters/mock/tests; pytest test_chat_ledger.py + test_warm_daemon.py.
## Not run
Full suites; an end-to-end gateway run proving the maxWorkerEvents failure (only asserted adapter-side that >512 events are produced).

## Deviations / follow-ups
- The ledger path is node-local on helpers; primary reaper cannot see helper chats (P4 concern).
- Adapter `mock_fail` is raised as an exception (runner reports failed) rather than a custom failed event.
