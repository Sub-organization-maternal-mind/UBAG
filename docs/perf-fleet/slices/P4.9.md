# P4.9 Fenced idempotent commit and helper ingest validation

Status: merged when its PR is merged into `feat/perf-fleet`. Size L. Depends on P4.2 (attempt ledger), P4.5 (trust plane), P4.7 (`HelperAttemptSpec`), all merged. Inert: nothing in the gateway constructs a `HelperIngest` yet (the helper dispatcher, later P4.x, is the first caller, behind `UBAG_HELPER_PLANE`); no flag, no migration, no route, no contract change.

## What landed

- **`jobs.FencedApplier`** (`jobs/store.go`, next to `ScopedStore`): the optional commit capability `CommitEvents(ref, events)`. P4.2 already implemented exactly this behaviour (fence check and per-event key dedupe in ONE transaction; all-or-nothing; replay-safe; Postgres and memory), so this slice only names it: `AttemptStore` now embeds `FencedApplier` (no behaviour change) and the executor depends on the narrow capability. `jobs.ValidateWorkerEventData` is exported (one-line wrapper) so the ingest layer classifies a payload with the store's own rules instead of guessing from a store error.
- **`executor/helperingest.go`**: `OpenHelperIngest(ctx, cfg, binding)` and `(*HelperIngest).Accept(ctx, *helperv1.AttemptEvent)`. One session per attempt stream.
  - **Binding is trusted-side only**: `HelperIngestBinding{TenantID, AppID?, JobID, AttemptID, Generation, NodeID, InputFingerprint?, WorkloadVersion?, ResumeAfter}`. `NodeID` is the authenticated certificate identity (or the dial's pinned identity), `TenantID` is the tenant the primary dispatched the attempt for. Nothing identity-bearing is taken from a message. `HelperBindingFromFence` builds one from a helper `Fence` (its `node_id` is only a cross-check).
  - **Open-time checks** (once; tenant, app, node and attempt id are immutable on their rows): the job exists and belongs to the tenant (a missing job and another tenant's job give the same `ErrHelperIngestScope`), the attempt exists, its ledger node equals the authenticated node, fingerprint/workload match when given, generation equals the ledger's, attempt not expired. The live fence (generation + active) is enforced again inside every commit transaction.
  - **Per event**: attempt id and lease generation must equal the binding (else fenced); sequence must be the next one (replays at or below the high-water mark are re-validated and committed idempotently, free of budget); the event type must be in the allowlist (the 7 non-terminal proto types mapped to `running`, `browser_opened`, `session.manual_action_required`, `prompt_submitted`, `token`, `artifact_created`, `warning`; `TERMINAL` is projected from the outcome; UNSPECIFIED and unknown values fail closed); `data_json` must be a JSON object within the byte cap; identity keys in data (`job_id`, `tenant_id`, `app_id`, `node_id`, `attempt_id`) must equal the bound value or the event is a scope violation; `novnc_url` and `session_id` are dropped (a helper has no viewer broker, D3); the gateway then stamps `data.attempt_id` and `data.helper{node_id, lease_generation}` over anything the helper sent (node-namespaced provenance) and the event id is `<attempt_id>:<sequence>` (helper proto key). `prompt_submitted` calls `MarkSubmitted` on the ledger BEFORE the event commits, so a crash between the two can only err toward "may have been submitted" (D4).
  - **Terminal projection** (the gateway owns the outcome-derived keys; helper data cannot smuggle `status`, `result`, `retryable`, ...): `COMPLETED` needs a non-empty JSON-object `result_json` and must not be `partial` (a partial completion is a contract violation, never a success); `TIMED_OUT` / `CANCELLED` / `FAILED` must not carry `result_json`; `TIMED_OUT` ends `timed_out` with `data.partial` (the helper's object, else `{token_count: n}` of the provisional tokens seen) and no result; `FAILED` is `failed` (retryable) before the submission boundary and `failed_terminal` with `submitted` and `reconcile_required` once the session or the helper saw it (D4); `error_code` / `stream_end_reason` must be short tokens; the error message is cut to 512 bytes on a rune boundary.
  - **Two failure classes**. Entitlement failures (wrong node/tenant/job/attempt, stale or superseded generation) and sequence gaps are REJECTED: nothing written, audited, the legitimate holder unaffected. Content failures (type outside the allowlist, malformed or oversize data, a payload the store policy refuses, output over the per-attempt budget, a partial "completed") FAIL THE ATTEMPT: a `failed_terminal` event with gateway-composed text only (`error_class` `helper_output_limit` or `helper_event_invalid`, `submitted`, `reconcile_required` once past the boundary) is committed through the same fence and the session ends. Over-limit output is therefore never truncated into a success.
  - **Caps** (`HelperIngestLimits`, zero = default): 60 KiB per `data_json` and per `result_json` (below the store's 64 KiB so the stamps always fit; a larger configured value is clamped), 4 MiB and 4096 events per attempt (every event is a stored row).
  - **Audit** (`audit.Store`, optional; one record per distinct action and reason per session so a misbehaving helper cannot flood the chain; an audit failure never masks the rejection): `attempt.fenced_rejected` with `error_code` `UBAG-WORKER-NODE-FENCED-005` for a fenced writer, `helper.policy_violation` (`job_scope`, `node_mismatch`, `unknown_attempt`, `fingerprint_mismatch`, `data names another <key>`, `sequence ...`, `helper_output_limit`, `helper_event_invalid`) for the rest. Actor `node:<id>`, outcome `denied`, attributes carry only ids, the generation and fixed reason text, never helper-supplied text. Names follow the P2.5 vocabulary.
  - **Fenced is final**: a commit rejected by the ledger ends the session (a superseded generation never comes back); a transient store error leaves it open and the same event can be retried (the commit is idempotent on the event key). A failure that could not be recorded transiently also leaves the session open (the failure event key is stable).
  - A compile-time assertion keeps `MemoryStore` and `PostgresStore` satisfying `HelperIngestStore`; SQLite does not (no ledger, P4.2).
- **Tests**
  - `executor/helperingest_test.go` (memory store, real ledger): end-to-end commit incl. provenance and ledger `finished`+`submitted`; stale generation rejected with the job, its events and its dedupe state untouched, audited under the `UBAG-WORKER-NODE-FENCED-005` code, session ended, new session for the superseded lease refused, successor unaffected; event-level generation/attempt mismatch (one audit record per reason); cross-tenant, cross-app, missing job, foreign node, unknown attempt, fingerprint and workload mismatches refused and audited under the claimed tenant; identity claims inside data; duplicate commit idempotent in-session, across a reconnect, after completion (lost ack) and with `ResumeAfter`; sequence gap rejected without failing; over-limit table (per event, clamp, oversize completed result, cumulative bytes, event count) x (before / after the submission boundary): attempt failed `failed_terminal`, no result, no `completed` event anywhere, `reconcile_required` iff submitted; 13 contract-violation cases fail the attempt; sanitizer (cookie/api_key/password/storage keys redacted, `novnc_url`/`session_id` stripped, no secret in the serialized log); terminal outcome mapping (deadline cut, pre/post-submit failure, helper-flagged reconcile, cancelled); gateway-owned outcome keys and message truncation; a superseded writer that also sends oversize output is told it is fenced, nothing recorded; transient store error retryable and does not fail the attempt (and the boundary was already recorded); session stays open when the failure commit itself fails; `HelperBindingFromFence`; allowlist cannot drift from the proto enum or the store vocabulary.
  - `jobs/attempts_contract_test.go` (shared by memory and, env-gated, Postgres): a fenced commit leaves the job byte-identical even with a terminal event and does not consume the dedupe key; commit redacts secret-bearing keys and refuses secret values all-or-nothing.

## Deviations

- `FencedApplier` is a name for P4.2's `CommitEvents`, not a second implementation: the spec (written before P4.2) asked for a new capability whose fence and dedupe share one transaction, which `AttemptStore.CommitEvents` already is on both stores. `AttemptStore` embeds it; no store code changed.
- `jobs/store.go` gained only the interface; the Postgres and memory stores, and `workerconsumer.go` / `conversations.go` listed in the work item, are untouched. The local consumer keeps plain `ApplyWorkerEvent` (the helper path is separate). `conversations.go`: the helper event enum has no conversation event type, so a helper cannot bind a thread through this path; see the follow-up.
- The tenant check is made at open against the dispatch-time binding, not as an `AttemptRef` field inside every commit: tenant, app and node are immutable on their rows, so a one-time check cannot go stale, and it keeps the P4.2 store contract unchanged.
- The spec's "RemoteWorkerRunner" (`remoterunner.go`) is not built: it is the dispatcher (lease renew every 20 s, `RunAttempt` stream, reconcile), which depends on the primary-to-helper dial that P4.5 deliberately left out. This slice delivers the ingest/commit half the runner will call.
- Accept commits one event per call (one transaction per event, like the local path's `ApplyWorkerEvent`). `CommitEvents` already supports batches of up to 256; batching tokens is a later optimisation and is not needed for correctness.
- Sequence gaps are rejected, not failed: a gap can only mean a reconnect, and failing the attempt would turn a resume into a terminal job. `ResumeAfter` is how a reconnecting dispatcher resumes.
- The partial-count key is `token_count`, not `token_events` (the Python worker's `partial.token_events`): `payloadpolicy` refuses any key with a `token` segment except `token_index` and `token_count`.
- No new error code: output-limit and invalid-event failures use `error_class` (`helper_output_limit`, `helper_event_invalid`) like the existing `worker_execution`; the catalog code used is the P2.4 suffixed `UBAG-WORKER-NODE-FENCED-005`.

## Follow-ups

- **Latent bug in the local D4 path (not touched here)**: the Python worker's deadline-cut `timed_out` event carries `data.partial.token_events` (`apps/worker/ubag_worker/live/engine.py`). `payloadpolicy.Validate` refuses any key with a `token` segment other than `token_index` / `token_count`, and the store runs it on worker event data, so with `UBAG_WORKER_STRICT_STREAM_END` on the gateway would reject that event and fail the job instead of ending it `timed_out`. Rename the key to `token_count` (or exempt it in `payloadpolicy`) before enabling the flag; add a gateway-side test that applies that exact event shape.
- **Dispatcher (later P4.x)**: `BeginAttempt` then `OpenHelperIngest` with the binding from the dispatch record and the authenticated node, one `Accept` per streamed event, treat `errors.Is(err, jobstore.ErrAttemptFenced)` as a lost lease (stop, no retry), a content failure as a finished job (close the stream, cancel the helper), a gap or transient error as reconnect-and-replay with `ResumeAfter`; call `RenewAttempt` on the 20 s cadence; run the `ExpireAttempts` sweeper (P4.18) and fail `submitted` attempts with `reconcile_required`.
- **Conversation binding from helper output**: when the dispatcher reads a provider thread URL out of a completed result, it must bind `NodeID`/`ProfileRef` from the trusted attempt record (P4.16), never from helper data.
- **Manual-action events from a helper**: `session.manual_action_required` passes through (its `novnc_url`/`session_id` are stripped); raising the operator alert and login-state side effects live in `WorkerConsumer.RunOnce` and need the same treatment on the helper path.
- Audit failure currently only logs (P4.5's note applies: make the append fail closed in P4.8); the per-session audit dedupe is in memory, so a reconnect loop can still write one record per reason per session.
- Run the Postgres tests (see Checks not run) before relying on the Postgres path.
