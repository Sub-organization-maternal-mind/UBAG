# P4.6 - Attempt capability tokens and app-JWT audience guard

Status: merged. Library only: nothing in the gateway issues or accepts attempt tokens yet (the asset RPCs and the primary-to-helper dial are later P4 slices). Inert; no flag is read by this slice (the consumers sit behind `UBAG_HELPER_PLANE`).

## What landed
- `apps/gateway/internal/attemptcap/attemptcap.go` (new package):
  - Token: RS256 compact JWT, header exactly `{"alg":"RS256","typ":"ubag-attempt"}`, claims `aud=ubag-helper`, `node`, `attempt`, `generation`, `job`, `tenant`, `keys[]`, `ops[]` (`read`/`write`), `iat`, `exp`. Strict decode (unknown claims rejected), 8 KiB cap, <=64 keys, attempt id must match the ledger convention (`jobs.ValidAttemptID`).
  - `Issue(attempt, tenant, keys, ops, ttl, now, priv)`: `exp = min(now+ttl, attempt lease)`; refuses a non-active attempt, ttl outside (0, 15 min], a lapsed lease.
  - `Renew`: verifies the old token (signature, not expired), checks it still matches the attempt row (node, attempt, job, generation), then re-signs with a new `exp = min(now+ttl, lease)`. All other claims, `iat` included, are copied unchanged.
  - `Verify(token, pub, Expect)`: signature, typ/aud, shape, expiry, then node (`ErrWrongNode`), generation (`ErrWrongGeneration`), attempt/job/tenant (`ErrWrongBinding`), `exp` beyond the lease (`ErrLeaseExceeded`), key/op not granted (`ErrNotAllowed`). Every expectation field except key/op is required, so a zero value fails closed.
  - `Authorize(ctx, jobs.AttemptStore, token, pub, Request)`: the call every asset RPC makes. It loads the LIVE attempt row from the ledger (`ListAttempts`), requires it to be `active`, and verifies the token against that row's generation, node and current lease. A fenced/superseded/finished/unknown attempt returns `ErrFenced` even though its token has not expired.
  - `EnsureSeparateKey(attemptKey, appPublicKey)`: refuses a key under 2048 bits or equal to the app-JWT public key.
- `apps/gateway/internal/appjwt/appjwt.go`: `Verify` now rejects any token whose payload carries an `aud` member (string, array or null) and any token with header typ `ubag-attempt`, returning `ErrInvalid`. `AppClaims` is NOT widened. `resolveAppJWT` in `httpapi/server.go` is the only caller and already maps any `Verify` error to "not authenticated", so no change to server.go was needed; a test pins the behaviour at the HTTP layer.
- Tests: `attemptcap_test.go` (round trip, exp clamped to lease, expired / wrong node / wrong generation / wrong attempt, job, tenant / exp beyond lease / wrong key set / wrong op / wrong signer, Issue refusals, alg=none and tampered payload, mutual rejection with `appjwt`, renewal keeps claims except exp, separate-key guard, `Authorize` against the memory attempt store including supersession); `appjwt_test.go` (aud string/array/null and typ rejected, baseline still verifies); `httpapi/appjwt_auth_test.go` (attempt token gets 401 on `/v1/jobs`, even when signed with the app key).

## Flags / migrations
None added. Intended consumer flag: `UBAG_HELPER_PLANE` (default off).

## Semantics worth knowing
- The ledger, not `exp`, is the fence (ADR-0007): a lapsed-but-unsuperseded attempt still authorizes until it is superseded or reaped, consistent with `CommitEvents`. `exp` only guarantees a leaked token dies with its lease.
- The token is a capability, not an identity. The caller passes the mTLS node (helperauth) as `Request.Node`; a token presented by another node is rejected.
- Tenant is supplied by the caller (from the job it looked up); the attempt ledger rows do not carry it.
- Key format is opaque to this package (exact string match); the asset RPC slice defines key naming.

## Deviations
- `httpapi/server.go` unchanged: the audience guard lives in `appjwt.Verify` (single caller), the smaller and safer place.
- No PEM loading/config for the attempt keypair yet; there is no consumer. `EnsureSeparateKey` is the startup guard to call when the helper plane wires the key.
