# P4.4 Node, allocation and node-registry store

Status: merged into `feat/perf-fleet`. Size L. Depends on P2.4, P4.1, P0.3 (all merged). Inert: nothing reads or writes the store unless `UBAG_HELPER_NODES` is on, and no consumer exists yet (trust plane P4.5, allocation poller P4.15, placement land later).

## What landed

One consolidated store in `apps/gateway/internal/nodes` (memory + Postgres) with three kinds of data per node:

- **Allocations**: the latest accepted manager grant (`node-allocation.schema.json` v1 fields, no tenant or job ids) plus `AcceptedAt`. `ApplyAllocation` validates (schema rules plus the cross-field ones the schema cannot express: URI SAN equals `spiffe://ubag/node/<node_id>`, udp range order, voice needs range and NAT ip) and fences on `generation`: lower is `ErrStaleGeneration`; equal is accepted only when identical or differing in `valid_until` alone (a renewal), otherwise `ErrGenerationConflict`; higher replaces.
- **Helper state**: liveness (`LastHeartbeat`), pressure hysteresis (`PressureReduced`, `PressureCalmSince`, rebuilt with `HelperState.Pressure()` / stored with `WithPressure`), `RampedLimit`, host cores and memory (the input the P4.1 ceiling needs). Only for a node that has an allocation; a write older than the stored heartbeat is ignored (never rewinds liveness).
- **Pinned-SPKI registry**: URI SAN, SPKI SHA-256 `current` and `next` pins (rotation), sticky `RevokedAt`. `RegistryEntry.Matches(uriSAN, spki)` is the check P4.5 will call: not revoked, URI SAN equal, constant-time pin compare against current or next, empty pin never matches. `PromoteSPKI` ends a rotation; `RevokeNode` is idempotent (first time wins) and a revoked entry cannot be re-pinned.
- An accepted `state=revoked` allocation also revokes the node's registry entry in the same transaction, and the registry refuses new pins for a node whose accepted allocation is revoked, so the registry is the single authority the trust plane needs.
- Every table is bounded to `MaxNodes` = 256 (the schema's `allocation_list` maxItems): `ErrTooManyNodes` for a new node past the cap, updates of existing nodes still work.
- `Allocation.Grant()` converts to the P4.1 `Grant`, so `Evaluate(alloc.Grant(), state.LastHeartbeat, now, state.Pressure(), state.RampedLimit)` works straight from the store (covered by a test).
- The attempt table from fleet-03 is NOT here: P4.2 owns `0022_gateway_job_attempts`.

## Flags

- `UBAG_HELPER_NODES` (default off). Off: no store is built, nothing touches the tables. On: memory store (warns, per-process) or Postgres store (`Ready` asserts the three tables exist, never runs DDL). On with `UBAG_GATEWAY_STORE=sqlite` (the edge store) or any other store kind: gateway startup fails ("not supported"); SQLite deliberately has no implementation and no migration.

## Migrations

`migrations/postgres/0023_helper_nodes.sql` only. Applies automatically with the rest of `migrations/postgres/*.sql` on deploy; it creates three empty tables and changes no runtime behaviour while the flag is off. No SQLite migration (SQLite refuses helper mode).

## Deviations

- Migration is `0023`, not the `0022` the work item text says, per the P0.3 allocation table (0022 is reserved for P4.2's attempts table, which fleet-03 originally bundled).
- Three tables instead of one wide row, because the allocation poller, the heartbeat path and the cert registry write at different cadences and must not clobber each other's columns.
- `ApplyAllocation(state=revoked)` revoking the registry, sticky revocation, the equal-generation rule (renewal of `valid_until` allowed, any other change needs a generation bump) and the 256-node cap are design choices the spec leaves open; all fail closed. The schema itself only says a lower generation is stale.
- `security-03`'s sqlite migration and `sqlitestore/schema.sql` changes are not done: the slice deliverable says SQLite refuses helper mode. The rest of security-03 (mTLS listener, interceptor, `helperauth` package) is P4.5.
- The URI SAN format `spiffe://ubag/node/<node_id>` is taken from P4.5's deliverable and enforced here (`NodeURISAN`, `NodeIDFromURISAN`); the manager must issue certificates that way.

## Follow-ups
