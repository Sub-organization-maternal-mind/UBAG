# P5.5 - Voice lease excludes text and file jobs on the same browser

Status: merged (gateway code + tests + docs). On by default whenever voice sessions are configured (kill-switch `UBAG_VOICE_LANE_EXCLUSION=0`); it changes nothing while no voice session holds a browser. No deploy, no production access. Voice itself stays contained in production until the P5.4 evidence exists (this slice removes the "jobs interfere with a live call" blocker, it does not enable voice).

## What landed

The zcode review's unmet P1 ("ordinary text/file jobs must not change tabs, provider state or shared audio on an environment leased for voice") now holds in both directions. See `docs/adr/0012-voice-excludes-browser-jobs-on-a-shared-browser.md` for the design and its limits.

- **Browser Lane** (`apps/gateway/internal/topology/lane.go`, new): `BrowserLaneKey(endpoint)` names a physical browser by the host and port of its CDP endpoint (tenant-free; `ws://Browser:9222/devtools/..` and `http://browser:9222/` are one lane; "" for no endpoint). `ConcurrencyRegistry` gains `EnterLane(kind, lane)` / `LaneHolders(kind, lane)` / `UseLaneBackend`, and `LaneHold.Renew/Release`. Two kinds: `LaneJob` (a running job) and `LaneVoice` (a voice admission in flight). Process-local counts by default; with `UseLaneBackend` they are expiring tokens in the shared admission store (`TokenBackend.LaneLive` is the one new backend method; 90 s TTL, renewed by the job heartbeat, swept by the existing admission sweeper).
- **Voice side** (`voice/voice.go`, `sqlite.go`, `postgres.go`, `lane.go`): `Store.ListLeaseHolders(now)` lists the live-mode sessions that reserve a browser (live ones and terminated ones inside their terminating hold, across tenants, utterance sessions never). `voice.LaneProbe` turns that into "does a session hold this lane?" through topology (instance -> registered CDP endpoint -> lane), failing closed: a holder whose lane cannot be worked out, or a store/topology error, counts as held. The session's own lease IS its hold, so every replica, restart and terminating hold is covered without a second copy of the lease.
- **Voice handlers** (`httpapi/voice_handlers.go`): `voicePlacements` (used by create and by the connect-time claim) now registers `LaneVoice` on each candidate's lane, drops candidates whose lane has a running job, and returns a release the caller invokes right after `Reserve`/`Claim` returns. A session whose browser has a running job is not offered that placement, so it queues (202), and `connect` answers the documented 409 "no environment free". `voiceCandidates` is the old read-only resolution (the capability view still uses it and registers nothing).
- **Job consumer** (`executor/voicelane.go`, `workerconsumer.go`): after the exec lease and before the job is assigned, a job that drives the shared browser registers `LaneJob`, then checks for a voice admission in flight and asks the probe; a held lane returns the lease to the queue after a delay (`retryAfterDelay`, the generalised `retryAfterOverload`: exec lease released first, 2 s hold, then Retry; never failed, never run, not assigned so it stays `queued`). A lapsed shared registration cancels the run like a lost exec lease. Jobs that share no browser are untouched: `mock`, `antigravity_sdk`, `antigravity_cli`, jobs with no `UBAG_REMOTE_BROWSER_ENDPOINT`, and the gateway's own `voice.` control jobs (they run for the session that holds the lane).
- **Order**: both sides register first and look second (job: register, then look at voice admissions and the store; voice: register, look at running jobs, Reserve/Claim, then release). That makes the exclusion race-free without a lock across the two stores (argued in `topology/lane.go`, stress-tested in `TestLaneProtocolNeverOverlapsJobAndVoice`).
- **Shutdown fix on the way**: `retryAfterDelay` returns `ctx.Err()` when the context ended during the hold, so a queue that always has the held job cannot keep the consumer loop alive after shutdown (found by the spin test; also fixes the same latent case for pool overloads).
- **Wiring** (`serve/voicelane.go`, `serve.go`): `wireVoiceLaneExclusion` builds the probe, sets `httpapi.Config.VoiceLaneExclusion` and `consumer.VoiceLanes`, and moves the registrations to the admission store only when `UBAG_VOICE_STORE` is postgres (warns when that store is shared but `UBAG_ADMISSION_SHARED=0`).
- **Docs / deploy**: ADR 0012, `CONTEXT.md` (Browser Lane), `ALLOCATION.md` (ADR 0012), `live-voice.md` guide bullet, `UBAG_VOICE_LANE_EXCLUSION` passthrough (empty = default) in `docker-compose.vps.yml`, `docker-compose.small.yml`, `deploy/small/env.example`.

## Flags (defaults)

| Flag | Default | Effect |
|---|---|---|
| `UBAG_VOICE_LANE_EXCLUSION` | on when voice sessions are configured (`0`/`false`/`no`/`off` = off) | voice and browser jobs exclude each other on a shared browser |
| `UBAG_VOICE_STORE=postgres` | unchanged | additionally makes the lane registrations shared across replicas |

No migrations (the lane tokens reuse the migration-0021 admission tables; the voice query only reads existing columns). No contract, OpenAPI or SDK change: a session that cannot take its browser queues (202), and connect answers its existing 409.

## Deviations / notes

- **Default on, not inert.** BINDING rule 5 asks for inert-by-default flags. This one is a safety gate for enabling voice (the deliverable: voice may be enabled in production only after this), so the unsafe state is the one that would need the opt-in. It is inert in practice: with no live voice session the job path adds one map operation (process-local registry) and one memory-store scan, and the voice path nothing. With a shared voice store it adds the lane token round trips to browser jobs; production uses the memory voice store, so it does not. `UBAG_VOICE_LANE_EXCLUSION=0` restores today's behaviour exactly.
- **Lane = browser, not identity.** Jobs carry no account or instance at the gateway (their only handle on the physical browser is the worker's `UBAG_REMOTE_BROWSER_ENDPOINT`, which is also what `daemonIdentityKey` hashes), so the browser is the finest thing both sides can name. Voice's per-account lease is unchanged (voice vs voice stays in the voice store). One browser hosting two accounts is one lane, which is what the audio devices need. The pool's identity key (`sha256(cdp endpoint + target)`) is untouched; the lane key deliberately ignores the target and the URL scheme/path.
- **The long-lived hold is the voice lease, not a registry token.** The spec asked for a shared lane token; copying the lease into the registry would need release hooks on every termination path (client terminate, media end, sweeper, reconciler, terminating hold) and re-adoption after a restart. The consumer reads the lease through `LaneProbe` instead, and only the transient halves are tokens.
- **Held jobs wait at the head of the queue.** Same limit as ADR-0011: the file spool re-queues a Retry under the same name, so a held browser job also delays jobs behind it that do not need the browser (on the serial consumer; the pool consumer pins up to its size). The stale-job reaper's idle `MaxLifetime` can time out a job held through a very long call. A one-browser deployment that needs text and voice at once should dedicate a browser to voice.
- **Fail-closed side effect.** A live session whose instance is missing from topology, or has no registered endpoint, counts as holding every browser lane for jobs that do drive a shared browser (until it ends or its lease is swept, at most the lease TTL plus the 30 s sweep). Voice cannot activate without a registered endpoint, so this only occurs through topology churn.
- Rebased over P3.10 (streaming ingest) and P4.23 (helper-plane metrics): `runWorkerWithCancellation` now takes both the lane hold and P3.10's `ingest`. The lane registration is held for the whole `RunOnce`, streaming or not. A lapsed lane registration cancels the run but is not reported through P4.23's `helpermetrics` (its lease kinds are the helper-plane ones).
- Pre-existing and left alone: `internal/httpapi/topology_handlers.go` is not gofmt-clean on this branch.
- PROGRESS.md / AGENT_HANDOFF.md not edited (BINDING rule 10); P8.1 consolidates.
