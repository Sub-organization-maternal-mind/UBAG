# P5.8 - Voice lease generation, node id and terminating hold

Status: merged (store layer + flag-gated primary wiring of the hold; nothing binds a session to a Helper Node yet because no helper dispatch plane exists at this tip). Flag `UBAG_HELPER_VOICE` default off.

## What landed
- Migration `migrations/postgres/0025_voice_lease_generation.sql` (number from ALLOCATION.md; 0022 and 0024 are other slices'). Four additive, idempotent columns on `gateway_voice_sessions`: `node_id TEXT NOT NULL DEFAULT ''`, `lease_generation BIGINT NOT NULL DEFAULT 0`, `media_lease_expires_at TIMESTAMPTZ`, `terminating_until TIMESTAMPTZ`. No index changes. Self-records as `0025` like 0019-0023.
- `voice.Session` gains `NodeID`, `LeaseGeneration`, `MediaLeaseExpires`, `TerminatingUntil`, all `json:"-"`; `TestSessionJSONCarriesNoInternalLeaseState` pins the exact wire JSON (golden) and `TestVoiceSessionResponsesHideInternalLeaseState` checks the GET/list bodies of a node-bound session. The OpenAPI session object is unchanged (open object; nothing new is serialized).
- `voice.Store` gains five methods, implemented by the memory, SQLite and Postgres stores with identical semantics:
  - `BindNode(tenant, session, node, mediaTTL, now) (Session, error)`: records the node, grows `lease_generation`, opens the media lease; needs a live session with an unexpired lease.
  - `RenewMediaLease(..., fence, until, now)` and `CommitTransition(..., fence, from, to, ...)`: single-statement CAS fenced by `(node_id, lease_generation)`. A miss is classified with the P5.7 errors: `ErrNodeMismatch`, `ErrStaleGeneration` (older or forged future generation), `ErrNotFound` (also cross-tenant), `ErrConflict` (not live / lease lapsed / wrong `from`), `ErrBadBinding` (zero or malformed fence).
  - `BeginTerminate(..., reason, hold)`: the session reads terminated at once but keeps its account and environment until `ReleaseHold` or `hold` (clamped to `voice.TerminatingHoldMax` = 45 s, the deactivate timeout). `hold <= 0` is plain `Terminate`; a queued or already terminated session holds nothing; repeated calls keep the first hold.
  - `ReleaseHold(..., fence, now)`: the deactivate ack. Fenced (zero fence for primary-hosted sessions), idempotent, `ErrConflict` for a live session (its leases are never released here).
- `SweepExpired` also terminates a node-bound session whose media lease lapsed (`last_error = media_lease_expired`; the client lease reason `lease_expired` wins when both lapsed) and cleans elapsed holds (not reported as swept). Renew and sweep agree on the instant (`> now` vs `<= now`), so a lapsed media lease is never revived.
- Admission (Reserve and Claim, all three stores) counts a terminating hold as taken: `status IN (connecting, connected) OR terminating_until > now`. The partial UNIQUE indexes still cover live statuses only; the hold is enforced by the in-transaction check (a held row was live up to the instant it began holding, and a successor can only appear after the check sees the hold). A terminated session's `identity_ref` / `instance_ref` are blanked on read (`visible`), so clients still see a terminated session with no leases.
- Primary wiring behind the flag (`voice_control.go`, `voice_handlers.go`, `server.go`, `serve.go`): `Config.VoiceTerminatingHold` (from `voice.HelperVoiceEnabled(os.Getenv)`, requires `VoiceProviderActivation`). `terminateVoiceSession` is used by explicit terminate and by activation failure: when provider voice was requested on this replica it calls `BeginTerminate(..., TerminatingHoldMax)`, otherwise plain `Terminate`. `VoiceMediaEnded` calls `ReleaseHold` after the deactivate job succeeds; a failed deactivation does not ack, so the hold runs out at its cap. This closes the lease-released-before-deactivate race (`voice_handlers.go` terminate path) for those paths.
- SQLite: `Ready` adds the four columns to an existing `voice.db` (`pragma_table_info` + `ALTER TABLE ADD COLUMN`, idempotent); new databases get them in `CREATE TABLE`.
- Postgres `Ready` additionally asserts the four columns (fails closed with a pointer to 0025, like the 0019/0020 objects).

## Deviations
- Migration file name/number follow ALLOCATION.md (`0025_voice_lease_generation`), not the work item's `0022_voice_lease_generation`.
- The work item's flag name `UBAG_VOICE_HELPER_MEDIA=0` is stale; the binding flag is `UBAG_HELPER_VOICE`.
- The hold is enforced by the admission check rather than by widening the partial UNIQUE indexes (which would mean dropping and recreating them on a live table). Consequence: the index is not a backstop for a hold (see above for why none is needed).
- The terminating hold is only taken when provider voice was requested on the replica that serves the terminate (it is what guarantees a `VoiceMediaEnded` ack follows). A terminate served by another replica, and the media hub's own `OnClosed` terminate (peer failure), still release immediately, as before.
- The store-backed `HelperVoiceLease` (needs the attempt id from the 0022 attempt ledger) is not provided; `Session.NodeID` / `LeaseGeneration` are what it will read.
