# P2.6 - Truthful queue depth: GET /v1/jobs/summary

Status: merged.

## What landed
- Contract: OpenAPI `GET /v1/jobs/summary` (`getJobsSummary`, schema `JobsSummary`: `total`, `counts_by_status`, `queued_by_reason`, `oldest_queued_at` (nullable), `kind=jobs_summary`). Manifests regenerated with `tools/make-sdks/generate-manifest.mjs`.
- SDKs: TS `getJobsSummary` + `UbagJobsSummary`; Go `GetJobsSummary`; conformance scenario `jobs.summary.ok` mapped in both SDK conformance tests.
- Gateway: `apps/gateway/internal/httpapi/jobs_summary.go` (route + `routePattern` metric label). Authorised with `job:read`, scoped to the caller tenant/app. Counts come from the existing `MetricsStore.CountsByStatus` (memory/sqlite/postgres all implement it), so no store or migration change. `oldest_queued_at` = `created_at` of the first row of an ascending `List(status=queued, limit 1)` (job rows carry no separate queued-at timestamp).
- `queued_by_reason` is always `{}` until P6.2 computes a queue reason (D8: read time, no migration).
- Dashboard: Overview and Metrics take `jobs_total`/`jobs_failed` (+ `jobs_queued` on Metrics) from the summary via `parseJobsSummary`/`failedCount` (`lib/api/jobs.ts`), falling back to the capped list only when the summary is unavailable (older gateway).
- Docs: reference/api.md route row.

## Flags / migrations
None.

## Deviations
- The corpus lists no Go files; handler and test added in httpapi. `/failed` page still lists with `limit=100` (it needs rows, not counts).
- `oldest_queued_at` uses job `created_at`, not time-entered-queued.
