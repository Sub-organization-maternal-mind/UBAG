## What it does
- **Ladder**: for each step N of the manifest (`--steps` overrides), N closed-loop clients (one job in flight each) for `--step-seconds`
  (and, up to 3x, until `--min-samples` text accepts and polls were timed): create (text, native-multipart attachment, synthetic-WAV audio per the
  manifest mix, deterministic per `--seed`) -> poll -> verify result body, event log, tenant boundary -> think -> repeat. Per step: accept p95
  (text create), read p95 (polls), overload rate, per-class accept latency, completion p95, jobs/min, stage p50/p95 (histogram delta of
  `ubag_job_stage_duration_seconds`), queue wait, per-step cgroup headroom/OOM/throttle/CPU headroom, voice frame age, integrity counters.
- **Goals**: integrity zeros (`thresholds.json`) + plan goals (`thresholds.goals.json`: accept 200 ms, read 100 ms, memory headroom 20 %, OOM 0,
  voice 100 ms, min verified) + ladder keys (`max_overload_rate_pct` 0, duplicate committed results 0, false-successful truncation 0,
  attachment violations 0). Each goal is `passed` / `failed` / `not_measured`; `not_measured` fails only under `--require-goals`.
- **Capacity**: the longest passing prefix of the executed steps; UNVERIFIED when any goal was not measured there. Stops at the first failing step
  (`--continue-after-fail` runs on; the capacity stays the prefix).
- **Paused mode** (`--mode paused`): consumer disabled by the operator; 100 clients enqueue 1000 jobs, reads are timed against the deep queue, every
  acked job is swept (must exist and stay queued), live queue depth delta from `ubag_queue_depth_live`; optional `--resume-wait-seconds` waits for the
  operator to resume, then drains and verifies everything. Execution-dependent goals are unmeasured without a drain.
- **Guards**: acknowledgement flag first; `checkTarget` host guard unchanged (loopback/private or explicit `UBAG_LOAD_ALLOWED_HOSTS`); live
  providers need `--target` + `--allow-live-provider`; workload `voice` refused; keys never written; `--host-class 2c4g|4c8g` verified against the
  summed container limits (1.5 CPU/2.5 GiB, 3 CPU/5 GiB, +-5 %); authoritative only with `--isolated-lab-host` + verified class + cgroups read,
  otherwise the first line says NON-AUTHORITATIVE and why.

## Gateway bug found (fixed here, outside the slice's file list)
Running the ladder against a local gateway with `UBAG_WORKER_STAGE_TIMINGS=1` made **every job fail**: the worker's `data.timings_ms.first_token`
(a closed P0.9 stage key) hit the payload policy's "token segment" rule, so applying the terminal event returned `tokens are not accepted in job
payloads at $.timings_ms.first_token`. P0.9b/P0.9c never ran the two together. Fix: exempt the exact key `first_token` next to the existing
`token_index` / `token_count` exemptions (`payloadpolicy/policy.go`), test pins that `first_token_secret`, `refresh_first_token` and `token` stay refused.
Anyone enabling stage timings on a stack built before this fix would have seen all jobs fail; stage attribution (needed by this ladder and P7.9) depends on it.

## Evidence (NON-AUTHORITATIVE: Windows laptop, 36 logical CPUs, Go gateway built from this branch)
Stack: edge profile (SQLite job store, file spool), embedded Python mock worker with `UBAG_WORKER_CONCURRENCY=1` and `UBAG_WORKER_STAGE_TIMINGS=1`,
two throwaway tenants (RS256 app JWTs, fresh key, never printed). No cgroups, no `--host-class`, no attestation, so the reports said NON-AUTHORITATIVE.
- `--mode paused --workload text`, 100 clients x 1000 jobs: 1000/1000 accepted in 16.3 s, 1000 still queued at the sweep, live queue depth delta
  1000 (so the `ubag_queue_depth_live` parsing matches the real series), 0 overload, read p95 18 ms over 10 s at 20 reads/s, **create p95 5.5 s**
  (over the 2000 ms burst limit, so the gate failed as designed; SQLite edge store, not production Postgres).
- Ladder `--workload text`, steps 1/2/5/10/20, 8 s each: all integrity counters 0 including cross-tenant probes (real 403/404 from the second tenant),
  stage rows present, N=1..10 passed, N=20 failed accept p95 (208.9 ms > 200 ms) -> "highest N meeting every goal: 10 (UNVERIFIED: voice, headroom, OOM not
  measured)". jobs/min stayed at 50-60 from N=1 to N=20: the single mock-worker consumer was the limit, which is why the report prints completion p95 and
  jobs/min beside the API goals.
- `--workload attachment` (mock, artifact PUT path) and the failing-first-run before the policy fix (7/7 jobs `failed`) were also seen.
These numbers are a harness check, not capacity, and are not committed under `docs/benchmarks`.

## Deviations
- `PROGRESS.md` not edited (BINDING rule 10); this shard and `docs/benchmarks/capacity-template.md` carry the record. P8.1 consolidates.
- The work item named `acceptance.test.mjs` for the offline test; the fake gateway moved into `lib/fake-gateway.mjs` so both test files share it.
- Goals always apply in the ladder (not only under `--require-goals`), so a ladder without `UBAG_LOAD_API_KEY_B` fails (`min_tenant_probe_requests`
  measured 0). `max_overload_rate_pct` = 0 is a harness choice, not a plan number; both are edited in `thresholds.ladder.json` / `--goals`.
- Accept p95 is gated on the small JSON create (all creates when the mix has none); attachment/audio accept is reported per class only.
- Live voice media is not driven (D7): voice frame age per step is the in-process bench row with the smallest session count >= N, labelled as such;
  N > 20 or no report leaves it unmeasured.
- "Consumer paused" is operator-controlled: the consumer is embedded in the gateway and has no pause API, so the stack starts with
  `UBAG_WORKER_CONSUMER_ENABLED=false`.
- Per-step memory headroom uses `memory.peak` (lifetime-cumulative), a conservative lower bound for later steps.
- Out-of-scope gateway fix (`first_token`) and the `execFile` import landed here because they blocked or silently disabled measurements this slice needs.
- Not wired into `pnpm check`, consistent with the other `tests/load` suites.
