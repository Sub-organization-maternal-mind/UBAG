# P7.6 Python relay baseline fixes before any Rust verdict

Status: partial. The fixes are built and tested, but the roadmap condition ("only if P7.5 says continue and the profile names the cost") is NOT met: P7.5 is partial and its verdict is UNEVALUATED (it needs real libopus on Linux, which this Windows box lacks). The before/after bench comparison is therefore not recorded. The behaviour-preserving changes were landed anyway because each is byte-identical on the wire and covered by tests; the flag-gated knobs are inert by default. If the P7.5 run says `stop`, these stay harmless; if it says `continue`, the optimised Python is the Rust-gate baseline.

Files:

Changes (all behaviour-preserving unless a flag is set):
- Buffer reuse: each `OpusDecoder` keeps one 11,520 B output buffer (5760 samples x 2 B, lazily allocated); each `OpusEncoder` keeps one 11,520 B packet buffer. Both are used only under the per-codec lock and the result is copied out (`string_at`) before the lock is released. The encoder no longer copies all 11,520 B (`out.raw`) to slice a ~100 B packet.
- `read_exact` uses `recv_into` on one preallocated buffer (no per-chunk bytes, no join). `read_frame` still returns `(type, bytes)`.
- `write_frame` builds the header with one `struct` pack (`<IB`) and one concatenation instead of pack + `bytes((t,))` + payload (two concatenations). Wire bytes are identical.
- Health loop: `devices_ok()` spawns ONE `pactl list short sources` instead of two. The sink is proven by the exact `ubag_provider_sink.monitor` source name (PulseAudio always exposes a sink's monitor). One existing assertion changed accordingly: the old "monitor present but sink absent" fake state cannot occur in PulseAudio, so it was replaced by an exact-name (not substring) check plus a test that exactly one pactl call is made.

Flags (both default off / unset):
- `UBAG_VOICE_PIPE_BYTES`: `F_SETPIPE_SZ` on the mic FIFO and the parec stdout pipe, Linux only, accepted range 4096..1048576, anything else is ignored with a log line; a failing fcntl is logged and never fatal. Unset leaves the kernel default (64 KiB). Changes latency and mic-drop behaviour: verify live.
- `UBAG_VOICE_SINK_SPEC_PIN=1`: the relay creates the provider null-sink with `rate=48000 channels=1`. Only applies when the relay creates the sink (an existing sink is untouched). Must be checked live with `pactl list short sinks` (and `bench_relay.py --pulse-check`) before enabling anywhere; Chrome behaviour on a pinned sink is unverified.

Migrations: none. Contracts/protocol: none (wire protocol v2 unchanged).

Checks run: `python -m pytest deploy/vps/browser/tests` -> 148 passed, 1 skipped (test_opus_real.py, no libopus here). New tests assert: decode/encode corpus bytes identical with the reused buffer (long packet followed by short ones, no stale tail), one buffer address reused, concurrent decodes on one decoder never see each other's samples, `write_frame` bytes identical to the legacy formula for sizes 0..65535 and both types, `read_frame` reassembles byte-dribbled input via `recv_into`, peer close and deadline behaviour, pipe cap inert/valid/invalid/failing, sink pin off by default and exact args when on, one pactl spawn per health check.
Checks not run: real libopus (test_opus_real.py skipped), Linux FIFO / `F_SETPIPE_SZ` against a real kernel, a live pactl null-sink with the pin, the P7.5 bench before/after (`deploy/vps/browser/tests/bench_relay.py`), any live call. PROGRESS.md not edited (BINDING rule 10); P8.1 consolidates.

Deviations:
- The roadmap gate "before/after via the P7.5 bench recorded in PROGRESS.md" is unmet (no libopus/Linux here; PROGRESS.md off limits).
- The conditional trigger (P7.5 verdict `continue`) was not available; see status.
- "Reuse the 11,520 B buffers" is per codec instance rather than module-global, so concurrent sessions in one process (not the current model) would not share them.
