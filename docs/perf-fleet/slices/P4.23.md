# P4.23 Helper-plane metrics, alert rules and runbook (before canary)

Status: merged when its PR is merged into `feat/perf-fleet`. Size M. Depends on P4.3 (lease TTL) and P4.9 (helper ingest), both merged. No flag, no migration, no contract change. Everything is additive: new series on `/v1/metrics`, a new alert file and a runbook. Nothing was deployed or applied anywhere.

## What landed

- **`apps/gateway/internal/helpermetrics`** (new leaf package, imports only `nodes`):
  - Process-wide counters with bounded labels, recorded through `RecordLeaseRenewFailure`, `RecordFencedReject`, `RecordPolicyViolation`. Unknown kinds or reasons fold into `other`, so helper-influenced text cannot grow the label set.
  - `Write(ctx, w, src, now)` renders the series. With a node source it also computes, per scrape and from the node store: `ubag_helper_nodes{admission}` (admission by reason, using the same `nodes.Evaluate` placement uses), `ubag_helper_node_heartbeat_age_seconds{node_id}`, `ubag_helper_node_drain_state{node_id}` (0 active, 1 draining, 2 revoked or unknown), `ubag_helper_node_admission_limit{node_id}`, and `ubag_helper_metrics_source_up`. A store read failure shows as `source_up 0` rather than failing the scrape. A node with no state is treated as never having heartbeated (fail closed).
- **Series**: `ubag_lease_renew_failures_total{lease,reason}`, `ubag_helper_fenced_rejects_total{reason}`, `ubag_helper_policy_violations_total{reason}` plus the node gauges above.
- **Hooks**: `executor/helperingest.go` `deny()` counts every fenced reject and policy violation (the audit stays deduped per session, the metric does not). `executor/workerconsumer.go` records queue-lease heartbeat and exec-lease renewal failures (`lost` vs `error`); behaviour is unchanged (still cancels only on a lost lease), and nothing is counted when the run context is already cancelled. `httpapi` gets `Config.HelperNodes` (a narrow `helpermetrics.NodeSource`) rendered in `writeMetricsBody`; `serve.go` passes the node store (nil when `UBAG_HELPER_NODES` is off, which emits only the counters).
- **Alert rules**: `deploy/prometheus/helper-plane-alerts.yaml`, 10 alerts in two groups (liveness: heartbeat stale/missing, no eligible nodes, grant expired, drain stuck, metrics source down; fencing: attempt lease renew failing, queue/exec lease renew failing, fenced writes, policy violations). Each carries a `runbook` anchor.
- **Runbook**: `docs/perf-fleet/RUNBOOK.md` (flag ladder, containment order, metric reference, one procedure per alert, pre-canary checklist, what is and is not verified).
- **Gates**: `tools/check-helper-alerts.mjs` (promtool-free, line-based: structure, balanced expressions, unique names, severity, runbook anchors exist as headings in the runbook); `tools/check-alert-metrics.mjs` now also scans the new rule file so every metric it names must be emitted by the gateway. Both are wired into `package.json` (`check:helper-alerts`, in `check`) and the CI step that already runs `check:alert-metrics`.

## Deviations

- Spec says "Prometheus alert rules under deploy/" without a path: a plain rule file at `deploy/prometheus/` was chosen over extending the Helm `PrometheusRule` template, so it works for the VPS (non-Kubernetes) deployment. Wrapping it in the Helm template is left out.
- "Lease renew failures" is a general `lease` label (`queue`, `exec`, `attempt`) rather than helper-only: the queue and exec leases are real renewals that exist today and are what a canary can observe. The `attempt` series has no producer until the helper dispatcher (no `RenewAttempt` caller exists yet), so it reads 0 and the alert on it is armed but untested end to end.
- "Admission by reason" is a scrape-time gauge of nodes per verdict, not a counter of placement decisions: no dispatcher calls `Evaluate` yet, so there are no decisions to count.
- Counters are process-wide package state (same pattern as the attachment materialize-failure counters); tests assert deltas.
