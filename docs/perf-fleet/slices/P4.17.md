# P4.17 Placer, prober and serve wiring

Status: merged when its PR is merged into `feat/perf-fleet`. Size L. Depends on P4.1, P4.14, P4.15 and P4.16, all merged. Inert by default: everything new is behind `UBAG_HELPER_DISPATCH` (default off) or `UBAG_FLEET_MANAGER_URL` (default unset). No migration, no public contract change.

Design record: `docs/adr/0016-eligibility-aware-placement-after-the-lease.md` (written first, its own commit; first numbered 0015, renumbered to 0016 at merge because P4.18 took 0015 for the attempt reconciler).

## What landed

- **ADR-0016: lease-then-place stays, peek-by-eligibility is not built.** Peek would change `WorkerQueue` for the file spool and NATS together (NATS has no content filter on a pull consumer), evaluates eligibility twice with a race between the peek and the lease, and every refusal still needs the same delayed answer. What ADR-0011 left open was the head-of-line cost of a synchronous hold (the file spool returns a retried job to the head of the queue), which this slice removes with off-worker holds (below).
- **`nodes/placer.go`**: `Admission(allocation, state, now)` = `Evaluate` plus the UBAG-side ceiling table as defence in depth (D3): a host of unknown size has ceiling 0 so no capacity (fail closed); a grant over the table is cut in proportion to the tighter of CPU and memory, never below one workload; the manager's grant is only ever clamped down. `Placer` returns the eligible nodes (`Nodes`, ordered by id, 1 s view cache), their total workload limit (`Capacity`) and `Reserve(node, lane)`, which takes a node slot and the identity lane together or neither (`ErrNodeNotEligible`, `ErrLaneBusy`, `ErrNoCapacity`), with an idempotent `Release`. A shrink evicts nothing and refuses new work until usage falls under the limit. An unreadable store is an error, never an empty fleet.
- **`nodes/prober.go`**: the heartbeat source (ADR-0009). Every 15 s each granted, non-revoked helper is asked for `ReportCapacity` (5 s timeout, at most 8 in flight); the node's state is written: heartbeat stamped with the PRIMARY's clock, pressure hysteresis from the helper's own cgroup numbers, the earned 1-to-N ramp (run counter in memory, limit persisted) and the host size the ceiling table needs. A report that fails, times out or names another workload version or adapter registry digest than this primary's leaves the heartbeat to age, so placement stops after 45 s: silence fails closed.
- **`executor/helperplacer.go`: `FleetPicker`** (the real `HelperPicker`): after the lease it joins the tenant's own profiles (`helperauth.EligibleProfiles`) with the placer. Answers: a placement (slot and identity lane reserved, `profile_ref` is the lane key); `ErrNoHelper` (run here) when no node is eligible at all (manager unreachable past the stale grace, nothing granted: ADR-0014), when the tenant has no profile for the target, or when a conversation cannot resume on a helper; a `HelperRetryError` (delayed retry, never a failure) for `identity_busy`, `no_capacity`, `no_eligible_node` (the tenant's profiles are on ineligible nodes: never another tenant's or an unbound profile), `affinity_unavailable` (a conversation waits for its bound node, never relocates) and for any store error (`fleet_unreadable`, `profiles_unreadable`, ...: "could not tell" never moves work onto this gateway). `HelperPickRequest` gained an optional `Conversation` (Place never sets it today).
- **`executor/workerconsumer.go`** (all inert while `AsyncHolds` and `HelperCapacity` are unset, so a consumer without them is byte-for-byte as before): `AsyncHolds` (64 under dispatch) lets a refused placement wait out its delay in a goroutine and returns the worker at once, so a busy identity neither pins a worker nor starves the jobs behind it, and the held job is placed again once per delay; past the bound the hold is synchronous. Shutdown retries every held lease before `Run` returns. `HelperCapacity` sizes the pool: local pool (clamped to 32 as before) plus the granted helper workload limits, at most 512, re-read every 15 s, grow-only. A local gate of the local pool size keeps local concurrency where it was, because the extra workers exist only to feed helper attempts. `retryAfterDelay` now shares `holdPlan` with the async path. After rebasing onto P4.18 the reconcile gate's holds (a job whose previous attempt still holds its lease) take the same off-worker hold, and a job the gate resumes or fails closed counts as remote (no local slot).
- **`serve`**: `helper_fleet.go` builds the grant poller (`UBAG_FLEET_MANAGER_URL`), the placer and picker, the prober (same dial identity and registry as dispatch; `helper_dispatch.go` gained `newHelperDialer`, no behaviour change) and wires the consumer. `serve.go` starts the poller whenever the node store is on and a manager URL is set, the prober when dispatch is on, and replaces `NoHelperPicker` with the `FleetPicker`.
- **`helpermetrics`**: `ubag_helper_placements_total{outcome}` (9 outcomes + `other`) and `ubag_helper_probes_total{result}` (`ok`, `error`, `incompatible` + `other`); both fixed sets, no node, tenant, job or profile ever a label. The per-node `ubag_helper_nodes{admission}` and `ubag_helper_node_admission_limit` gauges now use `nodes.Admission`, the verdict placement uses (previously `Evaluate` alone).
- Docs: ADR-0016, `ALLOCATION.md` (which now also lists P4.18's ADR-0015), `RUNBOOK.md` (flags table, metrics, "Jobs held by the placer", heartbeat source), chaos definition `fleet-manager-down.json` now names the Go tests that cover it.

## Flags and defaults

- No new flag. `UBAG_HELPER_DISPATCH` (default off) now also selects the placer, the prober and the consumer wiring. `UBAG_FLEET_MANAGER_URL`, `UBAG_FLEET_POLL_SECONDS` (30, 5..3600) and `UBAG_FLEET_GRANT_STALE_GRACE_SECONDS` (600, 0..86400) are the P4.15 names, now read by `serve` (with `UBAG_HELPER_NODES` on and the URL set; unset = nothing polled, nothing ever granted). Defaults inside the code, not env: probe every 15 s, 5 s per report, 8 in flight; placement hold 2 s (at most 30 s); 64 async holds; pool bound 512 re-read every 15 s.
- Dispatch on with `UBAG_EXECUTOR_MODE=nats` logs a warning: every hold consumes a delivery (`UBAG_NATS_WORKER_MAX_DELIVER`, default 5).

## Migrations

None. The tenant profile registry is P4.16's migration 0024 (Postgres); `UBAG_HELPER_DISPATCH` with Postgres runs its `Ready` at boot and fails closed if the table is missing.

## Deviations

- Files: the work item lists `nodes/prober.go`, `nodes/placer.go`, `serve.go`, `workerconsumer.go` and `conversations/postgres.go`. The picker is `executor/helperplacer.go` rather than in `nodes` because `helperauth` (the profile rule) imports `nodes`; `nodes.Placer` is node-level (slots and lane keys) and `FleetPicker` joins it with `EligibleProfiles`. `conversations/postgres.go` is untouched: P4.16 already added `node_id` and `profile_ref`, and `Place` never carries a conversation (`helperEligible` keeps every conversation job on this gateway until the helper contract can carry one).
- Lease-then-place is kept (ADR-0016), but a hold now waits off the worker (bounded). This goes beyond ADR-0011, which accepted the synchronous hold, because the exit gate asks that a busy identity not block a runnable job behind it and on the file spool that is impossible with a synchronous hold at one worker.
- Beyond the spec: a local gate (the pool is larger than the local pool, so local concurrency would otherwise rise); the ceiling clamp scales the workload limit by the grant's share (the table gives CPU and memory, not workloads); the prober refuses a helper on another workload version or registry digest (the runner would refuse it at the handshake and the placer would keep choosing it).
- The ceiling's "host size" is the report's totals, which are the helper's own cgroup budget (or the machine when none is set). A constrained helper therefore gets a stricter table (never a looser one).
- "Manager unreachable" reaches the picker as "no node eligible" (the poller's stale grace marks grants draining), not as an error: ADR-0014 and the chaos definition say it runs locally. A tenant with helper profiles and a down node waits, as the P4.16 rule requires, so the two rules together mean a tenant whose nodes are down while another node is up waits, while a wholly absent fleet runs locally. Recorded in ADR-0016.
- Slot and lane counts are in-process (one primary replica per fleet). The helper's own admission is the backstop.
- No create-time overload (the work item's risk note): a deep backlog of held jobs is visible only in `ubag_helper_placements_total` and the logs.

## Follow-ups

- **Operator route to bind profiles** (P4.16 follow-up, still open): with no way to bind a `profile_ref`, `FleetPicker` finds no profile for any tenant and every job runs locally. This is the next thing needed before a canary can place a job.
- **Manager auth** for `UBAG_FLEET_MANAGER_URL` (P4.15 follow-up): the request has none; the HTTP client is injectable.
- **Helper-reported drain**: the primary does not read `ReportCapacityResponse.draining`; a helper that drains on its own (not via the grant) refuses admission and the runner holds the job each 5 s until its heartbeat stops. Store or skip the heartbeat when it reports draining.
- **Move lanes and slots into the shared admission store** before running more than one primary replica; consider peek-by-eligibility (a queue API change) if held jobs ever need to exceed the 64-lease bound.
- **P4.18**: `conversations.Manager.MarkNodeBroken` when a node is revoked or declared lost, and bind a conversation to the node and profile from the trusted attempt record once conversation jobs can be dispatched (lift the `helperEligible` rule with the contract change).
- **Per-node placement gauges** (slots in use per node) were not added; `Placer.Used` exists for it.
- **NATS**: raise `UBAG_NATS_WORKER_MAX_DELIVER` or let the placer hold on the helper side before dispatch is enabled on NATS (only the warning exists).
- The runbook's "What is verified" still says nothing was run against a real helper; that remains true.
