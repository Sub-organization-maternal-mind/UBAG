# P4.15 AllocationSource: poll manager grants with last-known-good

Status: merged when its PR is merged into `feat/perf-fleet`. Size M. Depends on P4.1, P4.4 (merged). Inert: the poller is not started anywhere yet (no call site in `serve`); the Fleet Manager endpoint and its auth are external and undefined, so only a fake HTTP server exists in-repo.

## What landed

`apps/gateway/internal/nodes/allocation_source.go`:

- `AllocationSource` interface (`Fetch(ctx, etag) (Snapshot, error)`) and `HTTPSource`, which GETs the `allocation_list` body of `node-allocation.schema.json` with `If-None-Match`/ETag. 304 is only accepted when an ETag was sent. Redirects are never followed, URLs with credentials or a non-http(s) scheme are refused, the body is capped at 1 MiB, any non-200 is `ErrBadResponse`.
- Strict, all-or-nothing parsing (unknown fields rejected, schema_version 1 at list and entry level, `generated_at` required, max 256 entries, duplicate `node_id` rejected, every entry through `Allocation.Validate`). One bad entry rejects the whole list: grants never change from a half-understood response.
- `Poller` applies a good list through `Store.ApplyAllocation` (generation fencing stays the store's job). Entries the store fences (stale generation, same-generation conflict, node cap) are skipped and logged, not fatal. Store errors fail the poll and leave the ETag untouched so the whole list is retried.
- Manager-down behaviour (D3), via `Poller.Current(ctx, now)`: only a fully valid fetch changes grants, so while the manager is unreachable nothing is granted or increased and the last accepted grant keeps governing (`valid_until` still expires it through `Evaluate`). After `StaleGrace` without a good poll every `active` grant is reported `draining` (no new placements; running attempts are not touched here). A node missing from a good list is reported `draining` (not revoked; the manager never said so). `draining` and `revoked` pass through unchanged. Before this process has had a good poll (restart with the manager down) freshness is the stored `AcceptedAt`, so a persisted grant is kept for the remaining grace rather than dropped at once.
- `PollerConfigFromEnv(lookup)`: `UBAG_FLEET_MANAGER_URL` (empty = not configured), `UBAG_FLEET_POLL_SECONDS` (default 30, allowed 5..3600), `UBAG_FLEET_GRANT_STALE_GRACE_SECONDS` (default 600, allowed 0..86400). Malformed or out-of-range values are an error (fail closed at startup).
- `Poller.Run(ctx)` polls immediately then every interval until cancelled; errors are logged without response bodies.

## Flags

`UBAG_FLEET_MANAGER_URL`, `UBAG_FLEET_POLL_SECONDS`, `UBAG_FLEET_GRANT_STALE_GRACE_SECONDS`. Nothing reads them yet; the poller should only be started when `UBAG_HELPER_NODES` is on and the URL is set. No migrations.

## Deviations

- No wiring into `serve`: no consumer of `Current` exists until placement lands, and the manager auth scheme is undefined, so starting a poller now would only fill the store.
- No auth on the manager request (undefined externally). The HTTP client is injectable (`NewHTTPSource(url, client)`) so mTLS or a bearer round-tripper can be added without changing the interface.
- The schema's `cert_identity.uri_san` is required by the consumer to equal `spiffe://ubag/node/<node_id>` (the P4.4 rule in `Allocation.Validate`); the shared conformance fixture's `spiffe://fleet.example/...` form would be rejected here, same as by the store.
- "Absent from a good list means draining" and "stale grace means draining" are design choices the spec leaves open; both fail closed.
