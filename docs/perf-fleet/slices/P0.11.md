# P0.11 Workload manifest and run provenance

Status: merged-ready (schema + manifests + provenance + offline tests + docs). No real gateway or container was used.

## Files

- `tests/load/workloads/workload.schema.json` (contract first): extended the P0.15 schema (it already said P0.11 would) with `kind` text/attachment/audio-upload/mixed/voice, `harness_support`, `provider_scenario`, `mix` (weights, payload sizes), `think_time_ms`, `ladder_steps`. The audio-only fields are now optional in the schema and enforced per kind in code.
- `tests/load/workloads/{text,attachment,mixed,voice}.json` (new); `audio-upload.json` (P0.15) gained the common fields.
- `tests/load/workloads.mjs`: `validateWorkload` adds cross-field rules (weights sum to 100, ranges ordered, ladder ascending, live-media never "implemented", audio fields only for audio-upload); new `workloadSha256`.
- `tests/load/lib/provenance.mjs` (new): env allowlist, gateway info from `/v1/metrics`, harness git sha, host spec, container limits, read-only `docker exec <c> env`.
- `tests/load/acceptance.mjs`: `--workload <name>`, `meta.provenance`, "Provenance" Markdown section; `run()` takes `env` as a third argument.
- Tests: `tests/load/workloads.test.mjs`, `tests/load/acceptance.test.mjs`.
- Docs: `docs/benchmarks/README.md` (new), `docs/load-testing.md`.

## Behaviour

- `meta.provenance` = `gateway{version,api_version,commit}`, `harness{sha,dirty}`, `harness_host`, `harness_env`, `stack_env`, `container_limits`, `workload{name,sha256,harness_support,manifest}`.
- Env allowlist: `UBAG_WORKER_CONCURRENCY`, `UBAG_WORKER_DAEMON`, `UBAG_WORKER_POLL_INTERVAL_MS`, `UBAG_ADMISSION_*`, `UBAG_GATEWAY_MAX_INFLIGHT_REQUESTS`, `UBAG_GATEWAY_STORE`, `UBAG_VOICE_STORE`, `UBAG_EXECUTOR_MODE`, `GOMAXPROCS`, `GOMEMLIMIT`. Values that are not plain knobs are withheld.
- Manifest hash is SHA-256 over the file with CRLF normalised, so Windows and Linux checkouts agree.

## Deviations

- The spec put the schema at `tests/load/workload.schema.json`; P0.15 had already landed `tests/load/workloads/workload.schema.json` and its checker, so that single schema was extended instead of adding a second one.
- No ajv dependency at the repo root: validation uses the P0.15 in-repo keyword checker.
- The harness env cannot know the gateway's env, so `stack_env` (read from the containers) is the reliable source; `harness_env` is only what the operator exported. Both are allowlisted.
- `--workload` records the manifest; it does not drive traffic. Generators for mixed and voice do not exist (`harness_support: planned`); `text`, `attachment` (`--with-upload`) and `audio-upload` map to existing scenarios.
- `mixed` weights (70/20/10) and the ladder `1/2/5/10/20` are roadmap proposals, not measured production shares. `voice` `command_type` is a label for the voice session API, not a job command.
- Host spec is the harness host; the gateway host's CPU/memory comes from the cgroup sampler (`resources.host_pressure`).
