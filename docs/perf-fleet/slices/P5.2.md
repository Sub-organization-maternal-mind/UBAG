# P5.2 Voice link-quality metrics (jitter, loss, mic queue depth)

Status: merged (code + tests + docs). Nothing deployed; no production access.

## Metrics (all label-free; the endpoint is unauthenticated, so aggregates only)

| Series | Type | Source |
| --- | --- | --- |
| `ubag_voice_inbound_jitter_seconds` | histogram (1 ms doubling to 512 ms) | `pc.GetStats()` inbound audio RTP jitter, one observation per live media session per sample (worst audio stream) |
| `ubag_voice_inbound_packets_received_total` | counter | `pc.GetStats()` PacketsReceived, summed, as per-sample deltas |
| `ubag_voice_inbound_packets_lost_total` | counter | `pc.GetStats()` PacketsLost, clamped >= 0 per stream, as deltas |
| `ubag_voice_mic_queue_depth` | gauge | frames queued toward relays across live sessions, evaluated at scrape time (each queue bounded at 64) |

Loss ratio = `rate(lost) / (rate(received) + rate(lost))`.

Forward latency is NOT a new series: `ubag_voice_relay_frame_age_seconds{direction}` (P5.1) is the forward-latency metric (mic = RTP read to relay Send returned, speaker = relay Recv to WriteSample returned).

## Deviations

- The work item named "forward-latency" and "queue-depth" metrics; forward latency already exists as P5.1's frame-age histogram, so no duplicate was added. Queue depth is a gauge, not a histogram, because the observability contract requires histograms to be `_seconds`.

## Ceilings / follow-ups

- Queue depth is an instantaneous gauge (scrape-time snapshot), not a peak; short bursts between scrapes are visible only through the mic frame-age histogram and `frames_dropped_total{direction="mic"}`.
- Jitter is the receive-side RTP interarrival estimate pion reports, sampled every 2 s; it does not include the browser audio stack.
- Loopback jitter/loss values are NON-AUTHORITATIVE.
