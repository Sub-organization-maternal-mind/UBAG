# P7.8 CONDITIONAL: Rust relay crate, env-selectable and rollbackable (NOT STARTED)

Status: blocked. Nothing in the P7.8 deliverable was built, on purpose. The roadmap condition ("only if P7.7 says go") is not met, ADR 0008 gates Rust on measurement, `docs/handoffs/rust-relay-gate-verdict.md` says none may be written until it says otherwise (only a `prototype` verdict lets P7.8 start), and no verdict can be produced from this box. The honest outcome is "not started; gate unevaluated" (BINDING section 4, ADR 0008). The change is documentation only (this shard and a pointer line in the verdict record): no runtime, image, CI or contract surface.

## Why blocked

1. The gate is a pure function of evidence (`node tools/benchmark/rust-gate.mjs`; rule pre-registered in `tests/load/voice-relay-gate.json`). `prototype` needs a real P7.5 baseline (`relay-baseline.json`). `go` additionally needs an authoritative paired A/B against a candidate and a passed rollback drill.
2. No evidence exists: no baseline or A/B report is committed, the verdict record's decision table is empty, and the P7.4 Opus golden is still a placeholder (`libopus_version: null`), so even a perfect candidate could not pass the byte-identity rule.
3. None can be produced here: this dev box is Windows with no Docker, podman or WSL (no loadable libopus, no FIFO, no `/proc`), and D5 labels laptop numbers NON-AUTHORITATIVE, which the gate rejects (`require_authoritative`). It needs the isolated Linux lab helper, which does not exist.
4. Static analysis expects `stop` (the relay is glue around libopus; a rewrite would FFI the same library and add a third runtime). That is a hypothesis, not a result.

Deliberately not built, because each adds cost before any verdict justifies it: the crate and its CI job (a third toolchain plus `cargo audit`), a Rust stage in the browser images, and the `UBAG_VOICE_RELAY_IMPL` selector with its entrypoint and compose edits (dead configuration in two production deploy paths while no binary exists, and not exercisable here: no Linux, no Docker).

## Start checklist (only after a recorded `prototype` verdict)

1. Gate. A `prototype` row in the decision record of `docs/handoffs/rust-relay-gate-verdict.md`, from a real P7.5 baseline on the lab helper (Debian image, with the live-call container CPU for rule B). The baseline for B is the optimised Python (P7.6). Record the P7.4 golden in that same image first (`UBAG_OPUS_GOLDEN_UPDATE=1`, see `P7.4.md`).
2. Crate `packages/relay-rust` (not `packages/sidecar-rust`: an Axum/Tokio loopback proxy with no audio code, in no image). `std::thread` plus blocking sockets. libopus is linked dynamically against the image's `libopus.so.0`, the same library `opus_bridge.py` loads (a vendored build can change encoder bytes and fails the byte compare), with the same call sequence: 48 kHz mono, `OPUS_APPLICATION_AUDIO`, default ctls. Add HMAC-SHA256 with a constant-time compare and compact JSON replies with the same key order as the Python relay (the harness compares reply bytes). Commit `Cargo.lock` (this ships in production; the sidecar's ignored lockfile is the known anti-pattern, see the comment in `ci.yml` L429-432). CLI contract the harness drives: `<bin> --addr host:port` plus the six env seams above.
3. Parity the default corpus does not exercise, so `cargo test` must: the 5 s whole-frame hello timeout, the 30 s idle timeout on reads and writes, a relay started with no secret (`unconfigured`), PulseAudio device loss (`devices_lost` after 2 failed 5 s checks), the 4-pending-handshake cap, the `UBAG_VOICE_RELAY_NODE_ID` pin, SIGTERM exit. Easy to lose in a port: decode-and-discard while muted (decoder state must keep advancing), zero-padded partial PCM tail, drain-then-close on refusal (a bare close can RST away the error frame), non-blocking FIFO open with ENXIO retry plus the held writer fd, `mkfifo` mode 0600, the bound hello and the one-slot generation fence (P5.7; the slot resets on relay restart, the primary's guard is the durable fence).
4. Tests. `tests/vectors.rs` over the shared fixture (the same cases pytest and go test run). Then on Linux: `node tools/voice-relay-bench/run.mjs --a <python> --b <rust>` byte compare identical, an A/A pair for the noise floor, and the paired A/B on the lab helper as in the verdict record.
5. Image. Multi-stage amd64 build on a bookworm (glibc) Rust image so the binary and the runtime share glibc and libopus (no musl). Copy the binary beside `audio-relay.py` in BOTH `deploy/vps/browser/Dockerfile` and `deploy/small/browser-viewer/Dockerfile`.
6. Selector. In both entrypoints' relay loops: `UBAG_VOICE_RELAY_IMPL=python|rust`, default `python`; `rust` only when the binary is executable; a missing binary or any unknown value logs one line and starts Python. Pass it through `docker-compose.vps.yml` and `docker-compose.small.yml` next to `UBAG_VOICE_RELAY_STATS`, and keep `node tools/check-small-deployment.mjs` and `node tools/check-enterprise-deploy.mjs` green. No gateway change: it dials `host:port` and sees protocol v2 only.
7. CI. A `relay-rust` job modelled on `sidecar-rust` (`cargo test --all-features`) plus `cargo audit`.
8. Rollback drill. Container env is fixed at start, so "flip the env" means recreating the canary browser container with `UBAG_VOICE_RELAY_IMPL=python` (and once with `rust` and the binary removed, expecting the fallback log line). A call must connect each way; record `--rollback-drill pass|fail` for the evaluator. Decide at start whether a per-iteration flag file (rollback without a container restart) is worth its extra surface.
9. Done = `cargo test` green on the shared vectors, harness byte compare identical, the paired A/B clears the pre-registered rule, the drill passes, `go` recorded. The default stays `python`; changing it is a separate human decision.

## Deviations

- Status `blocked`, not `partial` like P7.7: no part of the P7.8 deliverable exists.
- Selector, CI job and image change deliberately not landed ahead of the crate (reasons above).
- The spec says "only if P7.7 says go", but the P7.7 evaluator cannot say `go` before a candidate exists (stage 1 judges the A/B against one). As in the P7.7 verdict record, the start condition is a `prototype` verdict and `go` is the adoption and exit condition. Neither exists.
- rust-07 assumes one image and one entrypoint. Two ship the relay: `deploy/vps/browser/*` (`docker-compose.vps.yml`) and `deploy/small/browser-viewer/*` (`docker-compose.small.yml`; Dockerfile L76 COPYs the relay from `deploy/vps/browser/`, entrypoint relay loop L210-217). Helper-hosted voice (P5.7) reuses the same relay code with per-attempt keys, but its packaging is not defined yet (the P5.7 shard: no helper server exists), so a candidate must also reach whatever image the helper's relay runs in. A candidate ships in both images, or the small profile stays Python-only by an explicit decision.
- The relay grew after the spec was written: bound hello with `node_id` and `generation`, the `UBAG_VOICE_RELAY_NODE_ID` pin and stale-generation fence (P5.7), `UBAG_VOICE_ENV_ID` namespacing, the stats line (P7.4), pipe sizing and sink pin (P7.6). The port is larger than the "thin glue" the P0 reader notes described.
- PROGRESS.md and AGENT_HANDOFF.md not edited (BINDING rule 10); P8.1 should record "P7.8 not started; gate unevaluated".
