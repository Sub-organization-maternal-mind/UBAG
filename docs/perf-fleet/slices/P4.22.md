# P4.22 - Reconciler for queued-in-DB-but-not-in-spool jobs

Status: merged (see PR). Gateway-only, no contracts, no migrations.

## Problem
`createJob` writes the job row (status `queued`) and only then calls `EnqueueJob`. A gateway crash between the two leaves a queued job with no spool/queue entry: no worker ever sees it, and only the stale-job reaper (opt-in, idle-time based) eventually times it out.

## What changed
- `apps/gateway/internal/executor/queue_reconciler.go`: `QueuedJobReconciler` sweeps `queued` and `scheduled` jobs older than `MinAge` (default 120 s, so jobs whose handler is still mid-flight are left alone), and for each one with no queue entry calls the dispatcher's idempotent `EnqueueJob`. `Run` sweeps once immediately (the startup repair pass) and then on `Interval` (default 60 s). Per-job failures are logged and retried next sweep.
- `JobPresenceChecker` (`HasJob`) is the only way the reconciler decides a job is missing. `FileSpoolDispatcher.HasJob` checks pending, leased and terminal state, so leased jobs and jobs the worker already finished are never re-enqueued. Dispatchers without a presence check (NATS, noop) are skipped on purpose: re-publishing past the broker's dedupe window would execute a job twice.
- `serve.go` wires it against the raw (non-breaker) dispatcher.

## Flags
| Flag | Default | Effect |
|---|---|---|
| `UBAG_QUEUE_RECONCILER_ENABLED` | off | start the reconciler (live behaviour unchanged by default) |
| `UBAG_QUEUE_RECONCILER_INTERVAL_SECONDS` | 60 | sweep cadence |
| `UBAG_QUEUE_RECONCILER_MIN_AGE_SECONDS` | 120 | grace after job creation |

## Checks
Run: `go vet ./internal/executor ./internal/serve`; `go test ./internal/executor -run 'QueuedJobReconciler|FileSpool'`; `go test ./internal/serve`.
Tests (crash injection = job created, process "dies" before enqueue): stranded job re-enqueued and leasable, healthy job untouched, second sweep is a no-op, young / leased / finished jobs not re-enqueued, one enqueue failure does not block others, no re-publish without a presence checker, `Run` repairs at startup.
Not run: full suites, Postgres-backed tests, a real process kill.

## Deviations
- The dispatch outbox (`outbox.Store`) is not constructed anywhere in `serve.go`, so per the slice ("only if already present") it is not wired; noted as a `ponytail:` comment.
- NATS is intentionally out of scope (see above); a JetStream consumer-side check would be needed first.

## Follow-ups
- Enabling `UBAG_QUEUE_RECONCILER_ENABLED=true` in production is an operator decision.
- Concurrency tokens acquired by a crashed process are in-memory and are not restored for a recovered job (the registry release is idempotent).
