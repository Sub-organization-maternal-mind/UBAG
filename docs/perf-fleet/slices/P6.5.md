# P6.5 - Dashboard voice sessions and capabilities panel

Status: merged into `feat/perf-fleet`. Size M. Depends on P6.2 and P5.11 (merged). Dashboard only: no contract, gateway, SDK, proto or migration change, no new flag.

## What landed

A *Voice Sessions* section on the existing Browser Sessions page (`routes/browser/+page.svelte`, between Placement and Live Browser). No new route or nav entry. It renders only when **both** `GET /v1/capabilities` and `GET /v1/voice/sessions?limit=25` answer `200` with the contract shape; `501` (voice not configured), `404` (older gateway), `403`, a failure or a body that is not the contract all read as "no panel", never as an error.

- **Capabilities table** (per target that declares live voice): Supported, Configured, Verified (the `verified_note` is the cell tooltip), Available, Free accounts. Read from the `voice` object of each capability record; a missing flag is never read as true, and the legacy `live` / `available_accounts` aliases are used only when the new fields are absent.
- **Sessions table**: session id, target, mode, status badge (+ "Muted"), *Queued reason*, *Placement*, updated time.
  - *Queued reason* is shown only while `status` is `queued`. The gateway reports no per-session reason today (the session object is open, so `queue_reason` can be added later without a schema break): the dashboard shows the gateway's `queue_reason` when present, else "Waiting for account" with the one fact a queued voice session always means (no authenticated account with a free browser environment was available).
  - *Placement* is the gateway's `node_label` when present, else `identity_ref · instance_ref`, else an em dash. The helper node id is `json:"-"` on the gateway's `Session`, so the dashboard never receives or shows a node id or address.

Supporting code: `lib/api/voice.ts` (guards `parseVoiceTargets` / `parseVoiceSessions`, mappers `voiceQueueReason` / `voicePlacement`, loader `loadVoicePanel` through the P6.3 snapshot store, 10 s share, only 2xx cached), `lib/components/VoiceSessions.svelte` (self-loading, 45 s visible-tab poll like the page), `types.ts` (`VoiceCapability`, `VoiceTargetRow`, `VoiceSessionRow`), `StatusBadge` tones for `connecting`, `connected`, `terminated`. Read-only: no connect, mute or terminate controls.

## Flags and migrations

None. With voice off the routes answer 501 and nothing renders, so a deployment without voice looks exactly as before. With `UBAG_HELPER_VOICE` on and a gateway that later adds `node_label` / `queue_reason` to the session object, they show without a dashboard change.

## Deviations

- Queued reason and placement are derived in the dashboard from what the gateway sends today (see above) rather than from new gateway fields: the slice is dashboard-only and the P6.2 queue reasons cover jobs, not voice sessions.
- "Available" is the gateway's own `available` flag; the page does not recompute it from the free-account count.
- The panel needs both routes (`job:read`): either one failing hides it, as the spec's "hidden when voice or capabilities return 501 or 404" reads.
