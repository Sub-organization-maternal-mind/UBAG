# P3.9 StreamingWorkerRunner / EventSink with batch adapter

Status: merged (interface + gated consumer path; no incremental apply yet).

## What landed
- `apps/gateway/internal/executor/streamrunner.go`: `EventSink`, optional `StreamingWorkerRunner` (beside `WorkerRunner`), `BatchStreamAdapter` (batch `RunWorker` lifted to the streaming interface), `collectingSink` (bounded by `maxWorkerEvents`, requires `type`), `streamIngestEnabled()`.
- `WorkerConsumer.runWorker` is the single call site: when `UBAG_WORKER_STREAM_INGEST` is on AND the runner implements `StreamingWorkerRunner`, events are streamed into the collecting sink and then validated/applied by the unchanged post-run path (events stay provisional until exactly one valid terminal; a stream error or missing terminal fails the job). Otherwise the untouched `RunWorker` path runs.
- `DaemonWorkerRunner` implements `StreamWorker`. Its protocol loop is now `readDaemonJob` (shared core); `runDaemonJob` (batch, behaviour-identical) and `streamDaemonJob` (per-line emit) are thin wrappers. Process management moved into `runJob`, shared by `RunWorker`/`StreamWorker`.
- Process-runner streaming is dropped (cold path stays batch), per the slice spec.

## Flags
`UBAG_WORKER_STREAM_INGEST` (Go), default OFF. Off => byte-identical to before.

## Migrations
None.

## Checks run
- `gofmt -l` on touched files (clean), `go vet ./internal/executor`, `go test ./internal/executor` (whole package, all pre-existing consumer/daemon tests unchanged and passing, plus new `streamrunner_test.go`).

## Not run
Full suites, Postgres/NATS integration, Python worker tests (no Python change).

## Deviations
- Per-attempt event/byte budgets that replace 512/1 MiB, and incremental `ApplyWorkerEvent` before the terminal, are NOT in this slice: the sink only buffers, so the end state equals the batch path. They belong with P2.2 (stream ingestion apply). The stdout byte bound stays in the daemon reader.
- Daemon streaming reports a malformed line as soon as it arrives (batch reports it after the marker); both end in a failed job. Failed-marker vs malformed-line precedence can therefore differ on a doubly-broken stream.
- Test helper `runIngestConsumer` now delegates to a new `runIngestWith(WorkerRunner)`; existing tests are unchanged.

## Follow-ups
- P2.2: incremental apply through `EventSink` with a provisional/terminal barrier and per-attempt budgets; stale-attempt filter (`dropStaleAttemptEvents`) must run per event there.
