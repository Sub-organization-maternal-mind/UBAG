# P6.4 - Dashboard queue reasons, placement and assigned-capacity panels

Status: merged into `feat/perf-fleet`. Size L. Depends on P6.2, P6.3 (merged) and P0.6. Dashboard only: no contract, gateway, SDK or migration change, no new flag.

## What landed

Four existing pages gain panels; there is no new route and no new nav entry. Every fleet panel renders only when its fleet endpoint answers `200`. `501` (no fleet source), `404` (older gateway), `403` (not an operator), a failure, or a body that is not the contract shape all read as "no panel", never as an error.

- **Overview** (`routes/+page.svelte`): a *Shared Fleet* section from `GET /v1/fleet/summary` (eligible / total nodes with the other states counted underneath, workload slots in use against the limit, nodes under pressure), and a *Waiting jobs by reason* card from `/v1/jobs/summary` `queued_by_reason` plus the oldest queued time.
- **Jobs** (`routes/jobs/+page.svelte`): a *Queue Reason* column and, in the detail drawer, the reason, its one-line meaning and *Waiting Since*; a *Waiting jobs by reason* card (coarse counts from the jobs summary) and, on fleet `200`, a *Held by placement reason* card from `held_by_reason` (fine reasons, counts only, labelled as operator detail across all tenants).
- **Browser Sessions** (`routes/browser/+page.svelte`): a *Placement* table from `GET /v1/fleet/nodes`: node label (opaque `node_id` as tooltip), region, state plus ineligible reason, last heartbeat, slots in use / admission limit, pressure (reduced until `recover_at`), and provider-session readiness as `target: state xN`. It refreshes with the page's 45 s visible-tab poll.
- **Quotas** (`routes/quotas/+page.svelte`): an *Assigned Capacity* section: one `CapacityBar` card per node (slots in use against the admission limit) with state, the grant (workloads, CPU, memory) and `valid_until`.

Supporting code:

- `lib/api/fleet.ts`: contract guards (`parseFleetSummary`, `parseFleetNodes`), loaders through the P6.3 snapshot store (`loadFleetSummary`, `loadFleetNodes`; 10 s share, only 2xx cached), the queue-reason helpers (`queueReasonRows`, `humanize`, `QUEUE_REASON_HINT`) and the formatters (`fmtCount`, `fmtTime`, `fmtCpu`, `fmtBytes`, `capacityPct`, `barColor`). Every formatter returns an em dash for an unreported value.
- `lib/components/CapacityBar.svelte` (new): the Quotas bar pattern (`barColor` at 70 / 90 %) extracted into a card; the existing Concurrency Usage cards now use it with identical markup, so the quotas snapshot is unchanged. `lib/components/QueueReasons.svelte` (new): a reason / count list.
- `lib/api/types.ts`: `QueueReason`, `Job.queue_reason` / `queue_reason_since`, `FleetNode`, `FleetGrant`, `FleetReadiness`, `FleetSummary`, mirroring the OpenAPI schemas.
- `StatusBadge`: tones for the node states (`eligible`, `ineligible`, `draining`, `lost`, `unknown_reservation`), reusing existing colour tokens.

Design rules kept: NAJM tokens only, no new radius, no invented figures (a node field the gateway did not send shows as an em dash; `readiness: []`, which the gateway returns until the P4.13 probe is consumed, shows as an em dash). The helper node identity shown is the opaque label and `node_id`; the dashboard never sees or shows an address.

## Flags and migrations

None. The panels follow whatever the gateway serves: with `UBAG_HELPER_NODES` off the fleet routes answer 501 and the jobs summary reports no `queued_by_reason`, so a deployment without helper nodes renders exactly as before.

## Deviations

- Fleet panels are gated on the fleet endpoint, but the tenant-visible coarse queue reasons (the Jobs column, drawer fields and the *Waiting jobs by reason* cards) are gated on the gateway having reported them, not on `/v1/fleet/*`. A tenant without `fleet:read` still sees why their own jobs wait; on a gateway that reports none, nothing renders.
- A node missing what the panels draw (id, state, usage numbers, grant) is skipped, like `normalizeJobs` skips a job without an id. Other missing node fields show as an em dash.
- Fine reasons are shown by a humanised token (`identity_busy` -> "Identity busy"), not mapped to their coarse group on the client, so the dashboard has no copy of the gateway's fine-to-coarse table. Unknown tokens render as they are, per the contract.
- The Placement table's scroll area is a keyboard-focusable `role="region"` (with a `svelte-ignore` for the tabindex rule) so a narrow screen cannot trap a scrollable table with nothing focusable in it.
- `CapacityBar` reuses the quotas card as it was, so the Concurrency Usage cards were refactored onto it (same markup, same classes).
