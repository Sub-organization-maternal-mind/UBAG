Flags / env / migrations: none at runtime; nothing under apps/ or deploy/ changed. The harness sets the relay's existing seams for the child it spawns
(`UBAG_VOICE_RELAY_SECRET/ADDR/IDLE_S`, `UBAG_VOICE_MIC_PIPE`, `UBAG_VOICE_PAREC`, `UBAG_VOICE_PACTL`), nothing else. Not wired into `pnpm check`.

What was built:
- Corpus (`corpus.mjs`): mulberry32 seeded, 66 scenarios (smoke profile 15): every `hello_validation` and `framing` case of the shared v2 fixture
  (`packages/conformance/fixtures/voice-relay/v2.json`) before and after the handshake, all Opus durations 2.5..120 ms, DTX/PLC-shaped packets, corrupt and empty
  packets, 1275..65535 byte frames, mute interleavings and control noise, speaker PCM (exact, partial tail zero-pad, silence, full-scale square), mic plus speaker at once, a second
  connection while busy, stale lease generation. The manifest carries seed, profile, libopus version, fixture SHA and a corpus SHA. The seed is pre-registered in the gate file.
- Driver (`run.mjs`): black box over TCP; the relay is a command line with `{addr}`. A parec shim replays seeded PCM at 20 ms on an absolute schedule and holds the pipe
  open until the harness opens a gate file, so the relay ends every session with `monitor_exited` at a point both sides agree on. A pactl shim satisfies the relay's device health
  loop. A FIFO sink (real FIFO on POSIX, appended regular file on Windows) captures the mic stream. Byte compare per scenario on control replies, speaker packets, FIFO bytes,
  close behaviour (and the second connection for busy); scenarios the relay ends itself exclude the speaker stream because how many frames got out first is timing.
  Interleaved paired runs (order alternates): CPU per call-minute from `/proc/<pid>/stat`, VmHWM, threads, mic and speaker transit p50/p95/p99, drops, optional `--mixed-probe`.
  Reconnect leak check (fds, threads, children, RSS; minimum of six samples so a transient `pactl` child is not a leak). The compare report carries coverage counters so two
  empty streams cannot pass as a proof.
- Offline self-test (`selftest-relay.py`): runs `deploy/vps/browser/audio-relay.py` unmodified with a deterministic, stateful fake codec (decode and encode depend on every earlier
  packet or frame), and on Windows an append-mode FIFO stand-in. `UBAG_SELFTEST_MUTATE=speaker|mic|mute` breaks one behaviour: the negative control.
- Evaluator (`rust-gate.mjs`): `stop | prototype | go | inconclusive | invalid`. Stage 0 re-derives rule A, rule B and the Python-overhead ceiling from the raw P7.5 runs (the embedded
  stop_rule is only cross-checked). Stage 1 judges the A/B on paired t-intervals (win = any of overhead/CPU/RSS; regressions must be ruled out by the CI upper bound; leaks, byte
  mismatches, golden vectors, materiality, rollback drill). Self-test reports, non-authoritative hosts, fake codecs, another libopus, another seed and an empty compare are `invalid`.

Checks run:
- `node --test tools/voice-relay-bench/run.test.mjs tools/benchmark/test/rust-gate.test.mjs`: 43 tests, 42 passed, 1 skipped (the POSIX FIFO test, self-skips on Windows), ~70 s on this
  Windows box. Python (3.9) relay against itself: 15 smoke scenarios identical, 0 expectation failures against the shared fixture, work counters (frames moved) 0 % delta,
  evaluator answers `invalid` for the self-test report. Negative controls: a broken speaker encoder fails `spk.partial_tail` and `both.mixed`, a broken mic decode fails `mic.durations`, a
  broken mute fails `mic.mute`.
- One manual run of the full 66-scenario profile, Python against itself (fake codec, pace 2 ms): byte compare PASS, 0 expectation failures.
- `node --check` on every new module.
Checks not run: anything with real libopus; anything on Linux, so the POSIX paths are UNVERIFIED here (real FIFO sink against the relay's non-blocking open, `/proc` CPU/RSS/fd/child meter
(parsers are unit-tested on canned text), `sh` wrappers, `mkfifo`); a real A/B; the leak check; `--mixed-probe`; the full-profile run at the 20 ms pace; `--include-slow`.

Evidence / numbers: none. Self-test timings on Windows (15 ms timer granularity) are meaningless; mic transit there is dominated by the sink's poll interval.

Deviations:
- PROGRESS.md not edited (BINDING rule 10); the exit gate's "verdict recorded in PROGRESS.md" is carried by `docs/handoffs/rust-relay-gate-verdict.md` and this shard, for P8.1 to consolidate.
- No `parec-shim.sh`: a shell script cannot be executed by the relay on the Windows dev box, so the shim is `parec-shim.mjs` and `run.mjs` generates a per-platform wrapper (`sh` or `.cmd`).
- The roadmap says "Python versus Python reports 0% delta". Exactly 0 holds for the work counters (frames moved, which are deterministic); CPU, RSS and latency between two runs of one relay
  are noise and are `null` off Linux. The self-test therefore proves the pipeline, not a noise floor; an A/A pair on the lab host measures that.
- The roadmap verdict language (drops, regressions, rollback drill) presupposes a candidate while the slice writes no Rust. The evaluator therefore has two stages: stage 0 (baseline only) can
  only `stop`, stay `inconclusive`, or authorise a prototype; only stage 1 can say `go`.
- The libopus self-time for the overhead rule comes from the P7.5 in-process profile, not the black-box run (a black box cannot split libopus time).
- Regression and win claims are judged on CI bounds (a positive point estimate inside a CI that includes 0 is `inconclusive`, not a stop). With zero tolerance and the pre-registered 5 pairs that is
  strict by design: the default outcome without proof is "Python stays".
- "Material in the mixed ladder": the ladder does not drive live voice (D7), so the harness takes a `--mixed-probe` command that reports container CPU, job p95 and host headroom per run; the ladder itself is unchanged.
- A drift-guard test asserts the gate file equals the P7.5 bench constants (70 %, 5 %, 20 %, 25 %).
