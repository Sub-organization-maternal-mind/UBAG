# P5.11 - Primary RemoteMediaNegotiator and control forwarding

Status: merged when its PR is merged into `feat/perf-fleet`. Size L. Depends on P5.5, P5.8, P5.9, P5.10 and P4.14, all merged. Behind `UBAG_HELPER_VOICE` (default off; the whole ladder `UBAG_HELPER_NODES` < `UBAG_HELPER_PLANE` < `UBAG_HELPER_DISPATCH` < `UBAG_HELPER_VOICE`), so production behaviour is unchanged. With the flag on, a placed call can now be connected: the primary offers it to its Helper Node and supervises it. Live two-way audio on a real helper has NOT been run (human-supervised, see RUNBOOK "Helper-hosted voice: first live check"), and the Postgres half of the new store contract has NOT been run.

Design record: `docs/adr/0018-primary-negotiates-helper-voice-with-stateless-fenced-control.md` (its own commit, with the RUNBOOK sections).

## What landed

- **`voice.RemoteNegotiator`** (`internal/voice/remote.go`, new; the work item's `voice/remote.go`). The media plane of a node-bound session, slotted in at `httpapi.MediaNegotiator`: the connect response, the OpenAPI contract and the SDKs are unchanged, and no proto change was needed.
  - **Offer routed by `Session.NodeID`.** It checks the guard (tenant-scoped, the fence must equal the lease the store holds), resolves the node's endpoint and the account's `profile_ref`, dials the node, handshakes (protocol, node id, `helper_voice` feature, workload version, adapter registry digest, clock skew <= 5 s), mints per-attempt credentials (`HelperVoiceMinter`: relay key, media key, TURN credentials; never a global secret) and sends `OfferVoice` with a `VoiceFence`. The node's answer is the connect answer. A mute set before the media existed is applied right after the offer (fail closed: a failure ends the call).
  - **ICE restart.** A later offer on a supervised call goes to `ReconnectVoice` on the call's own connection (no new dial, no second provider activation); on a replica with no supervisor (another replica served the first connect, or a restart) a repeated `OfferVoice` under the same fence renegotiates the live call, and the credentials re-derive identically because the attempt is a pure function of the session record.
  - **Control is stateless and fenced.** `MuteSession`, `InterruptSession`, `EndSession` and the offer address the session record; each passes `HelperVoiceGuard` (a new `AuthorizeEnding` also admits a session that already reads terminated, with the same fence) and carries the lease's `VoiceFence`. A stale generation or another node is refused before any dial; another tenant's session is `ErrNotFound`, identical to an unknown session.
  - **One supervisor per call** (renewal loop + event stream on the call's connection). Every 20 s it renews the store's media lease FIRST and the node's lease SECOND (the node's deadline is shortened by the 5 s clock-skew bound), so the node cannot outlive the record; a node silent for a whole 60 s window is declared lost (`helper_unreachable`); a node that no longer holds the call ends the record (`helper_lost`); a replaced lease ends the supervisor's own call under its own fence and stops without touching the successor; the call ends before its credentials do (`call_time_limit`, 4 h after the session was created). The supervisor outlives an ended record until the node's ENDED (at most the 45 s hold cap).
  - **Events become fenced primary writes.** In order, resumed after the last applied sequence when the stream breaks: `CONNECTED` -> `CommitTransition(connecting -> connected)`; the client's own mute -> the new `CommitMuted`; `ENDED` -> `ReleaseHold` (the node's acknowledgement that the provider left voice mode), or, for a record still live, an end with the node's validated end reason as `last_error` (`media_ended: <reason>`, `activation_failed: <provider state>`, ...; free text is never stored) and no hold. An event of another attempt or another generation is rejected and counted (`attempt_mismatch`, `stale_generation`); the store's own fence rejects a stale writer a second time (`commit_fenced`) and stops the supervisor.
  - **`NodeRouter`** routes a session with a node to the negotiator and every other session to the primary's hub (offer, ICE servers, disconnect, mute), and declares `HostsNodeSessions`, which lifts P5.9's 503 exactly when a node-capable plane exists.
- **`voice.Store.CommitMuted`** (memory, SQLite, Postgres): the mute flag a node reports, fenced by `(node, lease generation)` like `CommitTransition`, with the same miss classification; covered by the shared lease contract table (`StaleGenerationMuteRejected`). No migration.
- **`voice.AttemptIDFor`** (`attempt.go`): the voice attempt id is a hash of the session id and generation in the `att_...` shape the node requires, so no attempt ledger row is needed and every replica derives the same attempt. The per-attempt credentials end `RemoteCallMaxAge` (4 h) after the session was created, so every replica derives the same keys too and a restarted primary can still issue the client a credential the node verifies.
- **`httpapi`** (`voice_handlers.go`, `voice_control.go`): `NodeSessionMedia` (session-aware control surface). Connect signs the media credential with the per-attempt media key for a node-bound session (the node holds no app secret; a primary-hosted session keeps its app-secret credential). Mute for a node-bound session is written only after the node confirmed it; an unconfirmed mute answers 503 `UBAG-VOICE-MEDIA-UNAVAILABLE-007` instead of claiming success, a stale lease answers the existing 409. Terminate takes the terminating hold for a node-bound session (when the hold flag is on) and ends the call on its node in the background; the node's ENDED releases the hold (UNKNOWN, nothing ever ran there, releases at once). `dropVoiceMedia` / `terminateVoiceSession` now take the session record. Another tenant's session answers the same 404 as a missing one on every route (tested).
- **`helperclient.Conn`** carries `HelperVoiceServiceClient` on the same verified mTLS connection.
- **`serve`** (`voice_nodes.go`, `serve.go`): `newVoiceRemoteFromEnv` builds the negotiator when the node placer exists (it reuses the dispatch dial identity, the node store's endpoints, `UBAG_HELPER_WORKLOAD_VERSION`, the `UBAG_ADAPTERS_DIR` digest and `UBAG_VOICE_RELAY_SECRET` as the master; a half-configured plane fails to start, an unset relay secret logs a warning and no node call can start). `voiceplace.Placer.ProfileRef` resolves the node-side identity: the node admits the call under the account's `profile_ref`, so a call and a job on one account exclude each other on the node too. The lease sweeper tells the negotiator which sessions it ended.
- **Metrics:** lease kind `voice` on `ubag_lease_renew_failures_total`; stale and fenced node events reuse `ubag_helper_fenced_rejects_total`. No new series, no new unbounded label.
- **Docs:** ADR-0018 (and a superseded-in-part note on ADR-0017), `ALLOCATION.md`, RUNBOOK (flag row, metric row, "Helper-hosted voice calls", "Helper-hosted voice: first live check"), `CONTEXT.md` (Node-bound session), the proto reference page, the shard index.

## Flags and defaults

No new flag and no migration. `UBAG_HELPER_VOICE` stays off by default (it needs the whole ladder); with it off `Config.VoiceNodes` is nil, no negotiator is built, the router is not installed and every call is hosted on the primary exactly as before. The lease window (60 s), renewal cadence (20 s), clock-skew bound (5 s), offer timeout (15 s), RPC timeout (5 s) and credential life (4 h) are constants of `voice/remote.go`.

## Deviations

- **The negotiator is in `internal/voice`, with seams, not in a package of its own.** P5.9 put the placer in `internal/voiceplace` because `voice` is linked into the `helpervoice` helper build; the negotiator needs only the proto, gRPC and four seams (dial, endpoint, profile, store), so `voice` still imports nothing from `nodes`, `jobs`, `executor` or `httpapi` and the import guard holds (re-run). The adapters live in `serve`, `voiceplace` and `helperclient`.
- **The flag is `UBAG_HELPER_VOICE`, not the work items' `UBAG_VOICE_HELPER_MEDIA`.** Same ladder and default as P5.8, P5.9 and P5.10.
- **No attempt ledger row for a voice attempt.** The attempt id and the credential expiry are pure functions of the session record (`AttemptIDFor`, creation time + 4 h), so any replica and a restarted primary re-derive them and no migration is needed. Cost: a call lives at most 4 h from its session's creation, and a session queued longer than that cannot connect.
- **Added beyond the spec:** `Store.CommitMuted` (the node's mute report needs a fenced write; no migration), `HelperVoiceGuard.AuthorizeEnding`, `voiceplace.Placer.ProfileRef`, the `voice` lease kind, and the handshake compatibility checks (the same as job dispatch).
- **Terminate always takes the hold for a node-bound session** (when the hold flag is on), not only when the primary requested provider activation: the node tears the provider down itself and acks with ENDED, and answers UNKNOWN when nothing ran. This replaces the "no hold yet" consequence recorded in ADR-0017.
- **Mute is node-first.** For a node-bound session the record is written only after the node confirmed the mute (the opposite order from primary-hosted voice, where the hub's flag is best effort): a mute that did not reach the live media is never reported as done.
- **Interrupt has no HTTP route.** `InterruptSession` forwards `INTERRUPT` fenced, and reports `ErrInterruptUnsupported` because the node answers `UNIMPLEMENTED` (P5.10: no provider-side barge-in primitive). A public route is a contract change that needs a primitive behind it.
- **`EndSession` works in the background.** A client's terminate returns without waiting for a node; the node closes the media on receipt, and the teardown acknowledgement releases the hold afterwards. The lease sweeper's `Disconnect` reaches a supervisor on this replica; a session swept elsewhere is noticed by its supervisor at the next renewal (at most 20 s).
- **Hold released on the node's ENDED for a record the supervisor did not own:** a replica that did not serve the connect streams the node's retained events (the node keeps them for an hour) for at most the hold cap.

## Follow-ups

- Run the Postgres lease-contract entries (P5.8, P5.9, and `StaleGenerationMuteRejected`) against a real database (dispatched CI or a local DSN with migrations 0019, 0020 and 0025).
- The human-supervised two-way check on a real helper (RUNBOOK), recorded in the ledger. `PROGRESS.md` and `AGENT_HANDOFF.md` (consolidated by P8.1) still list P5.11 as not landed; update them when the ledger is next consolidated (BINDING forbids editing them from a slice).
- A node-side reconcile for a helper restart: the node loses its in-memory calls and nothing deactivates their provider UI; the primary ends the record `helper_lost` (no hold, since no ack can come). Needed before enabling.
- Provider barge-in (`INTERRUPT`): a worker `voice.interrupt` action or a relay control on the node, then an HTTP route (OpenAPI first).
- Move the node slots and lanes into the shared admission store and re-take the slot of a surviving node-bound session after a restart (P5.9 follow-up): the control surface already works from any replica, placement does not.
- An operator route to register helper environments in topology and to bind profiles (P4.16 and P5.9 follow-ups); until then nothing is helper-bound and nothing changes.
- A TURN-relayed leg cannot outlive the 4 h credentials; if longer calls are wanted, re-mint on ICE restart (needs a credentials field on `ReconnectVoiceRequest`).
