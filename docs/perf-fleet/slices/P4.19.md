# P4.19 Helper workload manifest, image and CI (inert)

Status: merged into `feat/perf-fleet`. Size M. Depends on P4.12 (merged). Artifacts only: nothing starts the helper, nothing is built automatically, nothing is deployed.

## What landed

- `deploy/helper/workload-manifest.json` + `workload-manifest.schema.json`: the manager-facing workload. Image `ghcr.io/sub-organization-maternal-mind/ubag-helper:{{image_tag}}` (`sha-<commit>`), six declared parameters (`image_tag`, `wireguard_address`, `node_id`, `primary_uri_san`, `workload_version`, `tls_dir`), non-root numeric user, read-only rootfs, `no_new_privileges`, `cap_drop: [ALL]`, **host network with exactly one listen entry bound to `{{wireguard_address}}:7443`** (the helper refuses a wildcard/hostname, and a bridge container cannot name its WireGuard address), env = the `UBAG_HELPER_*` names with no secret, three mounts (read-only TLS bind, profile volume, tmpfs home and tmp) and **resource requests only** (1500 millicores, 2.5 GiB, 1 GiB shm; one workload, matching the ceiling table). The schema forbids `limits`, published ports and secrets by `additionalProperties: false`.
- `deploy/helper/Dockerfile`: Go build of `cmd/ubag-helper` (version via `-X ...helper.Version`), then `python:3.12-slim` with Playwright Chromium, `apps/worker` and `adapters`. One symlink (`/usr/local/bin/chromium` -> Playwright's Chromium) makes the helper's start-up Chrome lookup and the worker's real browser the same binary. Image-level env: adapters dir, chrome bin, profile root, worker python/script, `HOME`. No EXPOSE, no default listen address, no key/cert/env copied.
- `.github/workflows/helper-image.yml`: `workflow_dispatch` only; top-level `contents: read`; a `check` job runs the gate; `build` has `packages: write`, pushes only when the `push` input (default false) is ticked, tags only `sha-<commit>`. No deploy step, no deploy secrets.
- `tools/check-helper-deploy.mjs` (dependency-free): schema validation with a small built-in validator; no secret-looking names/values, no wildcard address, no `limits`/`ports`/`publish`/`secrets`; placeholders declared and used; `UBAG_HELPER_LISTEN` equals the listen entry; every `UBAG_HELPER_*` name exists in `internal/helper/config.go` and every required setting is supplied exactly once (manifest or image); mounts cover the TLS files, bind mounts are read-only with a placeholder source, `HOME` and the profile root are mounts; Dockerfile user/entrypoint/EXPOSE/COPY rules; workflow trigger, permissions and push default; wired into `test:deployment`.
- `package.json`: `test:deployment` now also runs the check; new `check:helper-deploy`.
- `deploy/helper/README.md`: what UBAG supplies vs what the manager does.

## Deviations and assumptions

- Spec listed `fleet-02` (allocation schema, merged earlier as `node-allocation.schema.json`) as contract-first; the manifest does not embed a grant, so no contract file changed. The manager's published grant stays the source of capacity.
- Network is host mode rather than "published ports on the WireGuard address": the helper's own validation (`ValidateListen`) requires a specific interface IP, which only exists in the host namespace. Firewall scoping is the manager's.
- `cpu_millis`/`memory_bytes` requests copy the defence-in-depth ceiling for one workload (1.5 CPU / 2.5 GiB); real per-slot measurements are still a follow-up from P4.12.
- The manifest names the manager's placeholders `{{name}}`; the manager's own templating syntax is unknown (no allocation API exists), so this is a proposal like the allocation schema.
- No UDP/voice ports (helper voice slice owns them) and no health check (the primary's mTLS handshake is the liveness probe).
