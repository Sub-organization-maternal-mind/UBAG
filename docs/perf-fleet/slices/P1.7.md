# P1.7 Dashboard polling hardening

Status: merged (see PR). Flags: none (behaviour-only, backward-compatible defaults). Migrations: none.

## Changes
- `apps/dashboard/src/lib/poll.ts`: `pollWhileVisible` no longer starts while hidden; new `{ immediate: false, maxBackoffMs }` options;
  in-flight guard (ticks never overlap); setTimeout chain with exponential, jittered backoff when `fn` returns a failure
  (status 429 / >=500 / network -1) or throws; honours `retryAfterMs`; resets on success; resumes immediately on visible.
- `lib/api/client.ts` + `types.ts`: `GwResponse.retryAfterMs` (optional, additive) parsed from `Retry-After` (seconds or HTTP date).
- Routes jobs/failed/workflows/webhooks/browser: `load()` returns the response on error paths so the poller can back off; the poller
  uses `immediate: false` (duplicate first load removed). `+layout.svelte` health poll unchanged (it has no separate first call).
- `antigravity/+page.svelte`: raw 3 s `setInterval` replaced by `pollWhileVisible(..., { immediate: false })`; `pollLiveState` still
  no-ops unless a login/verification is pending.
- `UpdatedAgo.svelte`: uses `pollWhileVisible` (no timer while hidden).
- `LiveBrowser.svelte`: no reconnect scheduling while hidden; reconnect on becoming visible.
- Test: `apps/dashboard/src/lib/poll.test.ts` (7 cases, fake timers, document stub).
