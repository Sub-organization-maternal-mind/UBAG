# P0.14 - Voice and admission carry-over safety

Status: merged (code + tests + docs). No deploy, no production access.

## What landed

- **Admission kill-switch (baseline-03)**: already delivered by P0.2 (`UBAG_ADMISSION_SHARED`, default true = live behaviour).
  Nothing further here; see `docs/perf-fleet/slices/P0.2.md` for the parity record and D2 rationale.
- **Voice reconciler (voice-0-reconcile-mute-failsafe)**, `apps/gateway/internal/serve/serve.go`:
  - The reconciler is now a small `voiceReconciler.step` driven through a `voiceMediaPeer` interface (`*voice.MediaHub` satisfies it).
  - It mirrors the stored `Muted` flag onto the live media path (`hub.SetMuted`) when the store value differs from the last applied
    value (a mute made on another replica, or by the store, now reaches the media path). Always on; it is a no-op when nothing changed.
  - Fail-closed mode, flag `UBAG_VOICE_RECONCILER_FAIL_CLOSED` (default OFF = today's fail-open): after 5 consecutive store errors
    for one session (`voiceReconcileMaxStoreErrors`, ~10 s at the 2 s tick) that session's media is disconnected. Any successful read
    resets the counter.
- **Memory voice store + SQL gateway warning (voice-0-store-default)**: `newVoiceComponentsFromEnv` logs a warning when
  `UBAG_VOICE_STORE` resolves to memory while the gateway store is SQL-backed.
- **Compose/env**: `UBAG_VOICE_RECONCILER_FAIL_CLOSED` passthrough (empty default) in `docker-compose.vps.yml` and
  `docker-compose.small.yml`; documented in `deploy/small/env.example`.

## Flags

| Flag | Default | Effect |
|---|---|---|
| `UBAG_VOICE_RECONCILER_FAIL_CLOSED` | off | stop media after 5 consecutive store errors per session |
| `UBAG_VOICE_STORE` | unchanged | `disabled` = containment switch (see runbook) |

## Runbook: containing voice (documented only; not applied anywhere)

Voice stays disabled for live media in production until P5.5: the relay secret is empty, so the audio relay refuses every session.
To also switch the routes off, an operator sets `UBAG_VOICE_STORE=disabled` in the gateway env and recreates the gateway container;
every `/v1/voice` route then answers 501. Revert by removing the override (default
memory). Before enabling live voice on a SQL gateway: set `UBAG_VOICE_STORE=postgres`, set `UBAG_VOICE_RELAY_SECRET`, and consider
`UBAG_VOICE_RECONCILER_FAIL_CLOSED=1`. None of this was applied by this slice.
