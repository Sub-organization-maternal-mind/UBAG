# P2.2 - Worker daemon protocol v2 and attempt/provisional event semantics

Status: merged (contract only; no runtime emits or consumes v2 yet).

## Files
- packages/shared-schemas/schemas/worker-daemon-request.schema.json (new): stdin line. v1 job line unchanged; opt-in `proto:2`, `attempt:{id,lease_generation,expires_at?}`, `slot_id`; opt-in control lines `{"__ubag_control__":"hello"|"probe","proto":2}`.
- packages/shared-schemas/schemas/worker-daemon-job-end.schema.json (new): JOB_END. v1 fields unchanged; opt-in `proto`, `attempt_id`, `slot_id`, `pid`, `warm_key` (lowercase hex hash only, never a raw profile path), `outcome_signal` (drift|manual_action|captcha|timeout|none), `submitted`, status `timed_out`. `$defs.control_reply` documents the hello/probe answers.
- packages/shared-schemas/schemas/job-event.schema.json: `data` gained documented, optional `attempt_id`, `stream_end_reason`, `partial`, `submitted`, `reconcile_required` (the envelope stays `additionalProperties:false`; `reconcile_required:true` requires `submitted:true`). Token events are provisional; the result comes only from a terminal event; `event_id` is derived from `attempt_id` when present (reference: `evt_` + sha256(`job_id:attempt_id:sequence`)[0:16]).
- packages/conformance/fixtures/worker-daemon/v2.json (new) + packages/conformance/scripts/validate-fixtures.mjs: schema verdicts for request/JOB_END/control-reply cases, a streamed job (tokens then terminal then JOB_END), an abandoned attempt (tokens, no terminal, no JOB_END; the retry reuses sequence numbers with distinct event ids), D4 failure semantics (deadline cut => `timed_out` + `data.partial`, post-submit ambiguity => `failed_terminal` + `submitted` + `reconcile_required`).
- tools/check-contracts.mjs: asserts the new schemas (Draft 2020-12, v1 required sets kept, v2 fields present, `proto` const 2) and the job-event data vocabulary.
- packages/sdk-go/generated_contract_manifest.go, packages/sdk-typescript/src/generated/contract-manifest.ts: regenerated.
- packages/shared-schemas/README.md: lists the worker schemas.

## Compatibility (both directions)
- New Go + old Python: Go sends a v1 line (or a v2 job line; old Python ignores unknown keys) and gets a v1 JOB_END. Control lines are never sent unless explicitly requested, because old Python answers an unknown line with a failed JOB_END with empty `job_id`; a sender treats that (or a handshake timeout) as "v1 daemon".
- Old Go + new Python: no `proto` in the request, so Python MUST reply v1-shaped (no v2-only fields, no control lines).

## Deviations
- `worker-daemon-request.schema.json` and `worker-daemon-job-end.schema.json` did not exist (the work item assumed edits); created them. `$id`s live under `/v1/worker/`.
- `packages/openapi/openapi.yaml` needed no edit: `JobEvent` is a `$ref` to the shared schema (same as P0.9a). The worker daemon schemas are internal and not exposed via REST.
- `stream_end_reason`, `partial`, `reconcile_required` are in job-event data (the work item put submitted/reconcile_required there but only outcome_signal/submitted in JOB_END); JOB_END deliberately carries no `reconcile_required`.
- Attempt id format `^att_[A-Za-z0-9]+$` is a new convention chosen here; P3.4 should confirm it.
- Cross-file `$ref` was avoided (the attempt id pattern is duplicated) because `lint:schemas` compiles each schema file on its own.
