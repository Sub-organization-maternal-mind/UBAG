# P4.8 - Fleet audit wiring with fail-closed append

Status: merged (library + auth-rejection wiring; enforcement points that do not exist yet adopt `Fleet.Guard`).

## Files
- `apps/gateway/internal/audit/fleet.go`: `FleetTenant` (`_fleet`), event-name constants (P2.5 vocabulary plus `viewer.opened`), `Fleet.NodeEvent` (node lifecycle -> `_fleet` chain), `Fleet.AttemptEvent` (job tenant chain), `Fleet.Guard` (append first; on append error the action does NOT run and `ErrAuditUnavailable` is returned; nil Fleet/Store also fails closed), `RejectAggregator` (one `node.auth_rejected` record per (reason, node) per flush with a `count`; bounded to N keys, overflow under node `other`; failed flush re-queues counts).
- `apps/gateway/internal/serve/{serve,helper_plane}.go`: when `UBAG_HELPER_PLANE=true`, `Authenticator.OnReject` also feeds the aggregator, flushed every minute (and once at shutdown) to the `_fleet` chain. Best-effort by design: a rejection is already refused.
- Tests: `audit/fleet_test.go`, `helperauth/fleet_test.go`.

## Flags / migrations
No new flag (behaviour only exists under `UBAG_HELPER_PLANE`, default off). No migration.

## Checks run
- `go vet ./internal/audit ./internal/helperauth ./internal/serve`: ok.
- `go test ./internal/audit ./internal/helperauth -run Fleet`: ok (forced store error refuses all three action kinds; VerifyChain passes on `_fleet` and job chains after a mixed sequence; 50 rejections -> one record with count 50; real mTLS rejections aggregate to one record).

## Not run
Full serve/httpapi suites, Postgres audit store.

## Deviations
- Grant, enroll and viewer-open handlers do not exist at this tip (viewer broker deferred, `/v1/nodes` enforcement not landed), so there is nothing to wrap yet. `Fleet.Guard` is the single fail-closed primitive those handlers must call; tests prove its behaviour for each event kind.
- Files named in the spec under `internal/siem` unchanged: the existing `BridgeStore` already forwards fleet records to SIEM.

## Follow-ups
- Handlers for node enroll/revoke/cert-rotate, attempt grant, and viewer-open must call `Fleet.Guard` with `fleet:manage` enforcement.
- Chain contention on `_fleet` under many nodes: appends are per-tenant serialized; aggregated rejections keep the rate low, lifecycle events are rare.
