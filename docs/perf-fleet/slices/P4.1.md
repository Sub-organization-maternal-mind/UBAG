# P4.1 Pure eligibility, pressure hysteresis and ceiling logic

Status: merged into `feat/perf-fleet`. Size M. Depends on P2.4 (merged). No wiring, no flag, no migration.

## Files

- `apps/gateway/internal/nodes/eligibility.go`: `Evaluate(grant, lastHeartbeat, now, pressure, ramped) Decision`. Ineligible (fail closed) when state is `revoked` or anything but `active`, `reservation_state != known`, `valid_until` zero or passed, last heartbeat zero or >= 3 x 15 s old. Limit = pressure-adjusted min(grant `max_browser_workloads`, ramped); a helper with no history (`ramped <= 0`) starts at 1.
- `apps/gateway/internal/nodes/pressure.go`: `Pressure.Step(sample, now)` hysteresis. Enter reduced immediately on CPU > 80% or available memory < 20%; leave only after 2 min continuously under 60% CPU and over 25% memory; any other sample (including the dead band) restarts the window. `AdmissionLimit` halves the limit when reduced, never below 1.
- `apps/gateway/internal/nodes/ceiling.go`: `CeilingFor(cores, memBytes)` = 75% of cores, 62.5% of memory (2c/4G -> 1.5 CPU/2.5 GiB, 4c/8G -> 3 CPU/5 GiB are that same rule); unknown host size -> zero. `EffectiveCap` = min(grant, ceiling), clamp-down only.
- `apps/gateway/internal/nodes/logic_test.go`: table tests; the clock is injected as the `now` argument.

All functions are pure: no I/O, no wall clock, no OET reservation recomputation (the grant is trusted as already net).

## Deviations

- Local `Grant` type with only the fields placement reads; the schema-parsing consumer (P4.15) will convert into it.
- Reduced admission is a fixed halving (floor 1), a design choice: the spec says only "reduces admission". Marked `ponytail:` in code.
- The ceiling table's two named rows are not separate entries; they equal the general 75%/62.5% rule and are asserted in tests.
- Ceiling input needs host cores/memory, which the allocation schema does not carry; P4.x inventory must supply them (unknown -> ceiling 0 -> effective cap 0, fail closed).

## Follow-ups

- Callers (P4.15 consumer, placement) must pass `now` and own the per-node `Pressure`, last heartbeat and ramp state.
- Ramp policy (how `ramped` grows from 1) is not defined here.
