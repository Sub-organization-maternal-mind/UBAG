## Behaviour

- Hub wait: if the store implements `jobs.JobWaker` and its hub is on (`UBAG_EVENT_NOTIFY=local`, P1.2 code already on this branch), the handler subscribes after auth and before its first read, re-reads on a wake, and otherwise only at `sseFallbackInterval` (2 s). Hub off or store without a hub (memory): unchanged `WaitEvents` path.
- `Last-Event-ID` resume (always on, additive): the header is resolved to a sequence by scanning the job history (bounded: 500/page, 20,000 events); replay starts after it. An unknown or over-long id replays from the start, as before.
- `UBAG_SSE_CLOSE_ON_TERMINAL=true` (default off): the stream ends after the first terminal event; a reconnect whose `Last-Event-ID` is itself a terminal event gets `204 No Content` (stops EventSource reconnecting). Terminal = `completed`, `completed_with_warnings`, `failed_terminal`, `dead_letter`, `cancelled`/`canceled`, `timed_out`/`timeout`, and `failed` with `data.retryable=false`. `failed`/`failed_retryable` stay non-terminal so a retry on the same job is still delivered. Resume and 204 are paired by design: closing without resume would make EventSource replay from 0 in a loop.
- `UBAG_SSE_MAX_STREAMS=N` (default 0 = unlimited): the (N+1)th concurrent stream gets `503` + `Retry-After: 5`, error `UBAG-SSE-STREAM-CAP-001` (retryable). The slot is reserved after auth and released on every exit path; 204 and error exits do not hold a slot.
- Unchanged: 10 s write deadline per frame, 15 s heartbeat `: ping`, 10 min connection TTL, `ubag_sse_connections_current`.

## Metrics

- `ubag_event_wakeups_total{source}` (`local` = hub wake, `fallback` = fallback tick or, with no hub, an event batch delivered by `WaitEvents`; `notify` is reserved for the deferred Postgres LISTEN/NOTIFY and always 0).
- `ubag_sse_event_frame_lag_seconds` histogram: `now - event.created_at` at frame write, live frames only (replay excluded). Cross-gateway clock skew is clamped at 0.
