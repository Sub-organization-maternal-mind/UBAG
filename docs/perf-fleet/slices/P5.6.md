# P5.6 Voice context index in control jobs and per-environment relay isolation

Status: merged (gateway code + relay/entrypoint changes + tests). Everything new is off by default; nothing deployed.

## Files

- `apps/gateway/internal/httpapi/voice_control.go`: `voiceContextIndex` + `runVoiceControl` adds `input.context` (zero-based) to `voice.activate` / `voice.deactivate` control jobs. The worker (`voice_job.py`, `voice_runner.pick_context`) already accepted `context`; before this the gateway never sent it, so a browser with several contexts always failed `context_ambiguous`.
- `apps/gateway/internal/httpapi/server.go`: `Config.VoiceContextIndex`.
- `apps/gateway/internal/serve/serve.go`: `UBAG_VOICE_CONTEXT_INDEX` wiring; `voiceRelayResolver` honours `UBAG_VOICE_AUDIO_RELAY_PORT_OFFSET`.
- `deploy/vps/browser/audio-relay.py`: `env_names()` + `UBAG_VOICE_ENV_ID` namespaces `ubag_virtual_mic_<id>`, `ubag_provider_sink_<id>` and the default mic FIFO `/tmp/ubag-voice-mic-<id>.pcm`. Invalid id raises at import (refuse to start; never fall back to shared names).
- `deploy/vps/browser/entrypoint.sh`, `deploy/small/browser-viewer/entrypoint.sh`: `UBAG_VOICE_RELAY_PORT_OFFSET` puts the relay on CDP proxy port + offset when `UBAG_VOICE_RELAY_ADDR` is unset.
- `docker-compose.small.yml`, `docker-compose.vps.yml`, `deploy/small/env.example`: pass-throughs. The compose default for `UBAG_VOICE_RELAY_ADDR` changed from `0.0.0.0:9099` to empty so the offset can apply; the entrypoint falls back to the same `0.0.0.0:9099`, so default behaviour is identical.
- Tests: `voice_control_test.go` (multi-context placement, opt-in, fail closed), `serve/voice_relay_resolver_test.go` (two instances on one host), `deploy/vps/browser/tests/test_relay_env_id.py`.

## Flags / env (all default off) / migrations

- `UBAG_VOICE_CONTEXT_INDEX` (gateway). Off = job shape unchanged.
- `UBAG_VOICE_AUDIO_RELAY_PORT_OFFSET` (gateway), `UBAG_VOICE_RELAY_PORT_OFFSET` + `UBAG_VOICE_ENV_ID` (browser). Unset = fixed 9099 and historic device names. The two offsets must be set to the same value.
- No migrations, no public API/contract change (control jobs are internal).

## Semantics

- Index = position of the session's (target, identity) context among its instance's topology contexts ordered by `created_at` then `context_id`. Sent only when the instance hosts more than one context. If the flag is on and the context cannot be pinned (unregistered or duplicated identity), the control job is NOT created and the session fails activation (fail closed), instead of guessing and risking the wrong account's browser context.
- Relay port with the offset on: registered CDP endpoint port + offset. An endpoint without an explicit port, or a result above 65535, falls through to the legacy single address or `ErrRelayUnavailable` (fail closed). The explicit `UBAG_VOICE_AUDIO_RELAY_MAP` still wins.

## Deviations

- The work item named only the vps entrypoint; the small browser-viewer ships the same relay script, so its entrypoint got the same change.
- The flag `UBAG_VOICE_CONTEXT_INDEX` is new (no existing synonym). Reason: topology contexts carry no explicit browser-context index, so the creation-order mapping is an assumption that must be verified against a live multi-context browser before it is turned on.
- Relay `--addr` default and the Pulse/FIFO names are unchanged when the new vars are unset; the relay does not read the port offset itself (the entrypoint computes the address).

## Follow-ups

- Verify the topology creation order equals Playwright `browser.contexts` order on a live multi-context browser (human-supervised, P5.4-style) before enabling `UBAG_VOICE_CONTEXT_INDEX`; a worker-reported explicit index in topology would remove the assumption.
- `UBAG_VOICE_ENV_ID` only matters when two environments share a PulseAudio server or `/tmp`; separate containers already isolate. Set per environment together with the port offsets when co-locating (helper plane, P5.7).
