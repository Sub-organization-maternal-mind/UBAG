# P1.3 - gRPC stream, OpenAI facade and cancel-watch on the event hub

Status: merged (see PR). Same flag as P1.2: `UBAG_EVENT_NOTIFY=off|local` (default off). No new flags, no migrations.

## What changed

- `jobs/notify.go`, `sqlite.go`, `postgres.go`: `JobWaker` interface and `SubscribeJobWake(jobID)` (ok=false while the hub is off).
- `executor/workerconsumer.go`: the per-job cancel-watch wakes from the hub and keeps a 2 s fallback `Get` (`cancelWatchFallback`); hub off keeps the legacy 250 ms `Get` poll. The worker context is cancelled on the wake, not on a timer.
- `grpcapi/server.go`: `StreamJobEvents` no longer does a `Get` after every batch (terminal detection is `isTerminalEvent`). Each wait is bounded by `streamIdleCheck` (30 s); on idle it does one `Get` and closes the stream if the job is already terminal (cursor past the terminal event), otherwise keeps waiting. No heartbeat message was added (the proto has none); the idle check is the TTL.
- `httpapi/openai_facade.go`: `waitFacadeJob` batches 100 events per wake instead of 1 (one `Get` per batch). It already waits through `WaitEvents`, so it uses the hub automatically; the "store error is not client disconnect" rule is untouched.

## Checks run

- `go vet` on jobs, grpcapi, httpapi, executor: clean.
- `go test ./internal/grpcapi` (incl. new idle-close test), `go test -run "Cancel|LostExecution" ./internal/executor` (incl. new `TestCancelWatchWakesFromHub`: cancel observed < 500 ms with a 2 s fallback), `go test -run Facade ./internal/httpapi`: pass.

## Checks NOT run

- Postgres-backed suite; off-vs-local A/B (no isolated stack, D5).

## Deviations / notes

- Facade `Get` per batch is kept: it must return the job, and not every terminal event is guaranteed to carry `data.status`.
- Hub is in-process: a cancel written by another gateway is seen by the 2 s fallback.
