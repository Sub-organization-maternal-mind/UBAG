# P0.9c - Stage timings: Go gateway stage metrics

Status: merged (Go gateway side only; Python marks are P0.9b).

## What landed
- `ubag_job_stage_duration_seconds{stage,adapter_family}` histogram. `WorkerConsumer` parses `data.timings_ms` from the run's events (later events win; unknown keys, non-numeric, negative, NaN and > 24 h values ignored) and records it once the job reaches a terminal status. `executor.JobStages` is the closed key set; `TestMetricJobStagesMatchEventSchema` pins it to `job-event.schema.json`. Recorder is an optional interface (`executor.StageMetricsRecorder`), so existing `WorkerMetricsRecorder` implementers are unchanged. Zero-valued `adapter_family="mock"` default series keep the name present before the first observation.
- `method_class` (`read`/`write`/`other`, `METHOD_CLASSES`) on `ubag_gateway_request_latency_seconds` (the overload route histogram) and on `ubag_gateway_http_request_duration_seconds_{sum,count}` (contract entry already added by P0.9a).
- Zero stubs made real or removed:
  - `ubag_gateway_ready{check=...}` is now probed per scrape with the same `Ready()` calls as `/v1/ready` (2 s bound); `queue` = `executor.Stats` succeeded.
  - `ubag_webhook_deliveries_total{outcome,error_class}` and `ubag_webhook_delivery_duration_seconds` (real histogram) are fed by `DeliveryWorker.OnDelivery` (wired in `serve.go`). `error_class` is bounded to the sender's closed set plus `other`.
  - `ubag_adapter_requests_total` / `ubag_adapter_request_duration_seconds` hard-coded mock zeros removed (adapter-owned; the gateway has no real source). Removed from `CONTRACT_METRIC_NAMES` in `tools/check-metrics-cardinality.mjs`; `ubag_job_stage_duration_seconds` added there.
