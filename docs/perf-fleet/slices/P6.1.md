# P6.1 - queue_reason and operator fleet read API: contract and SDK surface

Status: merged when its PR is merged into `feat/perf-fleet`. Size L. Depends on P2.6 and P4.17, both merged. Contract and SDK surface only: the gateway computes no `queue_reason` yet and has no fleet source, so nothing a client can observe changes in production. No flag, no migration.

## What landed

- **`queue_reason` on JobResponse** (`job-response.schema.json`): optional `queue_reason` (nullable, six coarse values, decision D8: computed at read time, nothing stored) and `queue_reason_since` (nullable date-time, restarts when the reason changes). `dependentRequired` makes `queue_reason_since` need `queue_reason` to be present. Only meaningful while `status` is `queued`. Absent means unknown, never an error.
- **Reuses queued/blocked, adds nothing else.** `job-event.schema.json` documents an optional `data.reason` token (queued event: the coarse queue reason; blocked event: the worker's own reason, unchanged). No new job status, no new event type, no new error code or category (`errors.json` untouched). `UBAG-QUEUE-BACKPRESSURE-002` stays the create-time depth answer.
- **`GET /v1/fleet/nodes` and `GET /v1/fleet/summary`** (OpenAPI `listFleetNodes`, `getFleetSummary`, tag Fleet; action `fleet:read`, operator and admin only; 200/400/401/403/405/429/500/501). Closed schemas: `FleetNode` (opaque `node_id`, `label`, `region`, `state`, `ineligible_reason`, `heartbeat_at`, `grant`, `usage`, `pressure`, `readiness[]`), `FleetGrant`, `FleetUsage`, `FleetPressure`, `FleetReadiness`, `FleetNodeListResponse` (`total`, `data`; no cursor, the registry is bounded to 256 nodes and `limit` defaults to 256), `FleetSummary` (`nodes_by_state`, `workload_limit_total`, `workloads_in_use_total`, `nodes_pressure_reduced`, `held_by_reason`: open identifier-token keys, at most 64, counts only). There is no address, hostname, endpoint, `nat_ip`, certificate or SPKI field and no `remote_endpoint`.
- **`JobsSummary.queued_by_reason`** now documents that its keys are the coarse `queue_reason` values.
- **Manifests regenerated, never hand-merged**: `tools/make-sdks/generate-manifest.mjs` now also emits the queue reason vocabulary from the schema (`UBAG_QUEUE_REASONS`, Go `UbagQueueReasons`); `GET /v1/fleet/nodes` and `/v1/fleet/summary` are in `UBAG_ENDPOINTS`; the `job-response` fingerprint changed.
- **SDKs (hand-written)**: TS `listFleetNodes`, `getFleetSummary`, `UbagQueueReason`, `UbagFleetNode` and friends, optional `queue_reason`/`queue_reason_since` on `UbagJobResponse`; Go `ListFleetNodes`, `GetFleetSummary`, `ListFleetNodesParams` (responses are `JSON` maps, so no Go type change for `queue_reason`). `apps/mobile/src/lib/types.ts` mirrors the two job fields (D8).
- **Fixtures and route mappings**: scenarios `jobs.get.queued-reason`, `fleet.nodes.ok`, `fleet.summary.ok`, `fleet.nodes.not-implemented` (501) mapped in the TS and Go conformance harnesses; `validate-fixtures.mjs` requires the first three, validates the `fleet` category against OpenAPI with Ajv, and rejects any address, hostname, endpoint or certificate pin in a fleet fixture.
- **Gateway**: `httpapi/fleet_handlers.go` registers both routes. Method check, then `fleet:read`, then 501 `UBAG-NOT-IMPLEMENTED-001` ("fleet source is not configured"). Authorization runs before the 501, so a role without `fleet:read` gets 403 on every deployment and learns nothing about whether a fleet exists.
- **Docs**: `contracts/job-lifecycle.md` (Queue reason section with the six values and the placer mapping below), `contracts/job-contract.md`, `contracts/error-catalog.md` ("Queue holds are not errors"), `reference/api.md` route rows.

## The vocabulary (so P6.2 can populate it)

Coarse tenant value (JobResponse.`queue_reason`, `JobsSummary.queued_by_reason`) from the fine value (operator only, `FleetSummary.held_by_reason`). The fine tokens are the `Reason` strings the consumer already uses when it holds a lease (read from the code at the P4.17 tip, not invented), plus `retry_backoff`, which is a scheduled retry rather than a lease hold. The coarse set is closed; the fine set is open (`held_by_reason` keys are identifier tokens, so a new hold reason never needs a contract change).

| Coarse (tenant) | Fine (operator) | Source |
|---|---|---|
| `waiting_for_worker` | `local_slots_busy` | `workerconsumer.go`: local gate full, job behind others |
| `waiting_for_identity` | `identity_busy`; `voice_session_active`, `voice_admission_in_flight` | `nodes.ErrLaneBusy` (identity lane); `voicelane.go` (a live voice session holds the browser, ADR-0012) |
| `waiting_for_capacity` | `no_capacity` | `nodes.ErrNoCapacity` (grant full, ramp, pressure, manager reservation) |
| `waiting_for_node` | `no_eligible_node`, `affinity_unavailable` | tenant profiles only on ineligible nodes; conversation's bound node down |
| `retry_backoff` | `retry_backoff` | retryable failure waiting out its delay |
| `temporarily_unavailable` | everything else: `fleet_unreadable`, `profiles_unreadable`, `profile_selection`, `reserve_failed` (placer store errors, "could not tell" holds, never a local run); `lane_state_unavailable` (voice lane check); `ledger_unavailable`, `attempt_lease_held`, `attempt_conflict`, `attempt_lease_lost`, `helper_lost`, `helper_unreachable`, `helper_still_running` and the other reconcile-gate reasons (P4.18: the earlier attempt's outcome is still being confirmed); `picker_error`, `placement_invalid` | `helperplacer.go`, `voicelane.go`, `reconcilegate.go`, `remoterunner.go`, `remoteresume.go` |

Node `state` from `nodes.Decision.Reason`: `draining` -> `draining`; `reservation_unknown` -> `unknown_reservation`; `heartbeat_missed` -> `lost`; `revoked`, `grant_expired`, `no_capacity` -> `ineligible` with `ineligible_reason` set; eligible -> `eligible`. `pressure.recover_at` is the end of the open recovery window (`PressureCalmSince` + 2 min) or null; `usage.admission_limit` is `nodes.Admission(...).Limit`, `usage.workloads_in_use` is `Placer.Used`. Readiness is `{target, session_state, count, checked_at}`, an aggregate with no account or profile identifier, fed by the P4.13 probe once the gateway consumes it (empty until then).

## Flags and migrations

None. The work item named `UBAG_FLEET_MODE`; it is not introduced (BINDING rule 5: reuse the existing ladder). P6.2 should gate the population on `UBAG_HELPER_NODES` (the first rung) and keep answering 501 when no fleet store is wired. The routes themselves need no flag: today they only ever answer 501 after authorization.

## Deviations

- The work item lists `routes.go` and a 501 handler under `UBAG_FLEET_MODE`; the routes and a flagless 501 handler landed (see Flags). No `Fleet` source field was added to `httpapi.Config`: that is P6.2's seam and a field with no implementation would be speculative.
- `errors.json` and `rbac.ts`/`authz.go` are unchanged: no new code (by design), and `fleet:read` already exists from P2.5.
- `job-event.schema.json` was not in the work item's file list; the optional documented `data.reason` is the only way to state "reuse queued/blocked with `data.reason`" in the contract.
- "Node-qualified `metadata.worker`" (in the work item title) is not part of the P6.1 deliverable and was not done: `metadata.worker` is already a free string (max 160), so a node-qualified value needs no schema change and belongs to the helper-plane writer.
- `scenario_count` in `scenarios.json` was already stale before this slice (nothing reads it) and is left alone.

## Follow-ups

- **P6.2**: build the fleet source and fill `queue_reason`, `queue_reason_since`, `queued_by_reason` and `held_by_reason` using the table above. Held jobs are in the consumer's off-worker holds (P4.17), not the store, so the read-time computation needs a bounded in-memory view of them (job id to fine reason and since), memoized per request; a job with no entry and status `queued` is `waiting_for_worker`. Voice-lane and reconcile-gate holds live in the consumer as well (`LaneBusyError`, `HelperRetryError`), so one registry of "held lease -> fine reason" fed from `holdLease`/`holdPlan` covers all of them.
- `UBAG-NOT-IMPLEMENTED-001` (used by every 501 route) is not in the `errors.json` catalog; pre-existing, now also on the fleet fixture. Add it when the catalog is next touched.
- P6.4 (dashboard) reads `Job` in `apps/dashboard/src/lib/api/types.ts`, which still lacks the two optional fields (that file is in the P6.4 work item).
- `FleetNodeListResponse` has no cursor on purpose (at most 256 nodes). If the registry bound is ever raised, add `cursor`/`next_cursor` additively.
