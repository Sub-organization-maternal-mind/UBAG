# P1.1 - Characterization tests: event waiting, streams, consumer terminal validation

Status: merged (tests only; zero behaviour change).

## What landed

Tests pinning today's behaviour, as the safety net for streaming ingestion (which removes the consumer's
pre-apply exactly-one-terminal gate).

| Area | File | Pinned behaviour |
| --- | --- | --- |
| `Store.WaitEvents` (memory, sqlite) | `apps/gateway/internal/jobs/wait_events_test.go` | existing events return immediately; missing job -> `(nil,false,nil)`; blocks then wakes on a new event; ctx cancel -> `(nil,true,context.Canceled)`; deadline -> `(nil,true,DeadlineExceeded)`; limit + ascending order (limit<=0 -> default page); duplicate worker event adds no event and does not wake waiters; the store does NOT close the wait on a terminal event |
| `Store.WaitEvents` (postgres) | `apps/gateway/internal/jobs/postgres_wait_events_test.go` | same shared suite (`waitEventsContract`); skipped unless `UBAG_TEST_POSTGRES_DSN` is set; matches `*postgres*_test.go` discovery in `tools/run-postgres-roundtrip-tests.mjs` |
| gRPC `StreamJobEvents` | `apps/gateway/internal/grpcapi/server_test.go` | replays history then closes cleanly (io.EOF) on a terminal event; `after_sequence`; live events then close; stays open without a terminal until ctx ends; auth/NotFound/InvalidArgument |
| HTTP SSE `/v1/sse/jobs/{id}` | `apps/gateway/internal/httpapi/sse_events_test.go` | replay from sequence 0 (`Last-Event-ID` ignored); stream does NOT close on a terminal event (next frame is `: ping`); idle ping; live events; replay continues past the first 100-event page without duplicates; `?snapshot=true` closes after replay; 404 / 401 |
| Worker consumer terminal validation | `apps/gateway/internal/executor/workerconsumer_ingest_test.go` | no events, empty output, malformed JSONL, zero terminals, two terminals (completed+completed, completed+failed), truncated stream (cut before terminal / mid terminal line), event without id/sequence, event for another job: all end `failed_retryable`, `lease.Fail`, no result, never `completed`, and the history is exactly `queued,assigned,failed` (worker events NOT applied: the pre-apply gate). Positive control: one terminal -> `queued,assigned,running,completed` + `lease.Complete`. `parseWorkerJSONL` truncation/blank-line rules |

## Deviations

- SSE tests live in a new file `httpapi/sse_events_test.go` (not `server_test.go`) to avoid merge conflicts with parallel slices editing `server_test.go`.
- `apps/gateway/internal/httpapi/server.go`: `sseHeartbeatInterval` changed from a `const` to a package `var` (same 15s value, never reassigned in production) so the ping test can shrink it. No behaviour change.
- `grpcapi/server_test.go`: `newTestClient` now delegates to a new `newTestClientWithStore` that also returns the store.
- The consumer's failure end state is `failed_retryable` (not `failed`) and the history includes the consumer's own `assigned` event; the tests pin the real behaviour.

## Observations (not changed, follow-up candidates)

- gRPC `StreamJobEvents` with `after_sequence` beyond the last event of an already-terminal job blocks until the client context ends (the terminal check only runs after a batch is delivered). Not pinned, to avoid freezing a latent bug.
- SSE has no `Last-Event-ID` resume (pinned as ignored; relevant to P2.7/P3.13).
