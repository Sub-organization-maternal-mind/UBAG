# P3.3 Slot-scoped page registry and physical-session identity lock

Status: merged (see PR). The real two-subprocess flock test is written but was NOT run (see below).

## Files
- `apps/worker/ubag_worker/live/identity_lock.py` (new): `slot_id()`, `identity_lock_enabled()`, `physical_session_key()`, `IdentityLock` (blocking POSIX `flock`; Windows no-op + one-time stderr warning).
- `apps/worker/ubag_worker/live/page_driver.py`: `_page_registry_path()` gains `.slot<id>` suffix in slot mode; `_registry_update` writes a unique tmp name (`<path>.<pid>.<thread>.tmp`) and removes it on failure; new `reap_orphan_registries(pool_size, endpoint)`.
- `apps/worker/ubag_worker/live/daemon.py`: `run_job` takes the identity lock around the real job (`_run_job`, the old body) in slot mode only.
- `apps/worker/run_worker_daemon.py`: on start, in slot mode with `UBAG_WORKER_POOL_SIZE` set, reaps registries of slots with id >= pool size.
- Tests: `apps/worker/tests/test_slot_isolation.py` (new), `apps/worker/tests/test_page_registry.py` (+2 tests).

## Flags (defaults)
- `UBAG_WORKER_SLOT_ID` unset: registry path, lock and reaping behave exactly as before (only the tmp file name used for registry writes changed).
- `UBAG_WORKER_IDENTITY_LOCK` (auto-on only when a slot id is set; `0/1` overrides). `UBAG_WORKER_IDENTITY_LOCK_DIR` overrides the lock directory (default `<dir of UBAG_CHAT_LEDGER_PATH>/identity-locks`).
- Go side must pass `UBAG_WORKER_SLOT_ID`, `UBAG_WORKER_IDENTITY_LOCK` (and `UBAG_WORKER_POOL_SIZE`) through `minimalWorkerEnv`: that is the P3.5 allowlist edit, not done here.

Migrations: none.

## Design notes
- Physical key = sha256(lowercased CDP endpoint without trailing slash, else realpath(user_data_dir), plus target); no tenant, so two tenants on one account serialize. The warm-page key in `_driver_key` still includes the tenant.
- flock is released by the kernel when the holder dies (SIGKILL included), so there is no stale-lock cleanup.
- Orphan reaping closes the orphan registry's tabs over `/json/close` (needs the endpoint), then deletes the file; if the browser is unreachable the file is kept for the next start. Only numeric slot ids >= pool size are touched.

## Checks run

## Checks NOT run
- `test_flock_blocks_same_key_passes_other_key_and_frees_on_sigkill` (two real subprocesses, `UBAG_ADAPTER_OFFLINE=1`, SIGKILL) self-skips on Windows; no POSIX Python was available to this agent. Run it on Linux/CI before relying on the lock.

## Deviations
- The spec lists `envelope.py`; it needed no change (key built in `identity_lock.py` from `_normalize_payload` output).
- The "supervisor reaps orphans on start" is done in the Python daemon start-up (`run_worker_daemon.py`) because the Go supervisor does not exist until P3.6; P3.6 may also call it by simply starting slots with `UBAG_WORKER_POOL_SIZE`.
- `_registry_update` still does read-modify-write without a cross-process lock; in slot mode each slot owns its file, so that is sufficient.
