# P0.10 cgroup, throttle and host-pressure sampler in the harness

Status: merged-ready (code + offline fixture tests + docs). No real container was sampled; the harness was not aimed at any host.

## Files

- `tests/load/lib/cgroup.mjs` (new): parsers (cgroup v2, v1 fallback, PSI, `/proc/meminfo`, `/proc/stat`), per-container summary, helper pressure rules, sampler, `docker exec` reader.
- `tests/load/acceptance.mjs`: `docker stats --no-stream` sampler removed; `--cgroup-containers role=name,...` added (`--docker-stats-container` kept as a one-container alias); `--pressure-window-ms`; report field `docker` replaced by `resources`; Markdown section rewritten.
- `tests/load/acceptance.test.mjs`: fixture-based v2 and v1 cases, pressure rules, sampler (dead container, no docker), target validation, integration through `run()`; the full `--require-goals` run now samples fixture cgroups.
- `tests/load/thresholds.goals.json`: `min_memory_headroom_pct` 20, `max_oom_kills` 0.
- `docs/load-testing.md`: "Resource sampling" section.

## Behaviour

- One read-only `docker exec <c> sh -c 'cat ...'` per container per tick (plus one closing sample so a short run still has a delta). Container/role names are regex-validated before they reach `docker exec`.
- Per container: `cpu_throttled_pct` (CFS periods throttled), `cpu_throttled_ms`, `cpu_cores_avg`, memory peak/limit/`memory_headroom_pct`, `oom_kills`, PSI maxima. A container with no memory limit has `memory_headroom_pct: null` (not counted).
- Summary keys: `memory_headroom_pct` (min), `cpu_throttled_pct` (max), `oom_kills` (sum). Under `--require-goals` they fail closed when unmeasured.
- Helper rules as booleans (`host_pressure`): `cpu_over_80`, `mem_available_under_20`, `pressure_triggered`, `recovered` (CPU <60% and MemAvailable >25% held for the whole window, default 120 s; `null` if never triggered). Not gated.

## Flags / migrations

New CLI options only (harness, no runtime flags): `--cgroup-containers`, `--pressure-window-ms`. No migrations, no contract changes.

## Checks not run

- No live `docker exec` against a real cgroup v1 or v2 container (Docker was not used); parsers are verified against hand-written fixtures only.

## Deviations

- `report.docker` was renamed to `report.resources` (internal harness report; the only consumer is the Markdown renderer and the tests).
- Throttle % is reported, not gated: the plan states no threshold for it.
- Host CPU % is derived from `/proc/stat` deltas read inside the sampled container, which is the host/VM view unless the runtime virtualises `/proc` (lxcfs). Documented in `docs/load-testing.md`.
