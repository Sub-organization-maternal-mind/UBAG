# P5.1 Voice frame-age metric and in-process relay latency bench

Status: merged (code + tests + docs). Local, NON-AUTHORITATIVE loopback numbers only; nothing was aimed at any host.

## Files

- `packages/observability/src/metrics.mjs` (+ test): contract entry `ubag_voice_relay_frame_age_seconds` (gateway histogram, label `direction`, added to the cardinality budget as `fixed`). Committed before the implementation.
- `tools/check-metrics-cardinality.mjs`: the new metric is a required contract name (always rendered, zeroed until observed).
- `apps/gateway/internal/voice/media.go`: mic frames carry an enqueue stamp (`micFrame`); `mic` age observed after `relay.Send` returns; `speaker` age = `relay.Recv` returned -> `WriteSample` returned. A `WriteSample` failure now counts `ubag_voice_media_frames_dropped_total{direction="speaker"}` (previously declared, never incremented) before the session is closed.
- `apps/gateway/internal/voice/metrics.go`: bucketed histogram in `MediaCounters` (`ObserveFrameAge`, `SnapshotFrameAge`, buckets 5 ms doubling to 1.28 s). Direction is a closed set; other values are ignored.
- `apps/gateway/internal/httpapi/server.go`: renders the histogram (both directions always present).
- `apps/gateway/internal/voice/media_bench_test.go`: `TestLatency*` guards and `BenchmarkRelayLatency` (1/5/10/20 sessions, 20 ms pacing, real `MediaHub` + pion client + `fakeRelay`), exact p50/p95/p99; optional JSON report.
- `apps/gateway/internal/voice/metrics_test.go`, `httpapi/stage_metrics_test.go`: unit tests.
- `tests/load/acceptance.mjs`, `acceptance.test.mjs`, `thresholds.goals.json`: `--voice-latency <report>` ingestion, `voice_relay_p95_ms`, goal `max_voice_relay_p95_ms=100`.
- `docs/load-testing.md`: the two measurement points are defined first ("Voice relay latency").

## Flags / env / migrations

No runtime flags; no migrations. New CLI option `--voice-latency`. New bench-only env: `UBAG_VOICE_LATENCY_REPORT` (output path), `UBAG_VOICE_LATENCY_SECONDS` (window, default 3).

## Behaviour notes

- The `MediaMetrics` interface is unchanged. Age reporting goes through the optional `FrameAgeObserver` interface, so existing sinks keep compiling and a sink without it simply records no ages.
- `--require-goals` now also needs `--voice-latency`; a missing or malformed report leaves `max_voice_relay_p95_ms` unmeasured, which fails closed.

## Evidence (NON-AUTHORITATIVE, Windows dev box, 2 s window, loopback)

1/5/10/20 sessions: mic p95 <= 0.06 ms, speaker p95 <= 0.52 ms (p99 <= 0.53 ms). On Windows the clock granularity quantises sub-millisecond ages (many p50 values read 0), so read these as "queueing is negligible in process", not as precise latency. No lab-host number exists (D5).

## Deviations

- The `mic` age is observed after `relay.Send` returns (not at dequeue before Send) so it covers the relay write, matching the "enqueue-to-Send" wording of the voice-0 work item. The speaker point is observed after `WriteSample` returns.
- `acceptance.mjs` cannot run Go, so the bench output reaches the goals file through a JSON report (`--voice-latency`) rather than a new scenario.
- `waitGathered` and `startFakeRelay` test helpers now take `testing.TB` so benches can reuse them.
