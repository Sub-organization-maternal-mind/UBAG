# P6.2 - Fleet read handlers and queue_reason population

Status: merged when its PR is merged into `feat/perf-fleet`. Size M. Depends on P6.1, P4.4 and P4.17 (all merged). No contract change, no migration, no new flag.

## What landed

- **`nodes.FleetView`** (`apps/gateway/internal/nodes/fleetview.go`): the read-only operator view. It joins what placement already reads (grants as the placer sees them: the manager poller's `Current`, else the store's list; `Store.GetState`; `Placer.Used`) and runs `Admission` per node, so the state is the placer's own verdict. `Decision.Reason` maps to the node `state` exactly as the P6.1 shard specified: `draining`, `reservation_unknown` -> `unknown_reservation`, `heartbeat_missed` -> `lost`, `revoked` / `grant_expired` / `no_capacity` -> `ineligible` with `ineligible_reason`. A node with a grant and no state row reads as `lost` with a null heartbeat. `pressure.recover_at` is `PressureCalmSince + 2 min` while a recovery window is open. `readiness` is `[]` (the P4.13 probe is not consumed by the gateway yet). The JSON types carry no endpoint, address, NAT IP or pin, and a test serialises a node whose allocation has all of them and asserts none appears. `label` is the opaque `node_id`.
- **`GET /v1/fleet/nodes` and `/v1/fleet/summary`** (`httpapi/fleet_handlers.go`): method check, then `fleet:read` (operator/admin), then 501 when `Config.Fleet` is nil, else the view. `limit` 1..256 (400 `UBAG-VALIDATION-LIMIT-001` otherwise); `total` is the unlimited count. A source error is an opaque 500.
- **`executor.HoldBoard`** (`executor/queueholds.go`): the bounded in-memory view of queued jobs the consumer is holding (job id -> tenant, app, fine reason, since). `WorkerConsumer.Holds` is told at every pre-start refusal (reconcile gate, placer, local gate, voice lane) and clears at assignment and when a re-leased job is already terminal. At most 1024 entries; an entry not refreshed for 2 minutes is ignored (a held lease is retried and re-noted every <= 30 s); reasons must be identifier tokens (else `other_hold`); at most 64 distinct reasons are counted. `since` restarts only when the fine reason changes.
- **`queue_reason` on job reads** (`GET /v1/jobs/{id}`, `GET /v1/jobs`): for `status=queued` only, the coarse value from `executor.CoarseQueueReason` (the P6.1 table: `waiting_for_worker`, `waiting_for_identity`, `waiting_for_capacity`, `waiting_for_node`, `temporarily_unavailable`; anything unlisted is `temporarily_unavailable`). A queued job with no hold is `waiting_for_worker` (`queue_reason_since` = its `updated_at`). The fine reason never reaches a job response. Create and retry responses are unchanged.
- **`JobsSummary.queued_by_reason`**: the tenant/app scope's holds grouped by coarse reason, plus `queued - held` as `waiting_for_worker` (clamped at 0: a hold can briefly outlive a cancelled job).
- **Operator detail**: `FleetSummary.held_by_reason` is the fine-reason counts across all tenants (counts only, no identifiers).
- **remote_endpoint redaction extended**: `GET /v1/browser/instances` withholds `remote_endpoint` for an instance whose endpoint host is the host of any granted helper node, whatever `UBAG_REDACT_REMOTE_ENDPOINT` says. If the fleet cannot be read it withholds every endpoint (fail closed). With no fleet source the legacy shape is unchanged.
- **Wiring** (`serve`): with `UBAG_HELPER_NODES` on, `serve` builds the board and the view (`newFleetViewFromEnv`; `Used` comes from the placer when `UBAG_HELPER_DISPATCH` is also on), passes both to `httpapi.Config` and sets `consumer.Holds`. Both are nil otherwise.

## Flags and migrations

No new flag. Everything is gated on `UBAG_HELPER_NODES` (default off; first rung of the ladder, per the P6.1 shard and BINDING rule 5): without it the fleet routes answer 501, `queue_reason` is omitted and `queued_by_reason` is `{}`, exactly as before. No migration.

## Deviations

- The work item named `UBAG_FLEET_MODE`; not introduced (BINDING rule 5; the flag is `UBAG_HELPER_NODES`, as the P6.1 shard asked).
- `retry_backoff` is not populated. It is in the closed coarse set, but a retryable failure is a new attempt, not a lease hold, so nothing the consumer holds maps to it today (a comment in `CoarseQueueReason` records this). A `scheduled` or `not_before` job is not shown as `retry_backoff` either: the two are not distinguishable from the job row.
- The hold view is in-process (one primary per fleet, the same limit the Placer documents). A gateway whose consumer runs in another process would report every queued job as `waiting_for_worker`.
- `queue_reason` is not set on create/retry/replay responses (a just-queued job has no hold yet); reads are the contract (D8).
- The fine reason is exposed to operators only as counts in `held_by_reason`; there is no per-job fine reason on any API ("full reason only on the operator API" is satisfied by the summary).
- The "helper-hosted instance" test is by endpoint host (the topology model has no node field to key on). A helper reached through a hostname that does not match its granted endpoint host would not be recognised; the fail-closed rule covers an unreadable fleet only.
