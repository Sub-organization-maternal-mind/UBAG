# P7.1 - synthetic_chat browser fixture (warm-daemon path)

Status: merged (see PR). Builds and unit-checks the fixture and overlay. A full gateway -> daemon -> real browser run, and the
Playwright e2e tests, were NOT run on this box (no Playwright); see "Checks not run".

## What landed

- `tools/synthetic-provider/server.mjs` (+ `README.md`, `server.test.mjs`): zero-dependency, loopback-only fake web chat.
  Per-prompt directive `[[synthetic scenario=... k=v]]` selects: slow think, streaming cadence, long output (<= 2 MiB),
  truncated (stalls with the Stop control up, so the worker hits its deadline), dropped connection (socket killed mid-stream,
  turn `data-state="error"`). Signed-out page (`?signed_out=1`, `--signed-out`, `POST /__control`), slow attachment accept
  (`--attach-ms`, `POST /__control`; Send stays disabled until every upload is accepted), `GET /__stats` counters
  (`page_loads`, `chat_requests`, `chat_truncated`, `uploads`, `max_active_streams`, ...). Every parameter is bounded; unknown
  scenario/key/value is a 400 and counted, never a silent default run. Refuses non-loopback bind and non-loopback `Host`.
  No form, password input, CAPTCHA or external origin in either page (asserted).
- `apps/worker/ubag_worker/live/synthetic.py`: the `synthetic_chat` `ProviderSelectors` (all `data-synthetic=` markers) and
  `register_synthetic_provider()`, called once at the end of `selectors.py`. Registered only when `UBAG_SYNTHETIC_PROVIDER`
  is truthy AND `UBAG_SYNTHETIC_PROVIDER_URL` (default `http://127.0.0.1:4799/`) is `http` on a loopback address; otherwise the
  target stays unregistered (stderr note, real providers unaffected). No settings, no `delete_chat` (the reaper can never
  touch it), no voice control.
- `adapters/synthetic_chat/manifest.json` (+ placeholder entrypoint package) and `adapters/registry.synthetic.json`
  (`kind: synthetic_overlay`, `extends: registry.json`). NOT in `adapters/registry.json`, `REQUIRED_ADAPTER_IDS` unchanged. The
  gateway reads `adapters/<target>/manifest.json` by directory, so the attachment policy applies without a registry entry
  (documents, png/jpeg, wav; 4 files, 8 MiB each).
- Gateway: `synthetic_chat` joins `warmDaemonTargets` routing only while `UBAG_SYNTHETIC_PROVIDER` is truthy
  (`isWarmDaemonTarget` in `serve.go`); `mock` and `voice.*` command types keep their existing path. `minimalWorkerEnv` forwards
  `UBAG_SYNTHETIC_PROVIDER`, `UBAG_SYNTHETIC_PROVIDER_URL`, `UBAG_WORKER_STAGE_TIMINGS`.
- `tests/load/workloads/mixed.json`: `provider_scenario.target` is now `synthetic_chat` (description says why). The manifest is
  still `harness_support: planned`; the acceptance harness takes `--target synthetic_chat` and, for non-mock targets, only
  requires non-empty result text (its echo-integrity check is mock-only).
- `package.json`: `test:synthetic-provider` (not part of `pnpm check`).

## Flags and migrations

- `UBAG_SYNTHETIC_PROVIDER` (new, default OFF). `UBAG_SYNTHETIC_PROVIDER_URL` (new config value, loopback only).
  Both forwarded by the gateway to the worker. No migrations. No public API/contract change.
- Run: `node tools/synthetic-provider/server.mjs --port 4799`, then gateway + worker with `UBAG_SYNTHETIC_PROVIDER=1`
  (and `UBAG_WORKER_DAEMON=true` for the warm path), jobs with `target: synthetic_chat`, `options.headless: true` locally.
  The browser must reach the fixture's loopback address, so run the fixture where the browser runs.

## Deviations

- The selector block is in `ubag_worker/live/synthetic.py`, not `selectors.py`: `check-provider-selectors.mjs` requires every
  `ProviderSelectors` block in `selectors.py` to be in `adapters/registry.json`, and the overlay must stay out of it.
  `selectors.py` only gets a three-line hook.
- Go routing and env passthrough are not in the work item's file list, but without them gateway jobs could never reach the
  daemon, which is the point of the slice.
- `UBAG_WORKER_STAGE_TIMINGS` is now forwarded to spawned workers. P0.9b added it but nothing forwarded it, so stage
  attribution (needed to read any scenario result) could not be switched on through the gateway. Default unchanged (off).
- `UBAG_SYNTHETIC_PROVIDER_URL` is a new config value (flag taxonomy has none for this).
- `adapters/registry.synthetic.json` has no runtime consumer; it is a declarative index validated by tests. The manifest also
  accepts `audio/wav` so the mixed workload's audio class can run, as an opaque attachment (no transcription, no live voice).
- Dropped connection is modelled as a DOM/network contract only. The engine has no provider-error signal for it, so by reading
  `stream_response` it would end that turn `completed` with partial text. No test asserts that verdict.
