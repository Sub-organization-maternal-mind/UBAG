# P3.2 - No blind resubmit: prompt_submitted marker and post-submit terminal failure

Status: merged (see PR). Flag: `UBAG_WORKER_STRICT_SUBMIT` (default OFF).

## What changed
- `apps/worker/ubag_worker/live/engine.py`: `_run_interaction` is now a thin wrapper over `_run_interaction_inner`.
  With the flag ON, a `prompt_submitted` event is buffered right after `driver.submit_prompt` returns, and any
  non-deterministic exception after that point becomes a terminal `failed_terminal` event
  `{submitted:true, retryable:false, reconcile_required:true, stream_end_reason:"error", reason:"post_submit_failure",
  current_thread_url (best effort), message (exception class name only)}` instead of re-running the interaction.
  Pre-submit failures (including an exception raised inside `submit_prompt`) still retry up to 3 times.
  `DriftDetectedError` / `ManualActionRequired` / `LiveSessionError` keep their existing handling.
- Flag OFF: no marker event, exceptions propagate, retry loop unchanged (byte-identical event stream).
- No contract change: `prompt_submitted`, `submitted`, `reconcile_required` already exist in job-event.schema.json and the gateway vocabulary.
- The warm daemon already discards the driver after any non-completed job (daemon.py), so no daemon change.

## Tests
`apps/worker/tests/test_strict_submit.py`: submit once when the stream raises; pre-submit failures retry 3x; flag-off unchanged (3 submits, no marker).

Not run: full worker suite, gateway tests (no gateway change).

## Deviations / follow-ups
- Exception raised inside `submit_prompt` itself is treated as pre-submit (retried); a click that landed before the raise remains an ambiguity of the live driver.
- Human must verify the live DOM before the default flips; flag stays off.
- The marker is buffered with the interaction (no incremental streaming yet), so it reaches the gateway with the rest of the batch.
