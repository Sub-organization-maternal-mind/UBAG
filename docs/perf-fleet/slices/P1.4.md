# P1.4 - File-spool correctness: not_before, lost-race lease, flat enqueue cost

Status: merged. Three separate commits, all in `apps/gateway/internal/executor/filespool.go` (+ tests) and one wiring line in `apps/gateway/internal/serve/serve.go`.

## What changed
1. **Lost-race lease (always on).** `LeaseNext` used to report "queue empty" when the rename of the oldest pending envelope lost the race (another worker or a cancel moved it first), delaying the next pending job by a poll interval. It now falls through to the next-oldest candidate. The common path stays sort-free (single-pass minimum; the candidate slice is sorted lazily only after the first candidate is lost). `tryLease` was split out; the oversize/bad-JSON/job-id-mismatch poison behaviour is unchanged.
2. **`not_before` honoured in file mode (contract bug fix, flagged).** Only the NATS consumer honoured `not_before` (blueprint 14.6); production runs `UBAG_EXECUTOR_MODE=file`, so scheduled jobs were leased immediately. With `UBAG_FILESPOOL_HONOR_NOT_BEFORE=true`, `LeaseNext` skips pending envelopes whose `not_before` is in the future and leases the next due candidate. The parsed time is cached per pending file (pruned to the pending set each poll), so a deferred envelope is read once, not on every poll. Unreadable or malformed envelopes are never deferred (the normal lease path parks them in `failed/`). Due scheduled jobs are picked up by the existing poll tick.
3. **Flat enqueue cost.** P0.8 confirmed enqueue grew with the terminal backlog (`jobExistsInAnyState` ran Stat+Glob over done/failed/cancelled). Terminal existence is now an in-memory ID index (`terminalIDs`): built lazily by one ReadDir pass, updated by this process's own moves into terminal dirs (`moveLeasePath`, pending->cancelled, cancellation marker), and rebuilt after a retention sweep deletes files. Lookup semantics match the old `<id>.json` / `<id>.*.json` match. Limitation: files dropped into terminal dirs by another process after the index is loaded are not seen until the next rebuild (the job store is authoritative and a terminal job is never re-enqueued).

## Flags
| Flag | Default | Effect |
|---|---|---|
| `UBAG_FILESPOOL_HONOR_NOT_BEFORE` | off | file spool defers envelopes until `not_before` (live behaviour unchanged by default) |

Migrations: none. Contracts: none (the envelope already carries `not_before`).

## Evidence (NON-AUTHORITATIVE: Windows dev box, `-benchtime=300x`)
Command: `go test -run '^$' -bench 'SpoolEnqueue|SpoolLeaseNext' -benchtime=300x -benchmem ./internal/executor` (P0.8 benchmark, unchanged).

| terminal files | enqueue before (P0.8) | enqueue after | allocs before -> after |
|---|---|---|---|
| 0 | 5.6 ms | 5.2 ms | 252 -> 213 |
| 1000 | 8.3 ms | 3.9 ms | 1263 -> 219 |
| 10000 | 41.0 ms | 4.0 ms | 10278 -> 280 |

LeaseNext unchanged and flat (2.4 ms at 0/1k/10k).

## Checks
Run: `go vet ./internal/executor ./internal/serve`; `go test ./internal/executor ./internal/serve` (pass); the benchmark above.
New tests: lost-race falls through to next candidate; all candidates lost -> empty without error; `not_before` respected with flag on (younger due job leased first, scheduled job leased once due, cache cleared); flag off leases immediately; terminal index (pre-existing terminal files, own moves, prefix-only IDs, retention invalidation).
Not run: full suites, Postgres-backed tests.

## Deviations
- `UBAG_SPOOL_PRIORITY_LANES` (an "inert" flag in the spec) was NOT added: a flag with no behaviour behind it is dead config; add it with the slice that implements lanes.
- The wake-up for a scheduled job is the existing poll tick, not a timer; due jobs are leased within one `UBAG_WORKER_POLL_INTERVAL_MS`.

## Follow-ups
- Deploying with the flag on is an operator decision (D2: live behaviour preserved by default). Scheduled jobs then actually wait for `not_before` in file mode; the stale-job reaper already respects a future `not_before`.
- A separate process writing into terminal dirs (none exists today) would need an index rebuild hook.
