# P4.16 Profile and conversation affinity (tenant-owned profile_ref)

Status: merged into `feat/perf-fleet`. Size L. Depends on P4.4 and P1.6 (both merged); builds on P4.7's `HelperAttemptSpec`. Inert: nothing calls the new registry or the new conversation methods yet (the placer is P4.17, the helper agent and trust plane are P4.5+), the new env flag lives in the helper worker's environment only, and the two migration columns default to `''`.

## What landed

- **Tenant-owned `profile_ref` registry** (`apps/gateway/internal/helperauth/profilebind.go`, `profilebind_postgres.go`). A `profile_ref` names ONE logged-in browser profile on ONE helper node for a `(tenant, provider, identity_ref)`. The primary mints it (`pr_` + 128 random bits from `crypto/rand`; it reveals neither tenant nor identity) and is the only party that maps it back. `ProfileStore` has memory and Postgres implementations (SQLite deliberately has none: the edge profile refuses helper mode): `Bind` (idempotent per `(tenant, provider, identity_ref, node)`), `Resolve`, `List`, `Revoke`. Every lookup is tenant-scoped: another tenant's ref is indistinguishable from an unknown one. Revocation is sticky: a revoked ref never resolves again and binding the same tuple mints a new ref (fresh profile directory, fresh human login). At most `MaxProfilesPerProvider` = 256 active bindings per `(tenant, provider)`.
- **Pure placement rule** `EligibleProfiles(SelectInput)`: returns only the tenant's own active profiles for the provider on nodes the caller says are eligible (the P4.1 `Evaluate` decision), ordered by `(node_id, profile_ref)` so the placer can take the first with a free identity lane. Anything else in the input is ignored, so a careless caller cannot leak across tenants. **No match is `ErrNoMatchingProfile`: queue, never assign (F9).** A conversation with a bound chat thread resumes only on its bound node and profile: exactly that one profile, `ErrAffinityUnavailable` when its node is not eligible (wait, never relocate), `ErrConversationBroken` when it cannot resume (state broken, thread bound outside the helper plane, tenant/provider mismatch, profile revoked or moved to another node). For `on_missing=restart` the caller selects again without the conversation to start a fresh chat.
- **Conversations gain `NodeID` and `ProfileRef`** (`conversations.go`, `postgres.go`, `sqlite.go`), set together or not at all (`ErrInvalidAffinity`, bounded to 128 bytes), persisted by the memory, SQLite and Postgres stores, `Bind` overwrites them (so a local re-bind clears them). They are tagged `json:"-"`: they are internal routing metadata (fleet node ids are not tenant data), so `GET /v1/conversations` and the OpenAPI contract are unchanged. New `Store.MarkNodeBroken(ctx, nodeID) (int, error)` (and `Manager.MarkNodeBroken`, nil-safe): marks every active conversation bound to the node broken, across tenants, and leaves node, profile and thread ref intact. **A lost node therefore gives `broken` with no migration.** An empty node id matches nothing.
- **Postgres `Ready`** for conversations now also asserts the two new columns exist and names migration 0024 when they do not (a clear boot-time error instead of query failures). **SQLite** `Ready` adds the two columns to a pre-existing table in place (idempotent `ALTER TABLE ... ADD COLUMN`, defaults keep old rows local) and creates a partial index on `node_id`.
- **Helper spec** (`executor/helperspec.go`): P4.7 already strips `user_data_dir`, `profile_dir`, `profile_path` and the whole `context` (where `account_binding_id` lives). This slice also drops `options.account_binding_id` and adds a test that no profile path or identity label survives the projection, wherever the envelope carries it.
- **Worker** (`apps/worker/ubag_worker/live/envelope.py`): with `UBAG_HELPER_PLANE` truthy in the worker's environment (set by the helper agent; it is not in the gateway's local-worker env allowlist, so the primary's own workers never run in this mode) the profile directory is `<UBAG_PROFILE_DIR or var/profiles>/helper/<profile_ref>`, derived from the **top-level** `profile_ref` only. `options`/`context` `user_data_dir`/`profile_dir`/`profile_path`, the tenant, the target, `context.account_binding_id` and the `UBAG_PROFILE_OPTIONS_POLICY` are ignored; `account_binding_id` (the identity-lock key) becomes the `profile_ref`. A missing or malformed ref in helper mode raises `EnvelopeError` (fail closed, no fallback to a caller-selectable directory). The worker's ref pattern is `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`: the gateway's pattern minus `:` (NTFS alternate-data-stream separator). Flag off: byte-identical behaviour.
- `nodes.ValidNodeID` exported (one line) so the registry validates node ids by the same rule as the allocation and URI SAN.

## Deviations

- Migration is `0024_helper_profiles` (Postgres) with no SQLite file, not `0022_helper_profiles` for both as the work item text says, per the P0.3 allocation table (0023 is P4.4's, 0022 is P4.2's). The conversations columns for SQLite are added in code by the existing SQLite store (it already owns its schema and has no file in `migrations/sqlite`).
- "Primary computes an opaque profile_ref": the primary **mints and stores** it (random, persisted) instead of deriving it. A derived ref (HMAC) would need a long-lived secret whose rotation would orphan every helper's profile directory; the table the work item calls for already holds the mapping.
- `profile_ref` is bound to a node as well as to `(tenant, provider, identity_ref)`: each helper needs its own human login (safe mode forbids copying credentials), so the same identity on two nodes is two profiles and two refs.
- `NodeID`/`ProfileRef` are `json:"-"` on `Conversation` so the public list response and OpenAPI contract stay unchanged and fleet node ids are not exposed to tenants. Operators needing them will get an operator-scoped view with the fleet routes (`/v1/fleet/*`, scope `fleet:read`).
- `MarkNodeBroken` does not stamp `last_used_at` (the conversation was not used) and takes no time argument.
- The worker accepts a stricter `profile_ref` pattern than the gateway (no `:`); refs minted by `MintProfileRef` never contain one.
- The spec's `HelperAttemptSpec` already dropped the three profile options and all of `context` (P4.7); this slice adds `options.account_binding_id` only.

## Follow-ups

- **Operator binding UX (the work item's stated risk):** there is no HTTP route, CLI or dashboard action to call `ProfileStore.Bind`/`Revoke` yet. It needs an operator-scoped route (an authz action in both `authz.go` and `packages/security/src/rbac.ts`, OpenAPI, audit events `profile.bound`/`profile.revoked`, MFA gate) and a check that `node_id` is a registered, non-revoked node. The store API is the primitive.
- **P4.17 placer:** call `ProfileStore.List` then `EligibleProfiles` with the P4.1 `Evaluate` predicate, treat `ErrNoMatchingProfile`/`ErrAffinityUnavailable` as a delayed Retry (never an immediate re-queue), apply `on_missing` on `ErrConversationBroken`, lane by `IdentityRef`, and `Bind` the conversation with `NodeID`/`ProfileRef` from the trusted attempt record (never from helper payload).
- **P4.18 reconciler / node loss:** call `conversations.Manager.MarkNodeBroken(nodeID)` when a node is revoked or declared lost.
- **Helper agent:** must put `UBAG_HELPER_PLANE=true` in the helper worker's environment and send the spec's `profile_ref` at the top level. The flat `HelperAttemptSpec` JSON puts `command_type` at the top level, which `normalize_payload` does not read (it defaults to `chat.prompt`); wrap the spec under `job` or add a fallback when the agent lands.
- Rows in `gateway_helper_profiles` are never deleted (revoked rows are history); add a purge if churn becomes real.
- Warm-daemon keying is `(tenant, target, user_data_dir)` and the helper layout adds a `helper/` segment under the profile root; nothing to migrate because no helper exists yet.
